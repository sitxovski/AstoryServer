# P38 — защита лимита мест клана: проверка сверяет ту же прибавку (+10)

- **Дата:** 2026-09-27
- **Статус:** СОБРАН, НЕ УСТАНОВЛЕН (на живой сервер не выкладывался)
- **Процесс/файл:** GameServer.exe (основной и Indun_GameServer) — правка байта хоста из НАШЕЙ
  DLL `AsdaPatch.dll`. Исходник: `AstoryServer/Patches/AsdaPatch/src/patches/p38_clan_slot_cap.cpp`. Version DLL 25.
- **Тип:** бинарный (1 байт, замена immediate).
- **Отчёт:** `Reports/owner_0927/who_clan_REVIEW.md` §4.
- **Бэкап DLL до правки:** `AstoryServer/Patches/AsdaPatch/out/AsdaPatch.dll.pre_p38_20260927`.

## ЗАЧЕМ (симптом → диагноз)

Обработчик расширения клана проверяет «текущий_лимит + 5 ≤ 100», а ПРИБАВЛЯЕТ +10
(0x404ADA/0x404AE8). Стартовый лимит 50, шаги +10: 50→60→70→80→90→100 — в обычной игре 100 не
превышается. Но при РУЧНОЙ правке БД (или у старых кланов), если лимит оканчивается на 1…5 и > 90,
проверка «лимит+5 ≤ 100» проходит, а прибавляется +10 → клан уходит ЗА 100 (до 105). Дефект
латентный (в обычной игре недостижим), правка — защитная.

## ЧТО (адрес + байты «было→стало»)

```
0x00404944  0F B6 8D 65 FF FF FF   movzx ecx,[ebp-0x9B]   ; текущий лимит  (окружение — сверяем)
0x0040494B  83 C1 05               add   ecx,5            ; ← immediate по 0x40494D
0x0040494E  83 F9 64               cmp   ecx,100
0x00404951  7E 34                  jle   (расширение разрешено)
```

Один байт по VA **0x0040494D**: `05` → `0A` (`add ecx,5` → `add ecx,10`). Гейт становится
«текущий_лимит + 10 ≤ 100» — сверяет ТУ ЖЕ прибавку, что и делает; за 100 клан не уходит.
Честный путь (лимит ≤ 90): 90+10=100 ≤ 100 — расширение проходит. Отказ — штатный (код 3 → нотис
12453 «клану больше некуда расти»). Протокол НЕ меняется.

Байты 0x404944…0x404951 одинаковы в живом GameServer, Indun_GameServer и базе IDA (md5 `e7b4ac38…`).
Площадки основного GameServer и Indun. С P01…P42 не пересекается.

## Ключ (ConfigSet\patches.ini)

`[P38_ClanSlotCap] Enabled=1` (0 = оставить сток 05).

## Проверки

- `verify_dll.py` — сток, живой GameServer и Indun: расхождений 0, пересечений 0 (площадка `P38.cap`).
- `verify_p38.py` (unicorn) — 7 [OK]: патч +10 отклоняет лимиты 91…100 (сток +5 их пропускал →
  итог +10 = 101…110 > 100), честный путь (лимит ≤ 90) проходит.

## Как ОТКАТИТЬ

Вернуть байт 0x40494D в `05` (или `[P38_ClanSlotCap] Enabled=0` + рестарт). Рестарт GameServer/Indun.

## Замечание (МЕЛК-5 ревизии, НЕ лечится здесь)

Соседний гейт `cmp eax,5; jne` ловит только «== 5»; при `v25 > 5` из БД цена читается за границей
5-элементного массива. Достижимо ТОЛЬКО ручной правкой БД, к переполнению лимита отношения не
имеет — оставлено как есть.
