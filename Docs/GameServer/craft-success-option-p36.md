## 1. Что было и что стало

* **Было.** У 13 амулетов фиксированная опция `item_table +12 = 24`, `+14 = N`: 23324 (2), 29827–29830 (7), 29831–29834 (6), 29835–29838 (5)
  (все — слот 7, `item_table` токен 16 = 7). В подсказке «Успешное изготовление +N %», эффекта нет: `sub_445DD0` (сумма опции по типу)
  зовётся 83 раза с литералами, 24 среди них нет; в `RecvUser_CraftEnter @0x53DBA0` ни одного бонуса игрока.
* **Стало.** Порог **каждой** ступени лестницы ремесла (`CraftRecipeMake` кол. 24…30, копия в кадре `[ebp+k*4-0x4EE]`) при сравнении
  с броском `sub_5329A0(0, 100000)` берётся как `min(100000, порог × (100 + N) / 100)` (целочисленно, 64 бита).
  Порог `≤ 0` и `≥ 100000` не меняется. N — `sub_445DD0(CParamManager, userNum, 24)`: пары доп-опций 11 надетых слотов (с прочностью > 0)
  + фиксированная опция трёх аксессуаров (слоты 5/6/7) — штатная сумма сервера, та же, что у P34 для типа 61.
  Зажим N: `[-100, MaxBonusPercent]`.
* **Не меняется:** «великий успех» (+1 шт., `0x53E84F`, порог `Make +5`), помощник вида 2 (нулевой первый бросок), уровни ступеней, опыт.
* Основание формулы: единственный бонус шанса у сервера — бонус дропа (NpcServer `sub_42E3A0`: `rate·(1 + x/100)`, P34 тип 61).

Примеры: ступень 80000, амулет +7 % → 85600; лестница 60000/39600/26136, амулет +5 % → 63000/41580/27442; ступень 100000 — без изменений.

## 3. Кадр и регистры

* `k = [ebp-0x7D0]` (0…6), бросок `[ebp-0x4BC]`, порог `[ebp+k*4-0x4EE]`, `this = [ebp-0x820]`, `CParamManager = [[this+4]+0x18]`
  (как у стока: `0x53E9D2 mov ecx,[ebp-0x820] / mov edx,[ecx+4] / mov ecx,[edx+18h]`), `userNum = (i16)[ebp+8]`.
* `eax/ecx/edx` на обеих целях пишутся до чтения (стоковая площадка сама портит `eax/edx`; путь провала → `0x53E80B`/`0x53E9C8` пишет `ecx` до чтения);
  флаги перезаписываются. Сравнение знаковое, как у стокового `jg`. Стековая копия порога не меняется.
* `P36_StageFail` — `__cdecl`, SEH-обёртка: при исключении — стоковый порог.

## 4. Журнал

Первые 20 применений за жизнь процесса (только когда N ≠ 0) — строка в `Log\Log_Craft` (категория 26):
`P36: craft option 24 user <idx> stage <k> bonus <N>% threshold <было> -> <стало> roll <бросок> PASS|FAIL`; 20-я — с пометкой
`(further messages suppressed)`. Больше не пишется ничего.

## 6. Выкладка (делает владелец / координатор после ревизии)

1. Остановить `GameServer` и `Indun_GameServer`.
2. В `v2\GameServer` и `v2\Indun_GameServer`: текущую `AsdaPatch.dll` (MD5 `00E64028…`) → `AsdaPatch.dll.bak_pre_p36_20260926`;
   скопировать `AstoryServer\Patches\AsdaPatch\out\AsdaPatch.dll` (MD5 `9CB1AD99…`, 337 920 б).
3. Запустить. DLL допишет секцию `[P36_CraftSuccessOption]` и поднимет `Version` 17 → 18.
4. PatchLog: `[OK] P36_CraftSuccessOption`, строка `P36/тип 24: …`, строка P34 `P34/тип 24: не здесь — см. P36…`, итог «ошибок 0».

## 7. Проверка на живом

1. PatchLog (§6.4).
2. Надеть амулет с опцией 24 (например 29827, +7 %), изготовить предмет с порогом ступени < 100000 — в `Log_Craft` строка `P36: … threshold 80000 -> 85600 …`.
3. Без амулета — строк `P36` нет, поведение стоковое.

## 8. Откат

* **Частичный:** `Enabled=0` (или `CraftSuccessOption=0`) в `[P36_CraftSuccessOption]` → рестарт.
* **Полный:** вернуть `AsdaPatch.dll.bak_pre_p36_20260926` (или `out\AsdaPatch.dll.pre_p36_20260926`) → рестарт. Прежняя DLL **сама** запишет
  Секцию `[P36_…]` можно оставить — старая DLL её не читает.
  ★ Если `patches.ini` не пишется — прежняя DLL, увидев `Version=18`, не поставит **ни одного** патча; тогда перед стартом вручную `Version=17`.
