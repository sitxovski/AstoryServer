## 1. Диагноз

Фиксированная опция предмета — `item_table` +12 (тип; загрузчик `sub_4A96A0` кладёт `(u8)atol`) и +14 (значение, i32).
GameServer суммирует её в `sub_445DD0 @0x445DD0` (три блока: коды аксессуаров слотов 5/6/7 — `CUser+0x2D9/+0x312/+0x34B`) вместе с парами доп-опций —
но только для типов, которые спрашивает сам (83 вызова, все литералы). Типы **4, 24, 61** не спрашивает никто:

| тип | подсказка клиента | где этот тип работает у других источников | почему у ожерелий нет эффекта |
|---|---|---|---|
| 4 | «Крит при атаке %» | NpcServer `sub_457280`/`sub_459C50`: каждая пара типа 4 из 8101/8305 (`игрок+65340`, 50 пар) прибавляется к шансу крита (`sub_457280` — зажим 100 на каждом шаге; `sub_459C50` — без зажима по шагам, итог режется до **75**) | фиксированную опцию в пары никто не кладёт; коды аксессуаров (`+65124…+65136`) NpcServer только записывает, своей item_table у него нет |
| 61 | «Шанс выпадения трофея %» | ни у одного источника (0 строк Item_OptionTable). Единственный бонус дропа сервера — `CUser+0x46F` (`sub_43F790` = самоцветы Cellob вида 7, `sub_44B0D0`) → 8101/8305/8209 → NpcServer `игрок+30852` → `sub_42E3A0`: `rate·(1 + x/100 + …)` во всех бросках дропа | тип 61 в `+0x46F` не входит |
| 24 | «Успешное изготовление %» | **нигде**: в ремесле (`RecvUser_CraftEnter @0x53DBA0`) нет ни одного модификатора шанса игрока | — (не лечится, см. §4) |

## 2. Что делает патч (ключи)

* **`CritToBattleServer`** (тип 4). В готовой записи игрока 370 б (8101/8305): по кодам аксессуаров записи (+61/+65/+69 —
  те же поля, что у `sub_445DD0`) берётся фиксированная опция; если тип 4 и значение ≠ 0 — оно кладётся в массив пар
  (+132, 50 × (i16 тип, i16 значение)): в свободную пару (тип **≤ 0**; пустая пара у сервера — `(−1, −1)`) собственного слота аксессуара, иначе в любую свободную,
  иначе складывается с существующей парой типа 4. NpcServer суммирует все пары типа 4 одинаково, поэтому результат =
  «крит с вещи + фиксированный крит ожерелья», ровно как у любой доп-опции крита. Если все 50 пар заняты и пары типа 4 нет —
  строка в `Log_Item`: `P34: fixed crit option of item … not sent to battle server - all 50 option pairs are busy` (не более 20 строк за жизнь процесса, последняя с пометкой `further messages suppressed`). Ни один потребитель пар в NpcServer на тип ≤ 0 не реагирует: все сравнивают с конкретными типами, switch'и 25…90 и 39…52/316 идут через `sub; cmp; ja` → default (`0x40CA91`, `0x40A945`, `0x40BF35`).
  Код проверяется `sub_532A90` (у стока проверки нет — защита от чтения мимо таблицы).
* **`DropRateStat`** (тип 61). В `sub_43F790` к сумме `sub_4437C0 + sub_44B0D0` прибавляется `sub_445DD0(idx, 61)` —
  штатная сумма GameServer по типу (пары 11 слотов + фиксированная опция 3 аксессуаров). Стоковый зажим «< 0 → 0» остаётся
  (наш `add` стоит последним перед `jns`). Поле уходит в NpcServer в 8101/8305/8209 и множит каждый шанс дропа владельца
  добычи: ожерелье «+5 %» → шанс ×1.05, «+40 %» → ×1.40 (как самоцвет вида 7 со значением 5/40).
* **Тип 24** — только строка в PatchLog «НЕ лечится».

## 4. Что видит игрок после выкладки

* Ожерелья с «Крит при атаке +N %» (20634–20638, 23327, 24954, 69681 — у 69681 значение 0, эффекта не будет и после патча)
  дают +N к шансу обычного крита в бою (NpcServer: `sub_457280` — зажим 100, `sub_459C50` — итог до 75) — так же, как доп-опция «Крит при атаке» на любой другой вещи.
  Стат-блоки клиента (4060/4064) P34 не меняет: если крит с доп-опций в окне характеристик не отображался, не будет отображаться и этот.
* Ожерелья «Шанс выпадения трофея +N %» (23325 — 5, 29632 — 40) повышают шанс всех бросков дропа (предметы, золото,
  мировой дроп, кража навыком) в N/100 раз от базового, у владельца добычи.
* «Успешное изготовление %» (13 амулетов) — по-прежнему без эффекта, до решения владельца.
* Типы 4 и 61 действуют **и у сломанного ожерелья** (прочность 0) — это поведение стока для фиксированных опций: `sub_445DD0` в блоках аксессуаров прочность не проверяет, упаковщики 8101/8305 тоже (так же сейчас работают фикс. HP/статы колец и ожерелий).

## 5. Проверка на живом после выкладки

1. `Log\Log_Patch\PatchLog_<дата>.txt` (обе папки): `[OK] P34_NecklaceFixedOptions`, строки `P34/тип 4` (две площадки),
2. Крит: персонаж без доп-опций крита, одна и та же цель, ~200 обычных ударов без ожерелья и с 20638 (значение 5).
   Доля критов должна вырасти ≈ на 5 п.п. (крит считает NpcServer, поэтому проверять только статистикой на живом).
3. Дроп: сравнить частоту дропа с одного типа мобов с 29632 (+40 %) и без — заметно чаще. Строгий замер — только статистикой.
4. Отсутствие строк `P34: fixed crit option … not sent` в `Log_Item` у носителей 20634–20638/23327/24954.

## 6. Выкладка (делает владелец)

1. Остановить `GameServer` и `Indun_GameServer`.
2. В каждой из папок `v2\GameServer` и `v2\Indun_GameServer`:
   * переименовать текущую `AsdaPatch.dll` (P33, MD5 `5CB9B105…`) → `AsdaPatch.dll.bak_pre_p34_20260925`;
   * скопировать `AstoryServer\Patches\AsdaPatch\out\AsdaPatch.dll` (MD5 `93E09EA2…`).
3. Запустить серверы. DLL сама допишет секции `[P33_GearUpgradeServerDefects]` и `[P34_NecklaceFixedOptions]` и поднимет `Version` до 16.
4. Проверить PatchLog (§5.1). NpcServer перезапускать не нужно.

## 7. Откат

* **Частичный** (без замены DLL): `CritToBattleServer=0` или `DropRateStat=0`, либо `Enabled=0` у секции → рестарт GameServer.
* **Полный**: вернуть `AsdaPatch.dll.bak_pre_p34_20260925` → рестарт. Прежняя DLL сама запишет `[General] Version=15`
  ★ Если `patches.ini` недоступен для записи — понижения не будет, и старая DLL при `Version=16` не поставит ни одного патча:
  перед стартом вручную выставить `Version=15`.
* Данные и база не меняются — откат мгновенный и полный.

## 8. Замечания

* Документ `RE/docs/server/combat_formulas.md` §1 называет `+1135` (`sub_43F790`) «TotalDefence» — это неверно: поле читается ровно одним
  местом в NpcServer (`0x42E3A3`, скан всех операндов `disp 0x7884`) — множитель шанса дропа. В GameServer его читают только
  упаковщики 8101/8305/8209 и геттер `sub_43F830` (стат-блок 4060, `[28]`).
* Попутно (сток, не P34): упаковщики 8101/8305 шлют пары и сломанных вещей (прочность 0), тогда как `sub_445DD0` такие пары не считает. Не трогалось.
