## Что и зачем

Функциональные предметы (расходники) сервер держит в `Function_Table.txt` (`ItemTable_Info\`, загрузчик `sub_4AF980@0x4AF980`, `GameServer.c:70386`): `dword_5F5E70` — массив записей по 48 б, индекс `code−1`, число записей `dword_5F5EA4`; колонка 5 → байт `+8` = **тип**, колонка 6 → i16 `+9` = значение. Четыре обработчика проверяют только диапазон кода (`sub_532B10@0x532B10`: `1 <= code <= [0x5F5EA4]`) и принимают **любой** функциональный предмет:

| Обработчик | Дыра | Что требуем | Откуда тип (не выдумано) |
|---|---|---|---|
| 6551 `Recv_UserUpgradeBless@0x5358C0` (GS:118179) | свиток благословения — любой расходник; ступень берётся из его записи (`LOBYTE(a5[6])`) | тип ∈ {204, 206} | сток 6549 `Recv_UserUpgradeExtraction@0x534640` порождает свитки только из записей типа 204 (код 401: `movzx eax,[edx+4B08h]; cmp eax,0CCh` @0x534DDF) и 206 (код 363: `movzx ecx,[eax+43E8h]; cmp ecx,0CEh` @0x534E94) — это сверка фиксированных записей таблицы, не входа. В `Function_Table.txt` (12.10): 204 = 401/402/414, 206 = 363/413 |
| 6553 `Recv_UserItemOptionTrans@0x536460` (GS:118490) | свиток обмена опций — любой расходник | тип ∈ {67} | клиент: эталон `sumInventoryItemsType67@0xB63500` (порт `AsdaItemOptionSubsystem` `kScrollSubType = 67`) кладёт в окно только `special_itemlist.SubType == 67`; серверный тип 67 = коды 364/365/366/458/546. Сверка таблиц: у 529 из 558 кодов серверный тип == клиентский SubType; **коды 367 и 393** у клиента 67, на сервере 17/15 (расхождение таблиц; авторитет — сервер) |
| 5433 `Recv_ShellItemOption_Extraction@0x513F80` (GS:105447–105454) | «помощник» — бонус к шансу из `+9` любого расходника (`movsx edx,[ecx+eax+9]` @0x514A97) | тип ∈ {96} | клиент: порт `AsdaExtractShopSubsystem` `kScrollSubType = 96`; серверный тип 96 = коды 289/290/291/459 (у всех `+9 = 0`, т. е. честный бонус нулевой; у чужих кодов, напр. 393, `+9 = 80`) |
| 5450 `Char_FunctionItem_Use@0x4ED780` | гейты состояния (тип≠48), пола (35/36), уровня (54/55) решаются по коду **из пакета** (`[ebp-0x1FE]`, GS:91702–91745), действие — по коду **из слота** (`[ebp-0x16C]`, GS:91779) | код пакета == код слота | порт шлёт код слота (`AsdaInventorySubsystem.cpp`: `Code = Src->ItemCode` → `SendFunctionItemUse5450`) |

Механизм: четыре площадки — `E8 rel32` `call sub_532B10` целиком. Стаб зовёт сток (диапазон), при «1» читает тип записи (индекс уже проверен стоком, сверяется ещё раз) и сравнивает со списком ini; 5450 — сравнивает код пакета с кодом слота. Нарушение: `Mode=0` — строка `P65 ConsumableType: …` в канал `LogChannel` (1 = Log_Item) + журнал `ac.other` с ограничителем на (сессия, площадка), и **пропуск как в стоке**; `Mode=1` — стаб возвращает 0, сток уходит в свою соседнюю ветку отказа: 6551 → 6552 код 2 (119 б, `Recv_UserUpgradeBless(3)`), 6553 → 6554 код 2 (119 б, `Recv_UserItemOptionTrans(5)`), 5433 → 5434 код 0 (184 б, `…Extraction(13)`), 5450 → 5451 код 9 (68 б, `Not FunctionItem`, LABEL_165). Новых пакетов/кодов нет.

Риск для честного порта: 6551 порт не шлёт вовсе; 6553/5433 — только SubType 67/96; 5450 — код слота. Единственное место — коды **367/393** в 6553 (порт предложит их как свиток, сервер в `Mode=1` откажет кодом 2 — порт покажет штатный нотис); в `Mode=0` это видно в журнале (вид 46) до включения отказа.

## Площадки «было → стало»

| VA | Было (сток) | Стало |
|---|---|---|
| `0x535B01` (5) | `E8 0A D0 FF FF` → `sub_532B10` (6551) | `E8` → `St_Bless6551`: `push ecx/edx/ebp; push [esp+16]; push 1; call P65_Check; pop edx; pop ecx; ret` |
| `0x53664A` (5) | `E8 C1 C4 FF FF` (6553) | `push 2` … то же |
| `0x514A79` (5) | `E8 92 E0 01 00` (5433) | `push 3` … то же |
| `0x4EDD82` (5) | `E8 89 4D 04 00` (5450) | `push 4` … то же |

`P65_Check(site, code, ebp)` (`__stdcall`) возвращает как `sub_532B10`: 0 → сток в свою ветку отказа, 1 → пропуск; аргумент cdecl снимает сток (`add esp,4`). Соседи, по которым сверяется (все три образа): push кода из кадра (`0x535AFA` `8B 95 64 FE FF FF 52`, `0x536643`, `0x514A72`, `0x4EDD7B` `8B 8D 94 FE FF FF 51`), хвосты `add esp,4; test eax,eax; jcc` (`0x535B06 … 75 44`, `0x53664F … 75 4A`, `0x514A7E … 74 25`, `0x4EDD87 … 75 27`), тела отказов (`0x535B0D` `C6 45 80 02`, `0x536656` `… 02`, `0x514AAA` `… 00`, `0x4EDDA4` `… 09`), код пакета 5450 `0x4ED97D` `8B 95 02 FE FF FF`, бонус помощника `0x514A97` `0F BF 54 01 09`, `this` 5433 `0x513F93`, пролог `sub_532B10` (с адресом счётчика `0x5F5EA4`), сверки 6549 `0x534DDF`/`0x534E94`, загрузчик `0x4AFA10`/`0x4AFAC3`. Кадры: `userNum = word [ebp+8]` у всех; 6551 свиток `[ebp-0x19C]`, вещь `[ebp-0x194]`, pUser `[ebp-0x18C]`; 6553 `[ebp-0xFC]`/`[ebp-0xF4]`/`[ebp-0xEC]`; 5433 помощник `[ebp-0x134]`, `Src[0]` `[ebp-0x48]`, CUserManager `[ebp-0x260]`; 5450 слот `[ebp-0x16C]`, пакет `[ebp-0x1FE]`, pUser `[ebp-0x20C]`. Площадки других патчей рядом (P15 `0x4ED9EF`, P08 `0x4ED8DE`, P49 `0x4ED8CF`, P33 `0x535E01`) не пересекаются; переходов/abs32 внутрь площадок нет.

## Конфиг

```ini
[P65_ConsumableType]
Enabled=1
Mode=0                ; 0 журнал (пропуск как в стоке), 1 отказ стоковой соседней веткой
CheckBless=1

CheckOptionTrans=1
```

Журнал `ac.other`: вид 45 (6551), 46 (6553), 47 (5433) — `value1` = код предмета, `value2` = его тип, `value3` = код второго предмета (вещь / источник опций), `detail` = `"<обработчик> type N not in {список}"`; вид 48 (5450) — `value1` = код слота, `value2` = код пакета, `value3` = код пакета, `detail` = `"5450 FunctionItem_Use packet code != slot code"`. Версия ini 36 → 37 (`Config::kVersion` и шаблон `kGeneral`).

## Проверка

- `tools/verify_p65.py` (`P65_IMG_DIR` или `P57_IMG_DIR` с локальными образами): байты 4 площадок + 28 соседей в трёх образах, цели `E8` = `sub_532B10`, переходов/abs32 внутрь нет, границы инструкций (площадки, цели jcc, тела отказов), jcc после площадок ведут куда задумано, стабы в DLL (4, одна C-функция), unicorn: аргументы `(site, code, ebp)`, eax = вердикт 0/1, `esp = вход+4`, ebp/ecx/edx/ebx/esi/edi сохранены, возврат на адрес стока. Итог 12.10: **195/195**.
- `tools/stand_p65/` (`stand_p65.exe <GameServer.exe> <AsdaPatch.dll> <Mode>`): настоящий образ до 0x600000, настоящий `sub_532B10` с подставной таблицей (типы как в `Function_Table.txt`), установка P53 (журнал → файл) и P65 по реестру, вызов самих стабов через подставной кадр: честный путь (401/363/414 в 6551, 364/546 в 6553, 289/459 в 5433, слот==пакет в 5450) — 0 строк; код вне таблицы — 0 от стока без строк; нарушения — по одной строке на площадку, `Mode=0` возврат 1, `Mode=1` возврат 0 с пометкой `REFUSE`; ограничитель (повтор и другой код того же вида подавлены), смена учётки в слоте — новая строка, `userNum=−1` — без падения и без журнала; файловый журнал P53: виды 45 ×2, 46, 47, 48. Итог 12.10: **48/48 (Mode 0) и 48/48 (Mode 1)**.
- На живом: `PatchLog` строка `P65: режим ЖУРНАЛ; 6551 свиток типы {204,206}; 6553 свиток типы {67}; 5433 помощник типы {96}; 5450 код пакета == код слота; …`; в `Log_Item` строки `P65 ConsumableType: …`; в `ac.other` виды 45…48. Через неделю: если виды 45/47/48 пусты, а 46 — только по кодам 367/393 (или пуст), включать `Mode=1`.
