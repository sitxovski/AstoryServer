## 1. Что закрывается
Стоковый GameServer (сток 4e20f0ad, живой = Indun e7b4ac38 — все площадки побайтно одинаковы) содержит **закладку**: пять штатных действий
с предметами, выполненных строго по порядку за ≤ 60 с, взводят пять байтовых флагов объекта потока карты (`CThread = *(CUserManager+4)`,
`+0x51AC…+0x51B0`) и такт `+0x51B4`. После этого блок 10024 `RunProcess` (`sub_4C0EA0`, `@0x4C2735…0x4C28A3`) раз в минуту проверяет флаги и
через >10 мин после взведения **затирает `memset`'ом базовый блок персонажа `CUser+0x174` (0x45 б: charId, имя, уровень, опыт, группа) у всех 550
слотов процесса**, затем повторяет через 10 мин + rand(10…100 мин) до рестарта или «кода отмены».

| шаг | опкод | условие (дизасм живого образа) | площадка |
|---|---|---|---|
| 1 | 5000 CharItemMove | инвентарь ячейка 0 → ячейка 59, занятая (ветка обмена) | 0x4CFF17–0x4CFF98 |
| 2 | 5006 CharItemDump | выбросить ячейку 48, количество 3 | 0x4D3C9E–0x4D3D1A |
| 3 | 5028 CharSpendItemUse | зелье категории 200 из ячейки 50 под запрещающим состоянием (отказ 5029 код 12) | 0x4D9CA0–0x4D9D24 |
| 4 | 5288 CharExchangeDragDropItem | в обмене положить ячейку 47 со стопкой ровно 9 | 0x4E2ABD–0x4E2B38 |
| 5 | 5008 CharItemKeeping | сдать на склад ячейку 45, количество 8, на складе стопка того же предмета ровно 8 | 0x50A5A0–0x50A6B0 |

Последствия (разбор §5): онлайн-игроки теряют всё несохранённое (при charId ≤ 0 `DisConnectUser` не шлёт 2003), запросы в БД уходят с CharIdx 0,
свободные слоты (charId −1 → 0) считаются занятыми — **новые входы и порталы на этот GS отбиваются до рестарта**. P18 D4 стоит ПОСЛЕ взведения и
закрывает только дюп через DB 2029. Аналогов в NpcServer/DBManager/LoginManager/ItemRelayServer нет (разбор §7: два метода).

## 2. Меры P72
### Мера 1 — `DisarmTimer=1` (основная)
Площадка **0x4C2745**: `0F 85 1E 01 00 00` (`jne 0x4C2869`) → `E9 1F 01 00 00 90` (`jmp 0x4C2869; nop`). Блок 10024 всегда уходит в ветку
сброса (`@0x4C2869…0x4C28A3`: пять флагов := 0); `memset` `@0x4C2839` недостижим. Переходов/ссылок внутрь 0x4C2746…0x4C274A нет
(verify_p72: полный проход `.text` rel8/rel32/jcc32/abs32 на трёх образах — 0). Перед записью сверяются соседи: ветка сброса 0x4C2869,
`call memset` 0x4C2839, граница цикла 550 (0x4C27F2), выход блока 0x4C28AA.

### Мера 2 — `CatchArming=1`
Площадка **0x50A651** (`8B 95 14 FA FF FF`, `mov edx,[ebp-0x5EC]` — первая инструкция блока записи флагов шага 5 `@0x50A651…0x50A6B0`) →
`jmp` на трамплин `ArmTrampoline`:
```
pushfd ; pushad
movzx eax, word ptr [ebp+8]        ; userNum (как сток @0x50A6D1)
push eax ; push dword ptr [ebp-0x5EC]   ; CUserManager*
call P72_OnArmed                   ; stdcall
test eax, eax ; popad ; jnz stock  ; маршрут — во флаге ZF, popad флаги не трогает
popfd ; jmp [g_pRouteSilent]       ; 0x50A6EB
stock: popfd ; jmp [g_pRouteStock] ; 0x50A6B6
```
`P72_OnArmed`: обнуляет `CThread+0x51AC…+0x51B0` и такт `+0x51B4` (взведение не происходит); личность — `P69_ResolveSession` (CUser, учётка
сессии, слот, GM-флаг); строка `ac.other` **76** (item_code = Response, value1 = автоблок 0/1/2/3, value2 = состояние сессии, opcode 5008,
detail «P72 arm seq done …»); `Log_Operator` «P72 HiddenWipeDisarm: CharItemKeeping(11) arming sequence completed by UserNum …».
Маршрут по ключу `Response`:
- **0 (умолчание) — молча**: 0x50A6EB → штатный хвост (`jmp 0x50A9B6` → DB 2029): для игрока это обычная сдача 8 предметов; ни 5009 код 5,
  ни строки категории 26 — набравший комбинацию не узнаёт, что замечен. Этот хвост — тот же, куда уходят восемь `jne` при невыполнении
  условия ловушки (0x50A5AB…0x50A64B), регистры там не нужны (0x50A9B6 → 0x50ABE1 → 0x50AC24 → цикл 0x50967D).
- **1 — как сток**: 0x50A6B6 → строка кат. 26 «CharItemKeeping(11)» + 5009 код 5; при `P18 FixKeepingDupe=1` — return в эпилог без DB 2029.

`AutoBlock=1` (умолчание **0**): блок учётки сессии штатным 2271/`UPHackBlock` через `P48_SendHackBlock` на `BlockHours` (−1 бессрочно);
`ExemptOperators=1` — GM-флаг (`sub_52ED50`, как P47/P69) не блокируется (журнал пишется всегда). Санкция — решение владельца. **★ Решение владельца 15.10.2026: `AutoBlock=0` — только журнал `ac.other` 76 и Log_Operator, санкции по строкам журнала вручную.**
