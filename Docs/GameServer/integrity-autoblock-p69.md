## 1. Что считается
«Поддельный или битый пакет» — кадр, которого честный клиент прислать не может.
- **P55** (`ac.packet_validator`), ключ `CountP55Kinds=1,2,4`: 1 — кадр короче минимума опкода, 2 — длиннее максимума (паддинг
  клиента +0..19 уже в таблице), 4 — кадр короче заголовка. **Не считается вид 3** (частота класса): это темп, а не порча кадра,
  бывает от лагов, пороги ещё калибруются.
- **P61** (`ac.other`), ключ `CountChannelKinds=56,57,58,59`: 56 тег AES-GCM, 57 номер кадра не следующий, 58 мусор до рукопожатия
  / сбой рукопожатия, 59 длина кадра. Только приём (`phase 0`). **Никогда не считаются** 61 (кадр сервера не доставлен: отказ
  стокового Send, очередь моста, сток потерял кадр, общий предел, нехватка памяти) и 0 (сбой CNG/шифрования на сервере) — это сбои
  сервера или сети, не игрока.
- Счёт P55 — по **строкам журнала**: ограничитель P55 (`JournalIntervalSec`, 60 с на сессию и вид) пропускает одну строку, она даёт
  один шаг счёта; подавленные повторы счёт не прибавляют. Нарушение канала — одно на соединение (мост рвёт его на первом).

## 2. Чья учётка
- Только **подтверждённая учётка сессии**: сессия в мире (`CUser+0x2E == 1` — CharMake/CharPortalMake после DB-логона, сверенного
  P50). Вход соулмейтом (`SoulState CUser+0x182D3 == 2`) — учётка вошедшего, `iMateUserIndex CUser+0x182C6` (общая точка
  `P48_IdentityOf`, те же правила, что у счёта киков P48). Соулмейт без iMateUserIndex — учётка неизвестна.
- **До входа в мир** `CUser+0x174` — номер, заявленный клиентом в 20000. Нарушение пишется в журнал, но не считается (иначе
  подставной клиент заблокировал бы чужую учётку).
- **Операторы** (GM-флаг, общая точка `P47_IsGmUser`, `sub_52ED50 == 1`) не считаются и не блокируются (`ExemptOperators=1`).
- P61 работает в потоке IOCP и CUserManager не имеет: его запоминает гейт P47 на каждом пакете слота (`P69_OnClientPacket`, одна
  запись указателя), сброс — на accept/разрыве слота (`P61_ResetSlotC → P69_SlotReset`). Без P47 нарушения канала — без учётки.

## 3. Ступени и блок
| ключ | умолчание | смысл |
|---|---|---|
| `Enabled` | 1 | 0 — счёта нет |
| `Mode` | **0** | 0 — только журнал «был бы блок»; 1 — блок 2271 |
| `Stage1Count` / `Stage1Hours` | 20 / 24 | |
| `Stage2Count` / `Stage2Hours` | 50 / 720 | |
| `Stage3Count` / `Stage3Hours` | 51 / −1 | −1 — бессрочно (30 лет `UPHackBlock`) |
| `CountP55Kinds` / `CountChannelKinds` | `1,2,4` / `56,57,58,59` | §1 |
| `ExemptOperators` | 1 | не выключать |
| `SoulMateSessionAccount` | 1 | вход соулмейтом — учётка сессии |
| `KickOnBlock` | 1 | Mode=1: вывести игрока, оставшегося в игре после блока |
| `LogCounted` | 1 | строка PatchLog на каждое засчитанное нарушение |
| `CounterFile` | `..\GameServer\ConfigSet\ac_integrity_counter.ini` | общий для GameServer и Indun |

- Счёт **накопительный** (без окна), по учётке, переживает рестарт: файл ini, секции `[Mode0]` / `[Mode1]` (наблюдение до альфы в
  боевой счёт не переходит), значение `счёт,ступень,первое_unix,последнее_unix`; межпроцессный мьютекс
  `Local\AsdaPatch_P69_IntegrityCounter` + критическая секция.
- Каждая ступень срабатывает **один раз**: ступень забирается под замком до отправки; неуспешный 2271 её возвращает — повтор на
  следующем нарушении. Если счёт перепрыгнул ступень (из-за сбоя), срабатывает старшая.
- Пороги не по возрастанию / срок 0 или < −1 → умолчания владельца и строка в PatchLog.
- **Mode=0**: строка `ac.other` 62 «был бы блок» + PatchLog + `Log_Operator` (`P69 IntegrityAutoBlock: …`).
- **Mode=1**: штатный DB-запрос **2271** (как GM-блок 6094 / Recv_CharBlock; общая точка `P48_SendHackBlock`) → DBManager
  `sub_432950` → `EXEC UPHackBlock UserIndex, часы`. `UPHackBlock` добавляет строку `BlockList`; блок держится, пока не истекли
  ВСЕ строки — короткий блок бессрочный не отменяет.
- **KickOnBlock** (Mode=1, источник P55 — валидатор соединение не рвёт): штатный вывод — счётчик Hack Packet `CUser+0x22` = 6 →
  `CheckDisConnectUser 0x526C20` (кик тип 3). Этот кик P48 **не считает** (метка на учётку, `P69_TakeKickMark`; `ac.kick_block`
  `not_counted_reason` «кик после автоблока P69»). Нарушение канала P61 рвёт соединение само.

## 4. Журнал
- Нарушение — строка источника (P55 `ac.packet_validator`, P61 `ac.other` 56–59). С P69:
  - `user_index` — только подтверждённая учётка сессии, до входа в мир — NULL. Прежде P55 писал заявленный номер, и он попадал в
    `v_top_offenders`/`v_account_daily` чужой учётке; P61 писал NULL всегда;
    соулмейтом, 3 соулмейт — учётка неизвестна) и `char_owner_user_index` (`CUser+0x174`: заявленный номер / хозяин персонажа);
  - адрес — живой `getpeername`, при отказе (клиент уже сбросил соединение) — IP этого соединения из кэша (снимается на первом
    приёме P61, сбрасывается на accept/разрыве; без P61 кэша нет).
- Ступень — строка `ac.other` вид **62**: `item_code` ступень 1..3, `value1` счёт, `value2` часы (−1 бессрочно), `opcode` 2271
  (Mode=1, отправлен), `detail` `P69 Mode=0: would block 24h; last P55 kind 1` / `P69 Mode=1: 2271 sent|FAILED …`. Ограничитель
  сессии P53 (`PerSessionPerMinute`) строки 62 не режет.
- Нарушения до входа в мир и операторов — только строка источника, без счёта.
