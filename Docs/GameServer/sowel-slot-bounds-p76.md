## 1. Что проверяется

Правила честного клиента (эталон `invItemDropSendPacket@0xD06BA0`, порт `AsdaSowelSubsystem`):

| Пакет | Обработчик | Тело в кадре | Допустимые значения |
|---|---|---|---|
| 5022 извлечение | `CharCellobItemDetach@0x4DBC30` | `[ebp-0x524]`, 4 б | +0 контейнер предмета ∈ {1, 3}; +3 номер гнезда ∈ [0, 3] (гнездо 0 законно) |
| 5024 вставка/замена | `CharCellobItemMove@0x4DC390` | `[ebp-0x534]`, 11 б | +0 контейнер предмета ∈ {1, 3}; +3 номер гнезда ∈ [0, 3]; +8 контейнер камня = 2 |
| 5031 «святость» | `CharSpendHolyItemUse@0x4DE590` | `[ebp-0xC8]`, 6 б | +0 и +3 (контейнеры) = 2 |

Поле вне допустимого → отказ ДО любой записи штатной веткой обработчика (той же, что при ответе «занят»):
5022 → 5023 код 0 (ветка 0x4DBDFB), 5024 → 5025 код 0 (0x4DC52A), 5031 → 5032 код 0 (0x4DEC9D; код обнулён на 0x4DE628).
Новых пакетов, кодов ответа и строк у клиента нет; честный клиент отказов не получает.

Другие обработчики, берущие номер гнезда из пакета, по сплошному скану `.text` не найдены; остальные обращения к гнёздам
предмета — фиксированные циклы по 4 гнёздам.

## 2. Механизм

Каждый из трёх обработчиков вызывает `sub_52BFF0` (thiscall: `ecx` = CUserManager, аргументы номер игрока и опкод, `ret 8`;
`al ≠ 0` → ветка отказа). Площадки: `call sub_52BFF0` по адресам 0x4DBDEF (5022), 0x4DC51E (5024), 0x4DE70E (5031) —
заменены вызовом стаба. Стаб зовёт сток (P63 пролог `sub_52BFF0` только сверяет, не перехватывает — вызов идёт прямо в сток), при `al ≠ 0` возвращает его без изменений, иначе
сверяет поля тела в кадре обработчика (`ebp` не меняется) и при нарушении возвращает `al = 1`.

Сверяемые байты (кроме площадок): аргументы и `this` перед вызовом, хвост `movzx/test/je` и ветка отказа после, `lea` тела
каждого обработчика, обнуление кода 5032 (0x4DE628), `ret 8` у `sub_52BFF0` (0x52C169). Расхождение — `Mismatch`, ничего не пишется.

## 3. Ключи `[P76_SowelSlotBounds]`

| Ключ | Умолчание | Смысл |
|---|---|---|
| `Enabled` | 1 | 0 — патч не ставится (сток) |
| `Mode` | 1 | 1 — отказ; 0 — только журнал |
| `JournalIntervalSec` | 10 | строка лога и журнала не чаще раза за столько секунд на (сессия, вид) |
| `LogChannel` | 1 | канал стокового лога (`Log_Item`) |

Журнал античита — `ac.other` виды 85 (5022), 86 (5024), 87 (5031), реестр `ac-journal-p53.md` §9. Строка лога:
`P76 SowelSlotBounds: <пакет> fields a/b/c out of range, <имя> UserNum N UserIndex M -> REFUSE (code 0)`.

## 4. Выкладка и откат

- Выкладка: остановить GameServer и Indun_GameServer → `python AstoryServer/Patches/AsdaPatch/tools/deploy_p76.py --apply` → старт.
  В PatchLog (`Log\Log_Patch\PatchLog_<дата>.txt`) — `[OK] P76_SowelSlotBounds` и строка `P76:`; Version в ini 47 → 48.
- Быстрый откат без замены DLL: `[P76_SowelSlotBounds] Enabled=0` (или `Mode=0` — только журнал) в обоих `patches.ini` + рестарт.
- Полный откат: `deploy_p76.py --rollback` (вернёт v47 `a3680675` из `.bak_20261021_p76`) + рестарт. Секция P76 останется в ini —
  v47 её игнорирует и сама вернёт Version.
- Рестарт нужен в обоих случаях.
