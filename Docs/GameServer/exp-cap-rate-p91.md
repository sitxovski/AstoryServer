# P91 — потолок опыта за моба × рейт события (GameServer + Indun_GameServer, 26.10.2026)

**[ИСПРАВЛЕНИЕ]** по решению владельца 26.10 («сделай правильно»). Жалоба игроков: «Exp x3 даёт только 10 %».
Разбор: `Reports/exprate/MOB_EXP_AUDIT.md` §1–§3, §8.

## Сток

Опыт за моба (`a5 = 0`) режется потолком **(ExpTable[ур+1] − ExpTable[ур]) / 9**:

| ветка | функция | площадка (35 б) | диапазон уровня | продолжение |
|---|---|---|---|---|
| одиночка (8301) | `Recv_BattleServerFromCharParamExp_1` @0x4CBA90 | 0x4CBC09 `push 0 / push 9 / … / call __alldiv / mov [ebp-100h],eax / mov [ebp-0FCh],edx` | `[ebp-100h]` i64 | 0x4CBC2C |
| отряд (8306) | `sub_4C7C70` @0x4C7C70 | 0x4C8012 (то же, `[ebp-118h]`) | `[ebp-118h]` i64 | 0x4C8035 |

Рейт (fEvent NpcServer + Lucky Hours `GameServerEvent.txt` + личные %) применяется раньше — в `GetExpUpDownValue`
@0x4CC3A0 — и потолком «съедается»: на ур. 1 x2 = x3 = x5 = 10 % за моба.

## Что делает P91

`потолок = диапазон × max(1, fEvent + LuckyHours) / CapDivisor`, не больше целого уровня (дальше — стоковое «≤ 0 → 1» и
зажим прибавки).

- **fEvent** — аргумент `a6` функции (`[ebp+1Ch]`, float; обе функции снимают 18h байт аргументов) — тот же, что получил
  `GetExpUpDownValue`. **LuckyHours** — тот же цикл, что у стока (0x4CC3FE…0x4CC492): первая строка «год/мес/день = сегодня,
  час_от ≤ час < час_до», массивы 0x5E23AC / 0x5E2414 / 0x5E247C / 0x5E24E4 / 0x5E26DC / 0x5E2744, счётчик WORD 0x5A7964
  (со знаком), `GetLocalTime`; сумма во float, как у стока.
- **Личные проценты в потолок не входят** (бафы/зелья param 53 − 54, опция 53 вещей, поля-усилители `CUser+0xBEBB/0xBEE5`,
  опция 103). Обоснование: потолок ограничивает прыжок за одного моба относительно темпа сервера; событие меняет темп для
  всех — потолок растёт вместе с ним; личный бонус ускоряет игрока относительно других внутри того же предела (так же, как в
  стоке). С личными % (на живом до +162 %) потолок на ур. 1–3 вырос бы до ~51 % уровня за моба — предел потерял бы смысл.
- `max(1, …)` — строже стока потолок не становится никогда (событие со значением < 1 его не урезает).
- Задания / GM 6032 / зелье P75 (`a5 = 1`) — не затронуты (стоковая ветка обходит площадку). Доля соулмейта-партнёра
  (`sub_4CC290` → `_1` с `a5 = 0`) получает тот же потолок.
- Рейт вне 0…20 или не число → потолок стока, журнал `ac.other` **118**; исключение → потолок стока, **119**; 120 свободен.

## Ключи `[P91_ExpCapRate]`

| ключ | умолч. | смысл |
|---|---|---|
| `Enabled` | 1 | 0 — площадки не ставятся (сток) |
| `CapDivisor` | 9 | делитель потолка (1…1000) |
| `CapScalesWithRate` | 1 | 0 — без рейта; `CapScalesWithRate=0` + `CapDivisor=9` = ровно сток |
| `SoloSite` / `PartySite` | 1 / 1 | площадки по отдельности |
