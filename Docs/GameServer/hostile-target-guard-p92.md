## 1. Правило оригинала — `sub_556DB0@0x556DB0`

`char __thiscall sub_556DB0(CUserManager*, short a2 /*исполнитель*/, short a3 /*цель*/, short a4 /*навык или −1*/)`, `ret 0Ch`;
0 — нельзя. Оба пользователя ищутся `sub_5324A0`; нет кого-то — 0. Вход перехвачен P42 C1 (скрытый оператор — 0).

Поля CUser (по дизассемблеру живого образа e7b4ac38, адреса в `verify_p92` §2):

| Поле | Смещение | Смысл |
|---|---|---|
| режим боя | byte `+0x3E8D2` | биты 1 дуэль / 2 свободный бой / 4 война; ставит только `sub_556BB0` (4206, дуэль `sub_4C2D00`, война `sub_464DF0`) и шлёт 4206 в NpcServer |
| соперник / команда | dword `+0x3E8D3` | дуэль — arrayIndex соперника; война — номер своей команды |
| arrayIndex | dword `+0xC` | номер слота пользователя |
| соулмейт | dword `+0x182B9` | id пары (`CSoulMateManager`, `sub_532770`) |
| клан | word `+0x18318` | `CClanManager sub_401070` |
| отряд | word `+0x1B4` | `CPartyManager sub_44F470` (в декомпиле — миснейм `GameMoney_gold_`) |
| команда цели | word `+0x3F44C` | номер команды войны цели |

Враждебность навыка: `SkillInfo.sif[a4]+52 == 6` (значения +52: 0 нет, 1 себя, 2 отряд, 5 любой игрок, 6 враг); у навыков
хранителя 1201…1200+N — `SoulGuarderSkillTable+46 == 6`. **Режим цели правило не смотрит.** Биты режима применяются подряд.

## 2. Таблица правил

| Режим исполнителя | удар `a4 = −1` и враждебный навык (+52 = 6) | невраждебный навык (+52 ≠ 6) |
|---|---|---|
| 0 | нельзя | можно на любого |
| бит 1 дуэль | только соперник (`+0x3E8D3 == цель+0xC`) | всем, кроме соперника |
| бит 2 свободный бой | всем, кроме своих (соулмейт / клан / отряд — поле ≠ −1 и совпадает) | только своим |
| бит 4 война | всем, кроме своей команды (`+0x3E8D3 ≠ −1` и `== цель+0x3F44C`) | только своей команде |

Хранитель (a4 ≥ 1201): режим 0 — нельзя всегда; биты — как в таблице, по `+46`. a4 = 1200 или вне таблицы при режиме ≠ 0 — нельзя.
`a4 = −1` во всех режимах ровно равен «враждебному навыку» — P92 зовёт `sub_556DB0` именно так.
Копия в NpcServer — `sub_426000@0x426000` (зеркало: режим `+0x10AA2`, соперник `+0x10AA3`, свои `+0x770C/+0x7708/+0x7706`,
команда `+0x10250`; синхронизация 4206 → `CAi::Process_SetUserBattleState sub_457AA0`, свои — `sub_458ED0`/`sub_45B5E0`).

## 5. Решение

«Можно» = `sub_556DB0(менеджер, исполнитель/владелец, жертва, −1) != 0` и жертва ≠ исполнитель (S1/S3; S4 само-наложение — сток).
Исполнитель или жертва не найдены — решение стока (S3/S5 — стоковый вызов). Нельзя — жертва пропускается стоковым переходом цикла:
нет 4102, урона, смерти, прока (S4 — запись целиком, S5 — отказ 5256). `Mode=0` — сток + журнал «было бы».

Последствия: в мирном режиме прок «Взрыв» и площадной прок хранителя по игрокам не бьют вовсе (по мобам их считает NpcServer — без
изменений); отражение 220 бьёт только врагов отражающего; «Клеймо льда» — только по врагу (дуэль, свободный бой, война).
