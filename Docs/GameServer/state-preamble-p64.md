## 1. Что не так в оригинале (по декомпилу `RE/ida/server_work/GameServer.c` и дизасму)

- «душа» `sub_52EEA0` (`BYTE CUser+0x182D3 == 1`) — у 71 опкода в самом диспетчере (`if (!sub_52EEA0) handler`, **молча**);

## 2. Что делает P64

Гейт `P64_StateGate(mgr, opcode, userNum, pkt)` зовётся из `P47_OperatorGate` **вторым** (после `P55_PacketGate`) с теми же
аргументами. Для опкодов шести семей (списки и маски — ключи ini) читаются **те же поля CUser, что читают стоковые предикаты**
(все смещения сняты дизасмом стока; `verify_p64.py` сверяет опорные инструкции в трёх образах, установка — `VerifyAllSites` по 9 опорным
инструкциям, несовпадение = `Mismatch`):

| запрет | стоковый предикат | поле CUser | опорная инструкция | кто пишет |
|---|---|---|---|---|
| не в игре (`ingame`) | `sub_532670@0x532670` | `BYTE +0x190 == 0` | `0x53269D mov al,[ecx+190h]` | логон |
| мёртв (`dead`) | `sub_4CB030@0x4CB030` (= код 1 `sub_52BFF0`) | `DWORD +0x4F != 0` | `0x4CB05D mov edx,[ecx+4Fh]` | `sub_4CB070 @0x4CB0E7` (CharMake тип 3 → 1; CharRegen* → 0), ClearUserMemory `sub_4A2DC0 @0x4A33EC → 0`; порт зеркалит как `bSelfDead` («CUser+79») |
| обмен (`exchange`) | `sub_52BFF0` код 2 | `DWORD +0x145` | `0x52C070 cmp [eax+145h],0` | `CharExchangeAcceptReq @0x4DFF27 = 1` |
| биржа (`auction`) | код 3 | `DWORD +0x15F` | `0x52C0A6 cmp [ecx+15Fh],0` | `sub_521980 @0x5219AE` (запрос в полёте) |
| лавка (`store`) | код 4 | `DWORD +0x14D` | `0x52C0DC cmp [edx+14Dh],0` | `CharSelfStoreReady @0x502D8C = 1` |
| рыбалка (`fishing`) | код 5 | `BYTE +0x3F6B4` | `0x52C10F movzx ecx,byte [eax+3F6B4h]` | `Recv_StartFishing @0x40F292 = 1` |
| душа (`soul`) | `sub_52EEA0` | `BYTE +0x182D3 == 1` | `0x52EECD` | 1016 режим 1 |
| одержим (`possess`) | `sub_52EE40` | `DWORD +0x182B9 > 0 && BYTE +0x182D3 == 2` | `0x52EE6D`, `0x52EE79` | 1016 режим 2 |

⚠ `sub_52BFF0` из гейта **не вызывается**: он не предикат — шлёт `6001 {опкод, код}` на **каждой** из 6 веток, включая код 0
(`push 0x1771` ×6, `call sub_4C28F0` ×6 — `verify_p64.py`). Вызов из гейта добавил бы опкодам без стокового 6001 новый пакет.

**Режим.** `Mode=0` (умолчание) — только журнал, обработчик вызывается как в стоке. `Mode=1` — **тихий пропуск** обработчика
(стаб P47 уходит в хвост switch `0x42F036`) — ровно так сток молча пропускает обработчик под гейтом «душа». Новых пакетов/кодов
нет, счётчик Hack Packet не трогается.

**RespectStockGates=1.** У опкодов, где `sub_52BFF0` стоит внутри обработчика (6162, 6502, 6506, 4201, 4203, 6158, 6165, 6176 —
xref дизасма, сверено по `GameServer.c`), запреты `dead` и `busy` **не дублируются**: иначе в `Mode=1` тихий отказ подменил бы
штатный ответ стока (4202 код 0 / 6001 код N / 6166 код 117). У них действует только `ingame` (+ `soul`/`possess`, если включены).

**Семьи и маски по умолчанию.**

| семья | опкоды | маска |
|---|---|---|
| `OpcodesEconomy` | 6096;6098;6549;6551;6553;5433;6555;6586;6140;6162;6502;6506 | `dead;busy;ingame` |
| `OpcodesPets` | 6100;6102;6108;6110;6112;6114;6116;6118;6121;6148 | `dead;busy;ingame` |
| `OpcodesCombat` | 4201;4203;6158 | `dead;busy;ingame` (→ фактически `ingame`, см. RespectStockGates) |
| `OpcodesFishing` | 6165;6167;6169;6171;6176;6178;6180;6182 | `dead;exchange;auction;store;ingame` (без `fishing`: 6169/6171 законно идут во время рыбалки) |
| `OpcodesQuest` | 6591;6593 | `dead;busy;ingame` |
| `OpcodesMisc` | 6150;6067;5428;6127 | `dead;busy;ingame` |

`busy` = `exchange;auction;store;fishing`. `Opcodes=` (общий список) пустой = объединение семей; заданный — только эти опкоды
(чужой опкод = семья «прочее»). **`soul`/`possess` по умолчанию выключены во всех семьях** — см. §5.

**Журнал.** `joylog1.ac.other` (P53), виды **40** не в игре, **41** мёртв, **42** занят, **43** «душа», **44** одержим;
колонки: `item_code` = значение поля (для «занят» — код 2…5 как у `sub_52BFF0`), `value1` = семья (1 экономика … 6 прочее),
`value2` = действие (0 журнал / 1 отказ), `detail` = имя обработчика (таблица `OpcodeLengths.h` P55). Только нарушения,
ограничитель на (сессия, вид) `JournalIntervalSec` (60 с), подавленные — `repeat_suppressed`. Плюс строка штатного лога сервера
`sub_569DF0(LogChannel=1 → Log_Item, "P64 StatePreamble: op N (handler) dead=1 family economy UserNum … -> JOURNAL ONLY (Mode=0)")`
и строка PatchLog (`LogHits`) под тем же ограничителем.

## 3. Площадки

Своих нет. Байты площадки P47 `0x42AB4F` (`8B45FC 0FB74807 898D38EFFFFF`, 13 б) одинаковы в стоке и живых; переходов внутрь — 0;
ветка `userNum < 10000` (`jge 0x42F0BC @0x42AA80`). Стаб P47 ставится и при `OperatorGmFlag=0`, если P64 включён (общая точка
`P64_GateWanted`, как `P55_GateWanted`). Порядок в реестре: P47 → … → P53 → P55 → … → P59 → **P64** (журнал стартует раньше, стаб уже стоит).

Правка `p47_identity_operator_gate.cpp` (ровно две точки):
1. в `P47_OperatorGate` после `if (!P55_PacketGate(...)) { return 0; }` добавлено `if (!P64_StateGate(mgr, opcode, userNum, pkt)) { return 0; }`;
2. в `P47_IdentityOperatorGate()` после `const bool p55 = P55_GateWanted();` добавлено `const bool p64 = P64_GateWanted();`,
   условие `if (g_gmGate || p55 || p64)`, строка лога «стаб гейта 0x42AB4F поставлен ради P55/P64».

## 4. Ключи ini `[P64_StatePreamble]`

`Enabled=1`, `Mode=0`, `Opcodes=` (пусто), `RespectStockGates=1`, `OpcodesEconomy/Pets/Combat/Fishing/Quest/Misc=…` и
`MaskEconomy/Pets/Combat/Fishing/Quest/Misc=…` (см. §2; токены `dead;busy;exchange;auction;store;fishing;soul;possess;ingame;none`),
`LogHits=1`, `LogChannel=1`, `JournalIntervalSec=60`. Требует `[P47_IdentityOperatorGate] Enabled=1` (иначе `Failed`, стаба нет).

## 5. Сверка с портом (честный путь = 0 срабатываний)

- Порт шлёт все опкоды списка только после входа в мир → `ingame` честно не срабатывает.
- Смерть: порт закрывает окна при смерти (`AsdaAfterDeathSubsystem.cpp:141-156`), рыбалка спрашивает `IsSelfDeadOrBusyFlag`,
  лавка/обмен/навыки/ремесло читают `bSelfDead`. Остаточный риск: окна, которые порт при смерти не закрывает (NPC-окна заточки,
  питомцы) — в `Mode=0` это строка журнала, не отказ; в стоке такой запрос обработался бы.
- Занятость: окна обмена/лавки у порта взаимно исключают остальные (`AsdaTradeStateSubsystem` «лавка открыта» 107022, обмен 2008);
  биржа «запрос в полёте» — замок на клиенте; `fishing` снят с семьи рыбалки.
- **«Душа»/«одержим»: сток эти опкоды НЕ гейтит, и порт повторяет диспетчер** (`AsdaPossessGate.cpp`: «ГЕЙТА НЕТ (и ставить
  нельзя) на … блоке 0x1777…0x182D», память `soul-state-1-system.md`: «без гейта проходят рефайн/разбор/шелл-апгрейд/ItemOptionTrans/
  PremiumSum»). Честный порт в этих состояниях шлёт 6549/6553/6555/4201 и т. д. → по умолчанию `soul`/`possess` **выключены**;
  включать по семьям ключами масок — решение владельца (это уже не «как в оригинале», а ужесточение). Стенд проверяет, что с
  умолчаниями «душа»/«одержим» не дают срабатываний, а с включёнными масками — дают (виды 43/44).

## 7. Откат

`[P64_StatePreamble] Enabled=0` — гейт возвращает 1 без чтений (стаб P47 остаётся, как и прежде). Прежняя DLL (Version 36)
понизит Version до 36, секция останется и будет проигнорирована.
