# P99_UpgradeSplitStone — разделение улучшения выдаёт камень своего типа (31.10.2026)

**Статус:** собрано и проверено, НЕ выложено (выкладка — координатор). Решение владельца 31.10: «Да, патчить».
**Ярлык:** [ИСПРАВЛЕНИЕ] — дефект оригинального сервера.

## Симптом
Окно «Разделение улучшения» 50500 (клиент `UAsdaUpgradeSplitSubsystem`, вход — двойной щелчок по пустому камню 203/205):
разделил оружие с улучшением ≥ +88 % — получил «Доспех — камень улучшения» (363, подтип 206), который клиент кладёт только
на доспехи и украшения (`itemIsValidColorMixPair@0xB65590`: 206 ↔ itemType ≤ 8, 204 ↔ itemType 9). Разделил доспех —
получил «Оружие — камень улучшения» (401, 204), который ложится только на оружие. Улучшение переносилось не на свой тип.

## Диагноз (6549 `Recv_UserUpgradeExtraction@0x534640`, GameServer.c:117761; asm живого `GameServer.exe` e7b4ac38)
* Тип вещи: `v30 = (Item_Table[код].+0x1A == 9) ? 2 : 1` — 0x534929…0x53493B (9 — оружие).
* Пустые камни сверяются верно: v30 == 2 ⇒ подтип 205 (`cmp eax,0CDh` @0x534AD5), иначе 203 (`cmp ecx,0CBh` @0x534B6C).
* Готовый камень (исходы 0/1) — наоборот:
  * `cmp ecx,1` @0x534DD0 (НЕ оружие) → запись special_itemlist 400 (`[+4B00h]` = 400·48): код 401, сверка `[+4B08h] == 0CCh` (204);
  * `cmp edx,2` @0x534E86 (оружие) → запись 362 (`[+43E0h]`): код 363, сверка `[+43E8h] == 0CEh` (206).

## Что меняет P99 (в памяти процесса; файл exe не трогается)
| адрес | инструкция | было | стало |
|---|---|---|---|
| 0x534DD2 | imm8 `cmp ecx, 1` | `01` | `02` |
| 0x534E88 | imm8 `cmp edx, 2` | `02` | `01` |

Оружие (v30 = 2) идёт в ветку записи 400 → камень 401 (204); прочее (v30 = 1) — в ветку записи 362 → камень 363 (206). Тела веток,
сверки подтипа, запись камня (+0 код, +12 вес, +50 байт) и строки лога стока не меняются; v30 после ветки читают только строки
лога (11)/(12)/(13). Протокол 6549/6550 не меняется. До записи P99 сверяет 7 участков (оба условия с переходами, обе сверки
подтипа, обе выборки кода, источник v30) — расхождение ⇒ MISMATCH, патч не ставится.

Чужие площадки в той же функции (P62 0x5349DB / 0x535202, P63 0x534655 / 0x535202) участки P99 не пересекают.
