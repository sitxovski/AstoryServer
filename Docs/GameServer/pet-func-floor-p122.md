## Как было (`sub_459AD0@0x459AD0`, GameServer.c:36358)
Значение каждой функции = (int)(множитель уровня `PetExp_Table` × значение `PetInfo_Table` / 100), затем сытость: ≤ 39 → 0, 40–59 → ×0,8, 60–79 → ×0,9 (дробь отбрасывается). Множители уровней 1–10: 30, 60, 100, 120, 125, 130, 135, 140, 145, 150.
Значение уходит клиенту в записи питомца и применяется к статам как процент (`sub_455F60` → `sub_43B750`). Живые 6106: 1011 значений, расхождений с формулой 0.
Таблицы оригинального клиента, Fantazium, сток сервера и наша стойка совпадают — +0 % и +1 % на 1-м уровне есть и у оригинала.

## Что делает P122
Площадка `0x459C0E` (7 б: `mov edx,[ebp-4]; mov [ecx+eax+19h],edx` — запись значения i-й функции) → заглушка `St_FuncFloor` → `P122_Floor(ebp, значение)`:
при сытости от 40 значение = max(расчёт стока, `PetInfo[порода].значение_i`), при сытости ≤ 39 — 0, как у стока (слово владельца «0, как сейчас»), табличное читается там же, где его читает сток (`[0x7E0004] + 60·порода + 6·i + 0x24`, число пород `[0x7E0008]`). Затем штатная запись и переход на `0x459C15`. Протокол не меняется; клиент (alpha-7.0.0 и оригинал) печатает присланное.
Соседних площадок в 0x459AD0…0x459C20 нет.

## patches.ini `[P122_PetFuncFloor]`
`Enabled=1` (0 — сток) · `FloorWhenHungry=0` (по умолчанию, слово владельца: у голодного при сытости ≤ 39 остаётся 0, как у стока; 1 — пол и у голодного).
Откат: `Enabled=0` + рестарт, либо прежняя DLL (секция останется и будет проигнорирована, Version DLL понизит сама).
