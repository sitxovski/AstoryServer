**Доказательство S1/S2.** Во всей `sub_44F4C0@0x44F4C0` (5090) ровно ПЯТЬ сравнений:
`0x44F50C` (результат `sub_523F00` — подпись тела, на живом РАБОТАЕТ), `0x44F557` (отправитель
найден), `0x44F59C` (цель найдена), `0x44F5F6` (тип зоны == 4), `0x44F60F` (отряды армий совпали).
Сравнения `[ebp+8]` (charIndex отправителя) с `[ebp-0x6C]` (userNum цели) — **нет**, обращений к
состоянию отряда отправителя — **нет**. В `sub_44FDE0@0x44FDE0` (5094) список тот же
(`0x44FE2C`, `0x44FE77`, `0x44FEBC`, `0x44FF16`, `0x44FF2F`) с тем же результатом.

**Семантика полей `CUser`** (доказана записями `GameServer.c:31997-32001` и `:32230-32231` плюс
идиомой чтения `if (*(__int16*)(x+436) >= 0)` на `:32709` и `:32779`):
`+0x1B4` (436) i16 = индекс отряда, **отрицательный = «не в отряде»**;
`+0x1B6` (438) u8 = **1 у главы**, 0 у рядового участника.

**Доказательство S3** — живой дизассемблер, два подряд вызова `sub_532570`:
```
0044FCEB  66 8B 45 E4   mov ax,[ebp-0x1C]   ; partyBody[0] — ПРИГЛАСИВШИЙ
0044FCF9  E8 …          call 0x532570       ; -> имя пригласившего
0044FD12  E8 …          call 0x467AD0       ; (…, partyBody[0], idx, имя)     ВЕРНО
0044FD17  66 8B 45 E4   mov ax,[ebp-0x1C]   ; ★ СНОВА пригласивший
0044FD25  E8 …          call 0x532570       ; -> имя ПРИГЛАСИВШЕГО
0044FD30  66 8B 4D EA   mov cx,[ebp-0x16]   ; partyBody[3] — приглашённый
0044FD3E  E8 …          call 0x467AD0       ; (…, partyBody[3], idx, ЧУЖОЕ имя)
```
⇒ в квестовой регистрации отряда (ветка «зона типа 4») приглашённый получает имя пригласившего.

## 2. Площадки: байты ДО и ПОСЛЕ

### 2.1 `FixSelfInvite` + `FixPartyStateGuard`, обработчик 5090

| | |
|---|---|
| Площадка | `0x0044F5D9`, **6 байт** (две команды целиком) |
| Сверяется | 18 байт `8B 55 8C · 8B 42 04 · 8B 88 50 49 00 00 · 69 C9 EC 00 00 00` |
| БЫЛО | `8B 55 8C 8B 42 04` (`mov edx,[ebp-0x74]` / `mov eax,[edx+4]`) |
| СТАЛО | `E9 rel32 90` (`jmp Party5090Guard`, шестой байт — NOP) |
| Возврат | `0x0044F5DF` (площадка + 6) |
| Отказ «уже в отряде» | `0x0044F650` — трамплин кладёт код **8** в `[ebp-0x64]` и прыгает сюда, переиспользуя штатную отправку 5091 |
| Отказ «сам себя» | `0x0044F7AD` — штатный эпилог, **молча, без пакета** |

Дополнительно сверяется (не переписывается) ветка отказа `0x0044F64C`, 12 байт:
`C6 45 9C 0B · 6A 01 · 6A 00 · 8D 55 9C · 52`.

Логика трамплина:
```
если FixSelfInvite и (i16)[ebp+8] == (i16)[ebp-0x6C]  -> jmp 0x44F7AD   (молча)
если FixPartyStateGuard и (i16)[[ebp-0x68]+0x1B4] >= 0 -> [ebp-0x64]=8; jmp 0x44F650
иначе  mov edx,[ebp-0x74]; mov eax,[edx+4]; jmp 0x44F5DF                (как в стоке)
```
Код **8** выбран не наугад: `Party_DispatchEventNotice@0xF388E0` в клиенте переводит его в нотис
**1047** «Ты уже состоишь в отряде» — ровно то, что и произошло. Новых кодов не вводим.

### 2.2 `FixPartyStateGuard` (+S4), обработчик 5094

| | |
|---|---|
| Площадка | `0x0044FEF9`, **6 байт** |
| Сверяется | 18 байт `8B 55 A0 · 8B 42 04 · 8B 88 50 49 00 00 · 69 C9 EC 00 00 00` |
| БЫЛО | `8B 55 A0 8B 42 04` (`mov edx,[ebp-0x60]` / `mov eax,[edx+4]`) |
| СТАЛО | `E9 rel32 90` (`jmp Party5094Guard`) |
| Возврат | `0x0044FEFF` |
| Отказ | `0x004500AB` — штатный эпилог, **молча, без пакета** |

```
если FixSelfInvite и (i16)[ebp+8] == (i16)[ebp-0x58]      -> jmp 0x4500AB
если FixPartyStateGuard:
    (i16)[[ebp-0x54]+0x1B4] < 0                            -> jmp 0x4500AB   (не в отряде; это же и S4)
    (u8)[[ebp-0x54]+0x1B6] != 1                            -> jmp 0x4500AB   (не глава)
иначе  mov edx,[ebp-0x60]; mov eax,[edx+4]; jmp 0x44FEFF
```
★ **Почему здесь отказ молчаливый, а у 5090 — с кодом.** У ответа 5095 нет кода со смыслом «ты не
глава»: `Notice_ShowResultByCode@0xF391F0` знает коды 1…0xB, и ни один этого не означает.
Выдумывать новый код значило бы менять и клиента. Штатный клиент сюда не приходит вовсе — его
собственные гейты 1047/1089 не дают отправить пакет, — поэтому молчаливый отказ ничего не ломает.

## 3. Условие применимости

* Образ — `GameServer.exe` MD5 `E7B4AC38E8328AAA847BBD9BF261BB01` (живой на 2026-08-29).
* Сверка **всех включённых площадок идёт ДО первой записи**: не совпала хотя бы одна — не ставится
  ничего (`PatchResult::Mismatch`). Частично поставленный патч хуже неповставленного.
* Ключи ini (секция `[P20_PartyInviteValidation]`), все по умолчанию `1`:
  `Enabled`, `FixSelfInvite`, `FixPartyStateGuard`, `FixQuestNameCopyPaste`.

## 4. Как проверить после подмены

1. `PatchLog` при старте должен содержать строку `P20 S1/S2/S4 …` с адресами площадок
   и строку `P20 S3 … байт 0x0044FD1A: E4 -> EA`. `MISMATCH` означает несовпадение образа —
   ставить нельзя, перечитать адреса.
2. Штатный путь не должен измениться: обычное приглашение в отряд из клиента (кнопка окна 2250)
   создаёт отряд ровно как раньше — в логе GameServer `NewPartyReq … End` и `NewPartyRes
   PartyCreateSuccess`.
3. Негативные проверки делаются НЕ штатным клиентом (он их не может отправить), а нашим портом:
   `asda.Party.*` умеет собрать любой из этих пакетов. Ожидаемо: самоприглашение — тишина;
   приглашение при уже имеющемся отряде — ответ 5091 с кодом 8 и нотис 1047 в клиенте.

## 6. Почему «S5» здесь нет

Первая редакция отчёта `party_invite_2250.md` утверждала, что `sub_523F00@0x523F00` считает MD5,
вызывает `memcmp` и **выбрасывает результат** (`return 1` безусловно), то есть подпись тела не
проверяется. Это **ДУБЛЬ уже разобранного P19-S1** и **опровергнуто для живого сервера**:

| VA | наш образ | живой |
|---|---|---|
| `0x00523F8B` | `EB 47` (`jmp`) | `74 47` (`je`) |
| `0x0052400D` | `EB 41` (`jmp`) | `74 41` (`je`) |

В живом образе ветка несовпадения MD5 полностью на месте. Наша локальная копия — сборка со снятой
защитой (MEMANTO `gameserver-decompile-stale`). Подробности и диагностический ключ
`ReportMd5GateState` — в `GameServer/auction-record-bounds-p19.md` §1 и §5. Новой заявки не заводим.

## 7. Риски и связанное

* Трамплины портят `eax`/`ecx`/`edx` и флаги — безопасно: вытесненные команды сами задают `edx` и
  `eax`, `ecx` задаётся первой же командой после возврата (`mov ecx,[eax+0x4950]`), флаги там же
  переопределяет `imul`.
* Штатный путь не трогается: при выполненных условиях трамплин исполняет ровно те две вытесненные
  команды и возвращается на `площадка+6`, байт в байт.
* Связанное: P19 (тот же образ, соседние площадки не пересекаются), клиентская половина цепочки —
  `Reports/party_invite_2250.md`.
