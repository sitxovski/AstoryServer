# P94 — сообщения Друга не уходят самому себе и чужой паре; сброс устаревших строк CharPos (26.10.2026, волна charpos)

[ИСПРАВЛЕНИЕ] дефекта оригинала. Протокол клиента не меняется. Отчёт с доказательствами: `Reports/soulmate_self_echo/SERVER_FIX.md`.
Клиентская защита того же бага — ключ `asda.Soulmate.SelfEchoGuard` (волна smbar-self).

## Дефект

1. **Источник — `dbo.CharPos`.** При входе `UPCharSoulMate` (DBManager, 3 места: 0x409325, 0x418DB5, 0x42F285) берёт слот Друга и признак
   «в игре» из строки `CharPos` Друга с `Usernum <> -1`. В CUser это блок `+0x182B9` (`+99001` Smidx, `+0x182C6` учётка Друга,
   `+0x182CA` слот Друга, `+0x182CC` «Друг в игре», `+0x182CD/CE` Gsidx/Threadidx, `+0x182CF` карта, `+0x182D0` канал).
2. **Строка устаревает.** Сброс «в игре» есть только в `UPLogOutGame`, `UPLogOutCharacter`, `UPSoulLogOutGame`, `UPUserLogin` (повторный
   вход при `Us_member.Flag = 1`) и `UpGameServerStart`. Последнюю зовёт RelayServer **только при разрыве** с GameServer
   (`CConnectionManager::Disconnect`, RelayServer.c:740). Сток «сброс слота при разрыве» мёртв: DisConnectUser шлёт 2171
   (GameServer.c:111291), но обработчик DBManager `sub_4265C0` пуст, а тело `UPUserNumClear` закомментировано. Поэтому строка зависает:
   - **после портального выхода без входа на новую карту.** 5056 → `CharPortalLogoutReq` → `PortalDisConnectUser` → `UPPortalLogOut`.
     Эта процедура `Usernum` не трогает, а `Us_member.Flag` = 0. Переход зависает, клиент закрывают, игрок уходит в одержимость;
   - **после остановки всей стойки** (`restart_stack`): Relay гибнет вместе с GS.
3. **Маршрут сообщения.** Пара шлёт relay-сообщения 3309/3311/3313/3319 на слот Друга. RelayServer доставляет их как 3310/3312/3314/3320,
   а обработчики получателя отправителя не сверяют:

   | relay | обработчик (GameServer) | клиенту | что делает |
   |---|---|---|---|
   | 3314 ← 3313 `sub_4940C0` | `recv_1` 0x4945B0 | 5110 | «Друг вошёл»; при @23 = 1 записывает отправителя Другом (+0x182C6…+0x182D2), 5220, ответ 3313 |
   | 3310 ← 3309 `sub_493A90` | `recvSoulMateStateInfo` 0x493CB0 | 5112 | сведения Друга (CUser не ищет) |
   | 3312 ← 3311 `sub_494870` | `sub_4949C0` 0x4949C0 | 5227 | место Друга; Smidx сверяет сам (0x494A21) |
   | 3320 ← 3319 `sub_493D80` | `sub_494010` 0x494010 | 5111 | сведения Друга |

   Если слот совпал с самим отправителем, игрок получает о себе «Друг вошёл» и записывает себя Другом. Если слот занят посторонним,
   тот получает чужого Друга.

**Разметка relay-пакета** (сверена дизасмом отправителей и получателей, `verify_p94.py` §2): @0 Smidx отправителя (`+0x182B9`),
@4 слот отправителя, @6 карта (`sub_40C960` = `[CUserManager+0x8E9]`), @7 канал (`sub_4A7EB0` = байт `0x5F5EB4`; у 3313 канал @9),
@10 цель (слот Друга `+0x182CA`; у 3313 цель @16), у 3313 ещё @12 учётка персонажа отправителя (`sub_5324F0` = `CUser+0x174`)
и @23 признак входа.

## Исправление

### AsdaPatch P94 `[P94_SoulmateSelfEcho]` (GameServer, Indun_GameServer, Ch2_GameServer)

Четыре площадки стоят после стоковых проверок и до отправки клиенту. Трамплин сохраняет все регистры и флаги (pushfd/pushad).
- S1 `recv_1` @0x494631 (`mov edx,[ebp-214h]`), продолжение 0x494637, пропуск — эпилог 0x494855;
- S2 `recvSoulMateStateInfo` @0x493D2B (`push 0A8h`) → 0x493D30 / 0x493D71;
- S3 `sub_4949C0` @0x494A2F (`mov edx,[ebp-1Ch]; mov ax,[ebp-10h]`) → 0x494A36 / 0x494A98;
- S4 `sub_494010` @0x49407C (`push 32h; lea ecx,[ebp-37h]`) → 0x494081 / 0x4940B0.

Решение `P94_Decide(площадка, ebp)`:
- **«себе»** (вид 130): слот отправителя = цель, карта пакета = карта потока получателя, канал пакета = канал процесса. У 3314
  достаточно и совпадения учётки (@12 = `CUser+0x174` получателя; так ловится одержимость: персонаж одержимого = отправитель);
- **«чужая пара»** (вид 131, `ForeignCheck`, только S1/S2/S4): у получателя есть пара (`+0x182B9` > 0), и она не та, что в пакете.
  У обеих сторон пары Smidx общий (`Joy1.dbo.SoulMate`). Если Smidx ≤ 0 (пара создаётся, гонка 3313 a4 = 2), решает сток.

Ключи (умолчания): `Enabled=1`, `Mode=1` (0 — только журнал), `ForeignCheck=1`, `JournalIntervalSec=10`, `LogChannel=0`.
Журнал `ac.other` 130/131/132 (132 — исключение, решение стока).


- `dbo.UP_AsdaCharPosReset` — полный сброс при **остановленной** стойке. Его зовёт `restart_stack.py`, шаг 4в, перед `start.bat`.
  Тело — оригинальный операторский `OP_StartinfoInit`: `State 3` сохраняется. Плюс `Partyidx -1 / Captain 0 / SoulState 0` и сброс
  `Us_member Flag 0 / UserNum -1`. Без процедуры шаг 4в пишет «пропуск» и стойку не останавливает;
- `dbo.UPSameUser` — стоковое тело дословно плюс сброс брошенного портального выхода. Условие: `Usernum <> -1`, `Us_member.Flag = 0`,
  `LastDate` старше 180 с. DBManager зовёт процедуру раз в ~60 с на каждый поток карты. Переход клиента ограничен 150 с, а живой
  переход за это время приходит в `UPUserNumUp`, который ставит `Flag 1`. Ошибка сброса стоковую часть не ломает (TRY/CATCH);
- `dbo.CharPosResetLog` — журнал: что, когда и кем сброшено (`restart_stack` | `sweep`).
