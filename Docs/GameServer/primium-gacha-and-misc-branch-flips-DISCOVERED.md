## A. `Recv_UserPrimiumGaCha@0x4F6F10` — дополнительная отправка

**Перехват @ `0x4F7084`** (26 байт): исходный блок
`movsx eax,byte[ebp-5Ch]; imul eax,6; mov ecx,[7E0380h]; mov edx,[ecx+eax+2]; mov [ebp-48h],edx;
mov al,[ebp-5Ch]; mov [ebp-55h],al` заменён на `E9 BA B7 08 00` + `90×21` → `jmp 0x582843`.

**Cave @ `0x582843`:** исходные инструкции воспроизведены, затем:
```
sub  esp,78h ; lea ecx,[esp] ; call 0x4FAD00      ; конструктор структуры 0x78 байт на стеке
… заполнение полей [esp+1], [esp+5], [esp+6], [esp+5Eh], [esp+67h] …
lea  eax,[esp] ; push eax
mov  dx, word ptr [ebp+8] ; push edx              ; userNum
push 69h                                          ; 105
mov  ecx,[ebp-68h]
call 0x4F60E0
add  esp,78h
jmp  0x4F709E
```
⚠ **Назначение — гипотеза.** `sub_4F60E0` в декомпиле не назван; по форме (`ecx`=менеджер,
`push 105`, буфер 0x78) это отправка пакета/записи, добавленная в путь премиум-гачи (вероятно,
лог/выдача, отсутствовавшая в стоке). Требует отдельного разбора.

## B. `sub_4F6650` — отправка DB-пакета 2601 (0xA29)

**Перехват @ `0x4F6CA5`** (6 байт): `89 95 43 FD FF FF` (`mov [ebp-2BDh], edx`) → `E9 56 BC 08 00 90`
→ `jmp 0x582900`.

**Cave @ `0x582900`:**
```
cmp  byte ptr [ebp-0D8h], 1
jne  0x4F6E42                                   ; условие не выполнено → назад
mov  [ebp-2BDh], edx ; mov eax,[ebp-2Ah] ; mov [ebp-2B9h],eax   ; исходные + доп. поле
mov  ax, word ptr [ebp-8] ; push eax
lea  eax,[ebp-328h] ; push eax
mov  eax,[ebp-344h] ; mov ecx,[eax+4] ; call 0x4C0A30
push eax
push 78h                                        ; длина 120
push 0A29h                                      ; опкод 2601
mov  ecx, 7E0538h
call 0x5646C0                                   ; отправка в DBManager
jmp  0x4F6E42
```
⚠ **Назначение — гипотеза:** добавлена запись в БД (пакет **2601**, 120 байт) при выполнении
условия `[ebp-0xD8] == 1` в этой ветке.

## C. `sub_43C690` — ранний выход

**Перехват @ `0x43C6DD`** (9 байт): `8B 45 E0 8B 88 53 04 00 00` → `E9 6B 62 14 00 90×4` → `jmp 0x58294D`.

**Cave @ `0x58294D`:**
```
mov  eax,[ebp-20h]
cmp  dword ptr [eax+3BC3Dh], 0
je   0x582960
mov  al, 1 ; jmp 0x43C895            ; поле ≠ 0 → вернуть 1 (пропустить проверку)
0x582960: mov ecx,[eax+453h] ; jmp 0x43C6E6
```
⚠ Поле `CUser+0x3BC3D` — то же, что в «неуязвимости» (док
`operator-skillpoint-log-and-invincible-gate-DISCOVERED.md`, п. B). Похоже на «GM/неуязвимый
игрок проходит проверку автоматически».

## D. Группа переворотов ветвлений (11 байт)

| VA | функция | было → стало | смысл (⚠ частично гипотеза) |
|---|---|---|---|
| `0x5120B2`, `0x5120FF`, `0x512725`, `0x512772` | `CharChargeShopBuy@0x511DA0` | `74`(je) → `EB`(jmp) ×4 | безусловный переход — **проверка снята** (кэш-магазин) |
| `0x523F8B`, `0x52400D` | `sub_523F00` (проверка подписи пакета) | `EB`(jmp) → `74`(je) ×2 | **проверка MD5 ВКЛЮЧЕНА** обратно (в стоке она была закорочена и функция всегда возвращала 1) |
| `0x526CFC`, `0x526D3B`, `0x526D7A`, `0x526DB9` | `CheckDisConnectUser@0x526C20` | `EB` → `74` ×4 | восстановлены условные ветки отключения клиента |
| `0x526DEE` | `CheckDisConnectUser` | `EB` → `7E`(jle) | то же |
| `0x4A53E1` | (район `sub_4A5xxx`) | `E9 6A D4 0D 00 90 90` → `83 FA 03 74 02 EB 8E` | вместо безусловного перехода — `cmp edx,3 ; je +2 ; jmp -0x72` |
| `0x4ED8DE` | `Char_FunctionItem_Use@0x4ED780` | `E8 1D 66 03 00 85 C0 75 42` → `83 C4 10 6A 01 58 EB 43 90` | вызов+проверка заменены на «результат = 1» (проверка снята) |

★ Практический вывод для нас: **`sub_523F00` в живом билде реально проверяет MD5 тела пакета** —
это учтено в патче `rare-item-notice-6616-handler.md` (обработчик 6616 вызывает её с длиной 24,
что совпадает с тем, что подписывает клиент в `netSendSignedPacket6616@0xA0F140`).

Также изменён заголовок PE: число секций 5→4 (удалена секция `.mapext`, её дескриптор обнулён по
файловому смещению `0x288..0x297`, характеристики `0x2AC..0x2AF`), поправлены `SizeOfCode`/`SizeOfImage`.
