## 2. Что делает P74
Себе пакет уходит **как в стоке** (тот же `SendPacket`, те же аргументы и `ecx`), затем **тот же** пакет — соседям по сектору 3×3
**кроме себя**: `sub_52E6D0@0x52E6D0 → SendPacket_ClippingSectorInOtherUser@0x41EA80` (фильтр получателей тот же, что у стоковой
рассылки типов 2/4: `CUser+0x2E`, `+0x174 ≠ −1`, `+0x141 == 0`; заголовок «от» = 0 — как у пакета себе; паддинг `a7 = 1` — как в стоке).

| площадка | было | стало |
|---|---|---|
| S1 `0x0043C854` (sub_43C690) | `E8 97 60 08 00` — `call 0x4C28F0` | `E8 rel32` → `StubDamage` (AsdaPatch.dll) |
| S2 `0x0043CE82` (SetCurrentHpTimeValue, ветка «не 2/4») | `E8 69 5A 08 00` — `call 0x4C28F0` | `E8 rel32` → `StubTime` |

Сверяются ДО записи (иначе Mismatch, ничего не пишется): обе площадки; аргументы `0x43C83A`/`0x43CE68` (push 1/0/тело/кому/11h/0FDAh,
`ecx=[[ebp-28h|40h]+4]`); продолжения `0x43C859`/`0x43CE87`; гейт типов `0x43CE34`; тип 0 в `sub_448850` (`0x448876`).
Заглушка: `push ebp; mov ebp,esp; push ecx; 6× push аргументов; call [g_pSendPacket]; push eax; push <площадка>; push тело/кому/опкод/net;
call P74_AfterSelfSend; pop eax; mov esp,ebp; pop ebp; ret 18h` — соглашение SendPacket, ebx/esi/edi/ebp сохранены, eax = результат SendPacket
(после вызова на обеих площадках eax/ecx/edx не читаются). Переходов внутрь площадок нет ни в одном образе (скан .text).

Гейты рассылки соседям (`P74_AfterSelfSend`) — в редакции 1; **ред. 2 меняет типы 1/6 и прореживание — §9**:
- только опкод 4058, номер 0..549, тело того же игрока (`+0 == кому`), менеджер `net+0x34`;
- **только «тихие» типы**: S1 — тип 0; S2 — типы маски `TimeTypeMask` (умолч. 41 = 0/3/5); типы **1/4/6 никогда** (клиент рисует цифру),
  2/4 — никогда (сток шлёт сектору сам);
- скрытый оператор (`CUser+0x3BC3B == 300` и `IsOperatorIndex`, как P41) — соседям нет (`SkipHiddenOperators=1`);
- прореживание на игрока: S2 не чаще `RegenMinIntervalMs` (250), S1 — `DamageMinIntervalMs` (0 = каждый удар); **HP ≤ 0 и HP ≥ максимума — всегда**.

PatchLog: строки установки обеих площадок и строки `[P74] …: 4058 соседям по сектору №N` для первых 3 рассылок каждой площадки и далее
каждой 100000-й (`LogEvents=1`). Журнала античита нет (не нарушение).

## 3. Безопасность для текущего клиента (alpha-1.0.0 от 16.10)
Обработчик 4058 (`AsdaNetSubsystem.cpp`, `case OP_NET_HANDLE_HP_MP_UPDATE`), `SetVitalsHp`, `AsdaSelf::IsSelfUserIdx` и подписчики
`AsdaWorldSubsystem::OnVitalsChanged/OnVitalsFx/ApplyVitalsToNameplate` **побайтно одинаковы** в бэкапах 15.10 (`2026-10-15_mobpos`),
16.10 (`2026-10-16_eac_e1`, `2026-10-16_net_domain`) и в текущем исходнике — выпущенный клиент обрабатывает 4058 так же:
- ключ — `userIdx` i16 из тела (`+0`), то есть тот же номер сессии `userNum`, что и в стоковых рассылках 4058 типов 2/4 (они уже приходят
  соседям); charId (i32) в 4058 не участвует;
- `SetVitalsHp(Uidx, …)` пишет **только** запись `VitalsByUserIdx[Uidx]` соседа;
- свои HUD/окно персонажа (`UAsdaMiniStateSubsystem`, `UAsdaCharaInfoSubsystem`) отсекают чужой номер `IsSelfUserIdx` (строгая форма:
  номер известен из 4003 и равен своему) — своё HP не трогается;
- цифра дельты (`OnVitalsFx` → `SpawnOverActor 0x12`) — **только для типов 1/4/6**; P74 шлёт соседям типы 0/3/5 — цифр нет
  (ред. 2: типы 1/6 — копией с типом 0 и навыком −1, `AsdaNetSubsystem.cpp:11627` — тихая запись);
  звуков и нотисов в обработчике 4058 нет;
- мир: `ApplyVitalsToNameplate` — полоса плашки актора соседа (нет актора — выход), панель цели берёт `GetVitals(номер цели)`.
Побочное (не вред): у соседа на плашке может появиться подложка «второго» HP (`+13`, остаток зелья) — то же, что уже бывает после типа 2.
