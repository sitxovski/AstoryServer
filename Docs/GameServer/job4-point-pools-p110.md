# P110 — два пула очков навыков: основные деревья (110) и дерево 4-й профессии

Сессия job4-points, 05.11.2026. AsdaPatch v67 (поверх v65 P108 и P109 сессии job4-skills, одна сборка из общего дерева).
Метка: [ИСПРАВЛЕНИЕ]. Протокол не меняется.

## Жалоба

«4-я профессия: можно выйти за лимит очков. Изучаю навыки сверх лимита, уже −8. Тратятся очки из основного дерева,
а в дереве 4-й профессии счётчик уходит в минус.»

Воспроизведено на живом dev (клиент alpha-6.1.0, сервер AsdaPatch v65):

|---|---|---|---|---|---|---|---|
| Player58 | 75210/10 | 70 | 10 | 30 | 92 | **−8** | 4-я профессия взяла 8 очков основного пула |
| Player17 | 75214/10 | 70 | 132 | 0 | 0 | 22 (основной «−22») | основные деревья на 22 сверх 110 |

## Как устроены очки (эталон клиента + декомпил сервера, все ветки)

* **Счёт у сервера один**: word `CUser+0x19B` = `Charinfo.SkillPoint`. Всего очков = 2·ур.−8: +2 за уровень `sub_52E8A0`
  (сток: только до 59-го, P29 поднял потолок), полный сброс `sub_52E900` ставит 2·ур.−8, изучение — `sub_52E9E0`.
* **Вложено по деревьям**: dword `CUser+0xC024+4·дерево` = сумма уровней навыков дерева: загрузка `sub_475290`
  («+= уровень»), изучение `sub_47E9B0` («++»), сброс дерева `sub_480F20` («−= уровень»), полный сброс `sub_4803A0` (обнуление).
* **Дерево навыка** — `SkillInfo.sif +0xBD` (запись 209 б, `dword_5F5E4C`): 1–3 боец, 4–6 лучник, 7–9 маг — основные;
  10 / 11 / 12 — 4-я профессия бойца / лучника / мага. `+0xBE` — сколько нужно вложить в дерево (гейт кода 6).
* **Клиент оригинала делит счёт на два пула**: `Skill_BuildTreeUI@0xE532E0` — счётчик 12413 (SKILL_POINTTXT2) = «(вложено во все
  деревья + свободные) − 110 − вложено в 4-ю» = «основные + свободные − 110», при уровне < 60 — «0»;
  `skillUiUpdatePointText@0xE56720` / `skillwin_OpenSkillWindow` — счётчик 1092 при уровне ≥ 60 = «110 − основные».
  110 = все очки до 59-го уровня (2·59−8): пул 4-й профессии — очки с 60-го уровня.
* **Изучение**: клиент `skillWndSelectSlot@0xE53C80` (очки > 0, уровень < максимума, «доступен») → вопрос 9415 → 5253
  (4 б: навык, флаг 1, число 1). Сервер `Recv_SkillPoint_SkillActive@0x4774C0` → 5254: код 3 (очков < числа), 0 (навыка нет),
  6 (вложено в дерево < требования), 2 (уровень на максимуме), 1 (успех: очки, навык, уровень). Клиент оригинала знает и
  код 7 (111700 «не для твоей профессии») и **код 8 (111701 «недостаточно очков навыка после 4-й профессии»)** — старый сервер их
  не шлёт никогда.
* **Сброс**: дерево — `sub_480F20` (свиток 197, 5464 очки + grade, затем 5251): навыки с требованием удаляются, без требования —
  уровень 0; очки возвращаются. Полный — `sub_4803A0` (5462 очки, затем 5251).
* **Процедуры БД** (`UPSkillUP`, `UPSkillPointUP`, `UPCharSkillinit`) пишут то, что прислал сервер, без проверок.

## Причина

Проверки пулов нет ни в клиенте оригинала (гейт — только общий счёт > 0), ни на сервере (только `free ≥ число`).
Стоковый сервер держал потолок 59 → у него всего очков было ≤ 110 и второго пула не существовало; клиент — от более
поздней версии с 4-й профессией и кодом 8. P29 поднял потолок до 100 → появились очки сверх 110, и любое изучение брало их из
общего счёта: навык 4-й профессии — очки основного пула (Player58), основной навык — очки 4-й профессии (Player17).
Дефект оригинала (сервер старее клиента). Клиент порта повторял гейт оригинала.

## Исправление

**Сервер P110** (`src/patches/p110_job4_point_pools.cpp`): площадка `0x4778B3` (14 б, начало списания — ПОСЛЕ всех отказов
стока) → трамплин → `P110_Check(CUser, навык, число, свободные, userNum)`:
* дерево ∈ `Job4Trees` (10,11,12): остаток = ур. ≥ `MinLevel` (60) ? основные + свободные − `MainCap` (110) : 0; < числа → 5254 код 8;
* дерево ∈ `MainTrees` (1…9): остаток = `MainCap` − основные; < числа → 5254 код 3;
* дерево 0 / вне таблицы / учётка ≤ `ExemptMaxUserIndex` (0 = никого) — сток.
Отказ — запись кода в `[ebp-0CCh]` и вход в стоковый блок отказа `0x47787A` (тот же 5254, деструктор, выход).
Журнал `ac.other` 171 (4-я), 172 (основные), 173 (исключение — сток), ограничитель `JournalIntervalSec`; строка Log_Operator.
patches.ini `[P110_Job4PointPools]`: Enabled, Mode (0 — только журнал), MainCap, MinLevel, Job4Trees, MainTrees, Job4RefuseCode,
MainRefuseCode, ExemptMaxUserIndex, JournalIntervalSec. Откат: Enabled=0 или `deploy_p110.py --rollback`.

**Клиент** (`asda.Skill.Job4Pools`, по умолчанию 1; `AsdaSkillWindowSubsystem.cpp` `ComputePointPools`): счётчик 1092 при
ур. ≥ 60 = min(свободные, 110 − основные), 12413 = min(свободные, основные + свободные − 110), ниже 60-го — свободные / 0
(отрицательное число — долг старых данных, не прячется); подсветка «можно учить» и клик — по пулу навыка; при пустом пуле —
msgbox 111701 (4-я) / 2202 (основные), 5253 не уходит. 0 — прежнее.

`fix` (транзакция: бэкап `dbo.AsdaJ4Bak_CharSkill/Charinfo`, журнал `dbo.AsdaJ4FixLog`, сброс дерева по правилу `sub_480F20`:
с требованием — удалить, без требования — уровень 0 и статы нулевого уровня из SkillInfo (формула сверена на 764 живых строках),
SkillPoint += возврат; персонаж в игре → THROW), `rollback`. Нарушение 4-й — сброс деревьев 10–12; основных — наименьшее основное
дерево, покрывающее превышение. План на живом dev: Player58 — дерево 10, +30 (92 → 122); Player17 — дерево 2, +26 (0 → 26).
