# P42 — скрытый оператор не является допустимой целью боевых действий игроков

- **Дата:** 2026-09-27
- **Статус:** СОБРАН, НЕ УСТАНОВЛЕН (на живой сервер не выкладывался)
- **Процесс/файл:** GameServer.exe (основной и Indun_GameServer) — площадки в НАШЕЙ DLL
  `AsdaPatch.dll` (`\\@@ASTORY_SERVER_HOSTNAME@@\h(@@ASTORY_SERVER_HOSTNAME@@_ns)\ASDA\Working_ASDA\v2\GameServer\AsdaPatch.dll` при выкладке).
  Исходник: `AstoryServer/Patches/AsdaPatch/src/patches/p42_gm_hide_target.cpp`. Version DLL 27 (после правок ревизии).
- **Тип:** бинарный (11 площадок-детуров в DLL, `jmp rel32` → стабы; байты хоста сверяются до записи).
- **Отчёт:** `Reports/owner_0927/gm_hide_npc_2.md` §5, ревизия `gm_hide_npc_2_REVIEW.md` (СРЕДН-2).
  Клиентская часть (исключение скрытых из выбора цели) — `Reports/owner_0927/pick_hidden_filter.md`.
- **Бэкап DLL до правки:** `AstoryServer/Patches/AsdaPatch/out/AsdaPatch.dll.pre_p42_afterA_20260927`.

## ЗАЧЕМ (симптом → диагноз)

Признак «мастер игры наблюдает скрытно»: оператор командой скрытия (`Send_HideCommand@0x54E970`)
ставит `CUser+0x3BC3B (word) = 300`. Клиент уже не даёт выбрать скрытого целью (порт —
`pick_hidden_filter.md`), НО сервер **нигде не сверял признак скрытия у ЦЕЛИ**: собранным вручную
пакетом (удар/навык) или площадным навыком (жертвы собираются перебором сектора / приходят от
клиента) можно было ударить/наложить эффект по невидимому оператору. Признак 300 носит ТОЛЬКО
оператор (Send_HideCommand ставит его после `IsOperatorIndex`), поэтому один этот признак
однозначно опознаёт «скрытого оператора».

## ЧТО (11 площадок; отказ — штатным путём каждой функции, протокол НЕ меняется)

Условие отказа: цель — скрытый оператор И цель ≠ исполнитель (самоприменение не блокируется).
Признак: где CUser* цели уже в кадре — читаем `*(word*)(pUser+0x3BC3B)==300`; где только номер —
через `GetUser=sub_5324A0(userMng, idx)` + `IsOperatorIndex=sub_52ECF0`.

C1 — центральная проверка (8 вызывающих: удар 4201/4203, списки целей навыков игрока и стража,
часть разлётов). Остальные — обходы sub_556DB0 (реверс независимый, второй метод — скан `call rel32`
и xref по декомпилу): завершение каста навыка игрока/стража (556DB0 не зовут), разлёты стрелы/стража
(перебор сектора), перенос урона на соулмейта тремя путями (удар монстра C10, обычный удар игрока
C12, навык монстра C13 — все вызывающие `sub_4973D0(...,10)`) и цели навыка соулмейта из пакета
клиента (C11). C4/C5 (одиночное наложение состояния) покрывают транзитивный путь
sub_471C70/48FE40 → sub_473360/4913E0.

**★ C6/C7 (члены площадного 925) УБРАНЫ по ревизии (МЕЛК-3/п.4):** `sub_485940` =
`SetCurrentHpTimeValue(..., 2, 1, 4, 276)`, режим 2 = ПРИБАВКА HP — это групповое ЛЕЧЕНИЕ, не атака.
Гасить лечение скрытого оператора союзником не входит в задачу («групповые баффы на скрытого
согруппника действуют», эталон `pick_hidden_filter.md`). Снятие C6/C7 заодно устранило
несбалансированный стек СРЕДН-1 ревизии (у стоковых площадок аргумент `sub_485940` снимается самой
функцией).

Байты хоста всех 11 точек и соседних reject/skip/resume одинаковы в живом GameServer,
Indun_GameServer и базе IDA (md5 `e7b4ac38…`). С P01…P41 не пересекается.

## Ключи (ConfigSet\patches.ini, секция `[P42_GmHideTarget]`)

`Enabled=1`; группы `GateCentral` (C1), `GateSkills` (C2..C5), `GateSpreads` (C8/C9),
`GateSoulmate` (C10/C11/C12/C13); `LogEvents=1` (строки P42 в Log_Operator).

## Проверки

- `verify_dll.py` — сток, живой GameServer и Indun: расхождений 0, пересечений 0.
- `verify_p42.py` (unicorn) — 48 [OK]: на каждую точку контрольные пары «цель скрыта (не сам) →
  штатный reject/skip» и «цель не скрыта → продолжение», где применимо «цель == исполнитель →
  продолжение (самоприменение не блокируется)».

## Как ОТКАТИТЬ

Заменить `AsdaPatch.dll` на `pre_p42_afterA_20260927` (или выставить `[P42_GmHideTarget] Enabled=0`
в patches.ini и перезапустить GameServer). Рестарт GameServer/Indun_GameServer обязателен.

## Риски / связанное

- Скрытый оператор теперь не получит и БЛАГОТВОРНЫЙ эффект по этим трактам (соулмейт-навык и т.п.) —
  это соответствует «скрытый = не выбирается целью». Групповые баффы (charCollectPartyMembersInBox)
  идут другим путём и НЕ затронуты (скрытый согруппник бафф получает — как в оригинале).
- Пара к клиентской правке `pick_hidden_filter.md` и к P41 (4056 скрытого соседям не уходит).
