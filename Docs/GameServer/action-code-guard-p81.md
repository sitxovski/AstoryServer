## 1. Дыра стока

`CharEMotionSync@0x546730` (4024 → 4025) после проверок (номер, скрытый оператор 300 → выход 0x5467DE, MD5 тела `sub_523F00`,
гейт `sub_52BFF0`, номер в теле = отправитель, «в ходу» → выход 0x5468C1) принимает **любой** код 100…400 тела (`word [ebp-416h]`):

```
0x5468C6 movsx eax,[ebp-416h] ; cmp eax,64h ; jl 0x5468F7      ← < 100 → выход (0 честного клиента — сюда)
0x5468D2 movsx ecx,[ebp-416h] ; cmp ecx,190h ; jg 0x5468F7     ← > 400 → выход
0x5468E1 mov edx,[ebp-42Ch] ; mov ax,[ebp-416h]                ← ПЛОЩАДКА A (13 б)
0x5468EE mov [edx+54E4h],ax                                    ← статус действия CUser+0x54E4 := код
0x5468FC … 0x546940                                            ← курс +0x5512/+0x5516 (если не NaN)
0x546946 mov eax,[ebp-42Ch] ; mov cl,[eax+4A6h]                ← вход P80 S2 (131 в ходу)
0x546952 mov [ebp-414h],cl ; push 1                            ← ПЛОЩАДКА B (8 б)
0x54695A … 0x546973 call sub_52E6D0(4025, 13 б)                ← рассылка сектору кроме себя
0x546978 movsx ecx,[ebp-416h] ; mov [ebp-438h],ecx             ← ПЛОЩАДКА C (13 б)
0x546985 cmp 70h/71h → 0x546999 push 0,0,0Dh,num ; call sub_54A050   ← 112/113: накопитель звания «Dancer» (индекс 13)
0x5469AF эпилог
```

Честный клиент шлёт только **100–110, 112–117, 122, 124, 127, 128, 131 (прыжок, порт), 400** (оригинал — 35 мест; порт) и 0
(сток отбрасывает сам). Подделка: **300/301** — у соседей игрок выглядит скрытым оператором / раскрытым (настоящее скрытие — только
пакет 6005 `0x54E970`, не 4024), **200** — помечает себя «мёртвым» для мобов (NpcServer видит статус 200). Флуд 4024 112/113
набивает звание «Dancer» (`sub_54A050` без ограничения частоты; клип танца 13,3 с).

## 2. Что делает P81

- **A (стоя, 0x5468E1)** — до записи статуса и курса: код вне `AllowedCodes` (быстрый путь — таблица 512 байт прямо в трамплине,
  без вызова) → `P81_Check`: отправитель-оператор (GM-флаг `CUser+0x40B9F == 1`, общая точка `P47_IsGmUser` = `sub_52ED50`) — как
  сток; иначе журнал и при `Mode=1` выход 0x5469AF (статус, курс, 4025, «Dancer» — ничего).
- **B (перед рассылкой, 0x546952)** — общая точка обеих ветвей; сверяет только путь «в ходу» (`dword CUser+0x33 ≠ 0` — тот же флаг,
  что `sub_523ED0 → sub_542250` на 0x5468B8; между ними вызовов, кроме трамплина P80, нет). Стоя код уже сверен на A — двойного
  журнала нет. Нужна, если `RelayWhileMoving` P80 (131) не входит в `AllowedCodes`: тогда прыжок отклоняется и в ходу.
- **C (после рассылки, 0x546978)** — для 112/113: `sub_54A050` («Dancer») не чаще одного раза за `DanceCountMinSec` на сессию
  (слот `userNum`, сброс при другой учётке `CUser+0x174`). Анимация соседям (4025) уже ушла — танец виден как всегда.
  Применяется ко всем (и к оператору): честный клиент чаще клипа не шлёт.
- `Mode=0` — только журнал: поведение стока (коды проходят, «Dancer» засчитывается каждый раз).
- Скрытого оператора (300) сток отбивает ещё до площадок — P81 этого не меняет. Оператор скрывается пакетом 6005 — запрет 300/301
  в 4024 GM-скрытие не ломает.

## 3. Ключи `[P81_ActionCodeGuard]`

| ключ | умолч. | смысл |
|---|---|---|
| `Enabled` | 1 | 0 — не ставится (сток) |
| `Mode` | 1 | 1 — отклонять (A/B) и не засчитывать «Dancer» (C); 0 — только журнал |
| `AllowedCodes` | `100-110;112-117;122;124;127;128;131;400` | законные коды (формат `a-b;c;d`; коды вне 100…400 сток отбрасывает сам). Ошибка разбора / пусто → умолчание (строка в PatchLog). 200/300/301 в списке → предупреждение «подделка снова открыта». `RelayWhileMoving` P80 не в списке → предупреждение |
| `DanceCountMinSec` | 12 | «Dancer» не чаще раза за столько секунд на сессию; 0 — площадка C не ставится; 0…3600. ★ 24.10 (ревизия): было 13 — при клипе 13,33 с запас 0,33 с терял честный засчёт на сетевой задержке |
| `JournalIntervalSec` | 10 | журнал и строка лога — не чаще раза за столько секунд на (сессия, вид); 0 — каждый раз |
| `LogChannel` | 0 | канал стокового лога `sub_569DF0` (0 = Log_Game) |

## 5. Совместимость

- **P80** (тот же обработчик): его площадка S2 0x5468C1 (5 б) и сверяемые соседи 0x5468B8/0x5468C6/0x546946/0x5469AF не
  пересекаются с A/B/C (verify_p80 — исключение для P81 с проверкой непересечения, verify_p81 — встречная). P81 в реестре после P80.
  Путь P80 S2 (131 в ходу) проходит через B: при законном 131 — без изменений (стенд T6).
- Другие патчи адресов внутри CharEMotionSync не называют (verify_p81 / verify_p80). Карта площадок stand_map — пересечений нет.
- Клиент порта не меняется: шлёт только законные коды (35 мест оригинала + 131).

## 6. Откат

- Быстрый: `[P81_ActionCodeGuard] Enabled=0` (или `Mode=0` — только журнал) + рестарт GameServer/Indun.
- Полный: `python tools/deploy_p81.py --rollback` (при остановленных процессах) — DLL v52 из `.bak_20261024_p81`; v52 сама вернёт
  Version 52, секция P81 останется и будет проигнорирована.
