## 3. Как пишется (без задержки игрового потока)

- Источник (игровой поток, поток БД DBManager, поток боя NpcServer) только копирует ~200 байт события в ячейку
  кольцевой очереди без блокировок (CAS, без мьютексов и ожиданий). Замер стенда: среднее **0,11–0,12 мкс** на
  вызов, p99 0,6–0,7 мкс (`wA3_logs/stand_journal_*.txt`).
- Фоновый поток (приоритет ниже обычного) раз в `FlushIntervalMs` или при накоплении `BatchMax/2` событий забирает
  до `BatchMax` и пишет **одним пакетом**: `BEGIN TRAN; INSERT … VALUES (…),(…)` по таблицам; `COMMIT`
  (`XACT_ABORT ON` — пакет либо целиком, либо никак). Текст строк (русские описания) собирается в фоне.
- Соединение ODBC **своё** (`odbc32.dll` грузится лениво в фоновом потоке), в поток запросов DBManager не входит.
  Строка подключения: `ConnectionString`, а если пусто — `DSN/UID/PWD` из `DbConfigFile` секции `DbConfigSection`
  (`GAMEDNS`/`GAMEUSER`/`GAMEPASS`, как у DBManager) + `DATABASE=joylog1;APP=AsdaAcJournal`. В PatchLog пароль
  заменён на `***`.
- Все строки экранируются (апостроф удваивается, управляющие символы → пробел; на стенде проверено значением
  с `'`, `;` и `--`).

### 3.1. База недоступна
- Первая неудачная попытка подключения → строка в PatchLog `[P53] журнал: база недоступна — <ошибка>; запись в
  файл …`, служебная строка «журнал: база недоступна» (ac.other, вид 12) попадёт в базу позже.
  `-- <время> <DLL>/<сервер>: база недоступна, N событий — <ошибка>`), если `FileFallback=1`. Иначе отбрасываются.
- Повтор подключения не чаще `ReconnectSec`. Ошибка пакета при живом соединении — соединение закрывается, пакет
  уходит в файл, повтор через `ReconnectSec`. После восстановления — строка «журнал: база снова доступна» (вид 13).
  (на стенде: 10 002 строк из файла дошли одной транзакцией, `wA3_logs/stand_journal_replay_tx.txt`).
- Выход процесса: остаток очереди пишется в тот же файл (`FlushToFileOnExit` при выгрузке DLL; при аварийном
  завершении остаток теряется).

### 3.2. Переполнение и флуд
- Очередь полна → событие **отбрасывается и считается**, игровой поток не ждёт. Писатель раз в пакет кладёт служебную
  строку `ac.other` вид 11 «отброшено N, всего M (ёмкость очереди K)». Стенд: 50 000 событий без паузы → принято
  597, отброшено 49 403, всё посчитано (`stand_journal_flood.txt`).
- Ограничитель на сессию для `sign_replay`, `move_combat`, `other`: не больше `PerSessionPerMinute` строк в минуту на
  (таблица, `user_num`); лишние не пишутся, их число попадает в `repeat_suppressed` следующей строки.
  `operator_refusal` ограничивает сам P47 (раз в `RefusalLogIntervalSec`=60 с на сессию, подавленные — в той же
  колонке). `identity_mismatch`, `login_check_refusal`, `kick_block` — без ограничителя (редкие события).
- Очистка: GameServer/Indun_GameServer с `PurgeDays=90` раз в сутки (и сразу после подключения) зовут
  `ac.UP_AC_JournalPurge @Days=90`; DBManager и NpcServer не чистят (`PurgeDays=0`).

### 3.3. ★ fix2 (13.10.2026): ширина колонок и пределы файла (ревизия INTEG3 СРЕДН-3/СРЕДН-4)
- **Ширина колонок.** Пакет — `SET XACT_ABORT ON; BEGIN TRAN; INSERT …`; ODBC включает `ANSI_WARNINGS`, поэтому строка
  шире колонки (ошибка 8152) откатывала ВЕСЬ пакет с чужими годными событиями. Шире старых колонок было 22 текста видов
  (`ac.move_combat` 12, `ac.other` 10, до 87 символов против NVARCHAR(64)); процедуры A11c/A13 пишут в `ac.other`
  `server_name` до 64, `detail` до 512, `char_name` до 64 (против 32/256/32 — их INSERT в своём TRY/CATCH молча терялся).
  `ac.other.detail` — 512, `ac.other.char_name` — 64 (только расширение, NULL-ность и collation сохранены, представления —
  В коде (`AcJournal.cpp`, константы `kCol*`) каждое строковое значение обрезается до ширины колонки перед вставкой.
- **Файловый журнал.** Не больше `FileRowsPerMinute` событий в минуту на процесс (лишние — в счётчик `fileSkipped`, строка
  PatchLog при первом пропуске минуты и сводка «за прошлую минуту пропущено K» в файл и PatchLog) и не больше `MaxFileMB`
  на суточный файл (после — одна строка-комментарий в файле и одна в PatchLog за сутки). Ошибка открытия/записи файла
  видна в PatchLog (не чаще раза в минуту). `FileDir` — другая папка файла. Удаление старых файлов DLL не делает
  (принятого в проекте способа нет — за владельцем). Стенд `stand_acjournal filerows|filecap`.

## 4. Источники в GameServer — площадки штатных проверок (`StockSites=1`)

Подменена цель ровно одиннадцати `call rel32` (5 байт, вся инструкция): стаб → запись события → тот же стоковый
вызов с теми же аргументами. Остальные вызовы писателя логов `sub_569DF0` не тронуты; файл-лог сервера пишется как
раньше. Перед установкой сверяются байты `E8 rel32` каждой площадки и `push` ожидаемой строки формата перед ней;
не сошлось хоть одно — `[MISMATCH]`, ни одна площадка не ставится.

| VA вызова | строка лога (канал) | таблица / вид |
|---|---|---|
| `0x0054543D` | `CharMove Hack Position %s Error` | move_combat 1 |
| `0x00545A84` | `CharReMove Hack Position %s Error` | move_combat 2 |
| `0x005272B4` | `HackCheck %d/%d %s` | move_combat 3 |
| `0x0052440E` | `Secret Error User %d, Server %d` | sign_replay 1 |
| `0x0052448B` | `Secret Error Disconnect` | sign_replay 2 |
| `0x00523FC5` | `memcmp(szMD5 …+iSecretSize…)` | sign_replay 3 |
| `0x00524044` | `memcmp(szMD5 …(HEADER_SIZE-1)…)` | sign_replay 4 |
| `0x004ED910` | `SendChar_FunctionItem_Use() MD5 Error` | sign_replay 5 |
| `0x0050F561` | `CharItemBuy() CellobItem ShopBuyFlag Error` | other 1 |
| `0x0050F91F` | `CharItemBuy() NormalItem ShopBuyFlag Error` | other 2 |
| `0x0042F031` | `call sub_5244B0` (счётчик NotKnow Packet, default диспетчера) | other 3 |

Байты стока — живой `GameServer.exe` = `Indun_GameServer` `e7b4ac38…`. С площадками P01…P49 и P54 не пересекаются
(ближайшая — P13 `0x42F020..0x42F024`). Разбор аргументов — под SEH: любая ошибка разбора → событие не пишется,
вызов уходит в сток как обычно.

Прочие события GameServer пишут сами патчи: P47 (`operator_refusal`, `identity_mismatch`), P48 (`kick_block` — каждый
кик с адресом возврата; учёт автоблока не изменился). При `[P48_KickAutoBlock] Enabled=0` и
`KickJournalWhenP48Off=1` перехват `Send_DisConnectType` ставится только для журнала (счёта и блока нет).
