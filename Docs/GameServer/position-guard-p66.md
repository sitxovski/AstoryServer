## Правки ревизии fix13 (2026-10-13)

1. **БЛОКЕР — гейт 5427 слал клиенту 6001.** `P66_OnRecall5427` при `RecallGate=1` (умолчание, вне Mode) звал стоковый
   `sub_52BFF0@0x52BFF0` (GS:113973). Он на КАЖДОМ вызове, включая код 0, шлёт 6001 `{опкод i16, код u8}` (len 3,
   `push 0x1771` @0x52C051/0x52C08C/0x52C0C2/0x52C0F8/0x52C12D/0x52C154 → `sub_4C28F0`), а сток 5427 его не зовёт:
   лишний пакет на каждый честный зов, при кодах 2..5 клиент видел «отклонено», а перенос проходил (Mode=0).
   Теперь `StateCode()` воспроизводит ВСЕ ветки функции без отправки: GetUser(userNum) нет → 0; `sub_4CB030` (DWORD +0x4F)
   → 1; DWORD +0x145 → 2; DWORD +0x15F → 3; DWORD +0x14D → 4; BYTE +0x3F6B4 → 5; иначе 0 (смещения — `Srv::kOff*`, общие
   с P64 `ReadState`). Опорные байты пяти чтений (0x4CB05D, 0x52C070, 0x52C0A6, 0x52C0DC, 0x52C10F) сверяются при
   установке (одинаковы в стоке 4e20f0ad и живых e7b4ac38). Вид журнала прежний — 27, `v1` = код.
2. **LOOT-2 (СРЕДН).** (а) Шапка файла, этот док и комментарий ini: «исправление дефекта оригинала, работает при любом
   Mode». (б) Строка Log_Item о возврате — через ограничитель `Allow()` (свой слот 31, в `ac.*` не пишется; повторы
   считаются в «(suppressed before)»). (в) Ветка «iAmount <= 0» (GS:84265–84269: 0x4D54F3 `sub_4211F0` → 5015 сектору,
   0x4D54F8 сверка количества, 0x4D5510 лог, `jmp 0x4D5999`) — единственная из веток LABEL_103, где снятие уже разослано.
   Разослать появление штатно можно (`sub_421150@0x421150` → 5005 len 15, как `UserDrop_AddMapItem` GS:14005 и
   `Search_AddMonsterMapItem` GS:14171), но **небезопасно**: в ветку попадает только накопительный предмет (+7==4,
   +0x24==1, +0x23≠0, +0x1A≠10) с количеством ≤ 0 при найденной в сумке такой же стопке; показанный снова, он у каждого
   владельца стопки уходит в ту же ветку (5015 → отказ → 5005 — мигание), а остальным ложится в сумку пустой стопкой
   (`sub_4D6740`). Решение: такую запись **не возвращать** (ценности нет, вид клиентов уже согласован стоковым 5015),
   строка «NOT returned (zero-amount stack, 5015 already sent by stock)». Ветка определяется по данным: код ≠ 20551,
   `sub_532A90`=1, `sub_532B10`/`sub_532B30`=0, поля таблицы `dword_5F5E98` (запись 0x47, индекс code−20551; опоры
   0x4D530E/0x4D5317/0x4D531C/0x4D533E/0x4D5360/0x4D5381 и прологи предикатов 0x532A93/0x532B13/0x532B34 сверяются при
   установке), количество записи ≤ 0. Прочие ветки LABEL_103 с такими данными недостижимы. Штучный предмет с количеством 0
   (дроп монстра `a4 <= 0 → 0`, GS:14155) возвращается как раньше.
