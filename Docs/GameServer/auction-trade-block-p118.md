# P118 — обмен отменяется, пока игрок работает с аукционом

Дата: 09.11.2026. Пачка 20, баг 3 (рынок), жалоба 10. Слово владельца: «any trade request should be canceled by server while
communicating with auction». Исходник: `src/patches/p118_auction_trade_block.cpp`. Проверка: `tools/verify_p118.py`.
Выкладка/откат: `tools/deploy_p118.py`. Секция `patches.ini`: `[P118_AuctionTradeBlock]`. Протокол не меняется.

## 1. Сток

* Сервер не знает об окне аукциона: пакетов открытия/закрытия нет (9915 — один раз при входе в мир, `sub_521770`), разговор с NPC на
  сервер не уходит.
* Единственный признак — CUser+0x15F «запрос в ItemRelay в полёте»: диспетчер `sub_42A9D0` ставит его перед 9901/9905/9909
  (`sub_521980(…,1)`, GameServer.c:18837/18851/18866), снимает ответ ItemRelay. Живёт десятки миллисекунд.
* 5282 `CharExchangeReq@0x4DF830`: отказ по этому признаку есть (`sub_52BFF0` = 3 → 5283 код 8/9, клиент 5051/5052
  «убит/обездвижен» — дефект текста оригинала). 5284 `CharExchangeAcceptReq@0x4DFC80` признак не проверяет.

Ключи: `Enabled` (1), `WindowSec` (120, 5…3600), `StormGuard` (0), `StormStatus` (3; 0/1/100 заменяются на 3), `LogPerMinute` (30).
Журнал: Log_Game, строки `P118: 5282 …` / `P118: 5284 …`. Счётчики: экспорт `P118_GetStats`.

Соседи: P44 (0x4DFE5B выделение окна, 0x4DFFE2/0x4E001C ветка отказа, 0x4E004D — их продолжение, не площадка), P19 (тела
9905/9909 0x51ACC5/0x51E630) — не пересекаются (verify_p118 §3).

## 3. Окно метки (WindowSec = 120)

Журнал ItemRelay `ItemRelayLog0001_20261108` (единственный день с живой торговлей одного игрока): 145 событий, 30 пауз длиннее
1 с между аукционными запросами — ≤30 с: 24, ≤60 с: 25, ≤120 с: 26, ≤180 с: 29, ≤300 с: 30. Журнал клиента того же игрока:
окно «мои лоты» открыто в 10:24:41, следующий аукционный запрос (9909) — в 10:27:16, 2,5 мин тишины при открытом окне.
120 с покрывают 87 % пауз и не держат обмен запертым дольше двух минут после ухода с рынка. Новый клиент сверх того сам
отвечает «занят» на заявку, пока окно 13000 открыто (`asda.Exchange.ExclusiveWindows`), — длинные паузы при открытом окне
закрывает он; сервер закрывает старые клиенты и заявки во время выставления/поиска/покупки. Окно меняется ключом без сборки.

## 4. StormGuard — оценка нагрузки (решение владельца)

Клиент alpha-7.0.0 при пустой категории «моих лотов» шлёт 9907 без остановки (разбор — `Reports/npc_exchange_win_13000.md` §18).
Журнал клиента Player54 08.11: 3215 пар за сессию; пик 1448 запросов/мин (24/с), устойчиво ~190/мин (3,2/с) десять минут подряд в
фоне, пока игрок в игре. Каждый запрос — проход GameServer → ItemRelay → `EXEC UPCharExchangeItem` в БД → обратно. На одного
игрока с открытым однажды пустым списком — ~11 000 обращений к БД в час. ItemRelay такие пустые ответы не журналирует, поэтому
в его логах шторм не виден (видны только непустые: 116 строк `MyItemInquiry` за 08.11, из них 81 за минуту 08:45).
С `StormGuard=1` пустой ответ приходит одной записью со статусом 3: старый клиент открывает окно пустым и не повторяет запрос,
оригинал и новый клиент запись пропускают. Включается ключом и рестартом.

## 5. Откат

`[P118_AuctionTradeBlock] Enabled=0` + рестарт — ни одна площадка не ставится. Полный — прежняя DLL (`deploy_p118.py --rollback`).
