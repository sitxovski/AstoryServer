и сверяется с `pkt+9` (конверт БЕЗ 8-байтного анти-реплей секрета).

## Дефекты

### S1. `sub_44F4C0` (5090): нет проверки «цель ≠ отправитель»
Тело читается как `memcpy(v8, pkt+25, 3)`, затем `sub_5324A0(userMng, v8[0])`. Совпадение
`v8[0] == a2` (charIndex отправителя) НИГДЕ не проверяется. Самоприглашение блокирует ТОЛЬКО
клиент (нотис 1093 в ветке `exchangeUiOnCommand` 0x7D1). Модифицированный клиент отправит 5090
сам на себя, и ретранслятор получит пару «запросивший = ответивший».

### S2. `sub_44F4C0` / `sub_44FDE0`: нет проверок «я уже в отряде» и «я глава»
Обе живут только в клиенте (нотисы 1047 и 1089). Сервер их не дублирует: `sub_44FDE0` просто
берёт `*(WORD*)(pUser+436)` как partyIndex отправителя и шлёт дальше, не убедившись, что
отправитель вообще состоит в отряде и является его главой.

### S3. `recvResponseUserNewPartyCreate@0x44F9D0`: копипаста имени (`GameServer.c:32027-32031`)
В ветке «зона типа 4» имя для ВТОРОГО вызова `sub_467AD0` берётся тем же
`sub_532570(userMng, partyBody[0])` (приглашающий), хотя нужен `partyBody[3]` (приглашённый):

```c
v4 = sub_532570(userMng, partyBody[0]);
sub_467AD0(quest, partyBody[0], partyIndex, v4);
v5 = sub_532570(userMng, partyBody[0]);   // ← должно быть partyBody[3]
sub_467AD0(quest, partyBody[3], partyIndex, v5);
```
⇒ в квестовой регистрации отряда приглашённый получает ЧУЖОЕ имя.

### S4. `sub_44FDE0` (5094): partyIndex берётся без проверки диапазона
`inviteBody = *(WORD*)(pUser+436)` уходит в ретранслятор как есть. Если отправитель не в отряде,
поле содержит −1 (или мусор), и решение о валидности принимает уже релей, кода которого у нас нет.

### ~~S5~~. ⛔ СНЯТ (дубль P19-S1, опровергнут для живого) — `sub_523F00@0x523F00` (`GameServer.c:110836-110846`)

```c
if ( a4 ) { sub_567620((char *)a1 + 33, arg4, Buf1); memcmp(Buf1, (char *)a1 + 17, 0x10u); }
else      { sub_567620((char *)a1 + 25, arg4, Buf1); memcmp(Buf1, (char *)a1 +  9, 0x10u); }
return 1;                                  // ← результат memcmp отброшен
```
Дайджест считается, `memcmp` вызывается, но его значение никуда не идёт: функция безусловно
возвращает 1. ⇒ подпись тела не проверяется НИ У ОДНОГО пакета, проходящего через `sub_523F00`
(вся семья отряда в том числе). Найдено при перепроверке 2026-08-29.
Область действия шире отряда — при реализации патча это надо учитывать (много вызывающих).

## Что предлагается

Все четыре — кандидаты на детур в `AsdaPatch.dll` (закон `server-dll-patch-loader`, живой сервер
локально не запускаем). Приоритет: **S5** (сквозной, снимает подпись со всех тел), затем **S1** (единственный, дающий заведомо некорректное состояние
отряда из-под модифицированного клиента), затем **S3** (тихая порча данных), затем S2/S4.
