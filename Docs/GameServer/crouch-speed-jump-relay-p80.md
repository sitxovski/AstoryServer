## 1. Зачем

Порт (клиент) получает ходьбу вприсядку из донора: Ctrl переключает присед, анимация `hidewalk_01` (anim_239) видна соседям, ход
медленнее. Скорость хода считает ТОЛЬКО сервер (`RecalcMoveSpeed@0x5588F0`); клиент, идущий медленнее гранта, на следующем 4006
снапается к серверной точке, а соседи видят обычный бег — честно замедлить можно только на сервере. Для соседей присед должен быть
виден без нового опкода. Второе: прыжок порта (4024 код 131) с бега до соседей не доходил (§3).

## 2. S1 — скорость приседа (RecalcMoveSpeed@0x5588F0, площадка 0x558B39)

Сток: 0.35 + баффы/транспорт (`sub_4F2330(…, 15)`), потолок 0.66, пол 0, затем деление на 2.0 (`0x5874A0`), если у игрока
состояние 112 «Скрытность» (`byte CUser+0x999E`) или 186 «Быстрая маскировка» (`byte CUser+0xA08E`) — массив состояний CUser с базы
`0x8F1E`, шаг 24 б (в той же функции 29 → `+0x91D6`, 30 → `+0x91EE`, 230 → `+0xA4AE`, 241 → `+0xA5B6`; verify_p80). Результат —
в `+0x54FE` и, при `a3 = 1`, рассылка 6071 всем в секторе.

```
0x558B2B mov edx,[ebp-0Ch] ; movzx eax,byte[edx+999Eh] ; test ; jg 0x558B47     ← 112: деление (до площадки)
0x558B39 mov ecx,[ebp-0Ch] ; movzx edx,byte[ecx+0A08Eh] ; test ; jle 0x558B53   ← ПЛОЩАДКА (14 б): 186
0x558B47 fld [ebp-4] ; fdiv qword[0x5874A0] ; fstp [ebp-4]                      ← деление на 2
0x558B53 movzx eax,byte[ebp+0Ch] …                                               ← запись +0x54FE / 6071
```

Клиент порта в приседе шлёт 4006 со статусом хода @+3 = **4** вместо 2. CharMove@0x544EB0 в обеих ветках («стоит»/«идёт») пишет
статус в `word CUser+0x54E4` ДО вызова 0x5588F0 и пересчитывает скорость для 2/4/6/8; тело 4007 (статус и скорость @+21) эхом
уходит себе и соседям (`sub_52E6D0`). NpcServer (`Send_BattleServerToCharParamAll`) считает 2/4/8 «идёт». «Паника» (FEAR) всегда
пишет 2. CharStop на 4008 пишет 0.

**P80:** трамплин повторяет проверку 186 и добавляет «`word[CUser+0x54E4] == CrouchStatus` (4)» → тот же стоковый переход на
0x558B47. До площадки код доходит, только если 112 нет; при 186 трамплин сразу идёт в деление — двойного деления (невидим + присед)
нет. Делится уже ограниченная потолком скорость (0.66 → 0.33), как у скрытности. Соседи получают скорость в 4007 @+21 и идут тем же
темпом; P57 считает бюджет по `+0x54FE` — согласованно; пересчёт от баффов (`a3 = 1`, 6071) статус видит и замедление сохраняет.

## 3. S2 — прыжок с бега соседям (CharEMotionSync sub_546730, площадка 0x5468C1)

Сток 4024: проверки (номер, оператор-невидимка 300, MD5 тела `sub_523F00`, гейт `sub_52BFF0`), затем
`0x5468B8 call sub_523ED0 ; test ; je 0x5468C6 ; 0x5468C1 jmp 0x5469AF` — **в ходу (`dword CUser+0x33` ≠ 0) 4024 молча
отбрасывается**. Флаг ставит `SetEmpty_UserMoveStack@0x542300` на 4006, снимает `sub_542520` на 4008/ревизии (проверено тремя
способами: декомпил, писатели флага, байты живого образа). Стоя: код 100…400 пишется в `+0x54E4` (0x5468EE), курс в
`+0x5512/+0x5516`, байт шлема `+0x4A6` в тело, 4025 13 б сектору кроме себя (0x546946…0x546973), для 112/113 — `sub_54A050`.

**P80:** в ходу код == `RelayWhileMoving` (131 — прыжок порта) → переход на 0x546946: байт шлема и стоковая рассылка 4025;
запись кода в `+0x54E4` и курса пропускаются (статус хода 2/4 и NpcServer не портятся, ход не прерывается). Прочие коды в ходу —
как сток. Стоя — сток без изменений. Клиент порта менять не нужно — он и так шлёт 4024 131 с бега.

## 4. Ключи `[P80_CrouchSpeedJumpRelay]`

| ключ | умолч. | смысл |
|---|---|---|
| `Enabled` | 1 | 0 — патч не ставится (сток) |
| `CrouchHalve` | 1 | 1 — статус хода `CrouchStatus` делит скорость на 2 (S1); 0 — площадка S1 не ставится |
| `CrouchStatus` | 4 | статус хода приседа, 3..8 (2 — обычный бег — нельзя; негодное → 4) |
| `RelayWhileMoving` | 131 | код 4024 (100..400), рассылаемый и в ходу (S2); 0 — площадка S2 не ставится |

Откат только P80 без замены DLL: `Enabled=0` + рестарт GameServer/Indun. Откат DLL: `deploy_p80.py --rollback` (v50).

## 5. Проверки

* `verify_p80.py` — три образа: обе функции побайтно равны; байты площадок и соседей, `0x5874A0 = 2.0`, сетка состояний, обе записи
  статуса в CharMove перед вызовом скорости, `sub_542250` читает `+0x33`, 0x546946… — `sub_52E6D0(0xFB9, 13)` без записи `+0x54E4`;
  все точки — начала инструкций; переходов/abs32 внутрь площадок нет; другие патчи адресов внутри функций не называют. DLL: трамплины
  выходят только на 0x558B47/0x558B53 и 0x546946/0x5469AF, стек не трогают.
* `stand_p80` (режим `on`): скорость — без состояний/статусы 2, 8, 131 → 0.35; 112, 186, статус 4, 4 + 112, 4 + 186, 4 + 112 + 186 →
  0.175; потолок 0.70 → 0.66, с приседом 0.33; на транспорте 0.175; `a3 = 1` — `+0x54FE` 0.175 и 6071 с 0.175. CharMove: 4006
  статус 4 стоя → 4007 себе и сектору со статусом 4 и скоростью 0.175, в ходу статус 2 → 0.35, снова 4 → 0.175, «Hack Position» нет.
  4024: стоя 131 → 4025 (как сток); в ходу 131 → 4025 (код, шлем, курс), статус хода 4 и курс не тронуты, ход не прерван; в ходу 100 →
  нет; оператор-невидимка → нет. `nocrouch`/`norelay`/`off` — соответствующая часть = сток; `mismatch` — установка = Mismatch, обе
  площадки не тронуты.

## 6. Ревизия 24.10 — правки в исходнике ПОСЛЕ сборки v52 (войдут в следующую выкладку; v52 на стойке их НЕ содержит)

* `CrouchStatus` — допускается только 4 (иное → 4): 2 — обычный бег, 6 NpcServer считает «не идёт».
* `RelayWhileMoving` — особые коды сервера 108/110/112/113/114/200/300/301 недопустимы (рассылка в ходу выключается):
  у них свои ветки и смысл вне рассылки (112/113 — `sub_54A050`, 200 — мёртв, 300/301 — GM-скрытие, 108 — сидение,
  110/114 — копание P66). Умолчание 131 не затронуто; на поведение с умолчаниями правка не влияет.
* Клиент (`AsdaWorldSubsystem_Entities.cpp`): сосед, появившийся посреди хода вприсядку (код состояния появления @102 = 4,
  то же поле CUser+0x54E4), сразу показывается в приседе; переключение приседа, пока прежний 4006 в пути, досылается после ответа.
