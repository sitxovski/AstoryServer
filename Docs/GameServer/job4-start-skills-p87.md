## 1. Дефект оригинала
4-я профессия на сервере — **подкласс**, а не смена класса:
  (`Nick_name_[13]`); основной класс `CUser+0x190` (`Nick_name_[12]`) остаётся 3/14/25; счётчик профессий (`CurWeight+3`) растёт до 4.
- После смены (награда квеста `GameServer.c:37955-37962` и `:38182-38188`) при счётчике 4 зовётся `sub_481CE0(skill, user, 1)`
  (`GameServer.c:51460`); при счётчике ≠ 4 — сразу `sub_48A8C0(skill, user, Job − 1)`. Из изучения навыка `sub_47E9B0`
  (`:50716`) — `sub_481CE0(skill, user, 0)`. Других вызовов нет (verify_p87: ровно 3 — `0x45D533`, `0x45DE95`, `0x47EDD0`).
- `sub_481CE0`: `switch (CUser+0x191)` (`0x481D22 movzx ecx, byte ptr [eax+191h]`) по 4/6/15/17/26/28 — сумма очков категорий
  1–3 / 4–6 / 7–9 (`CUser+0xC024+4·кат`) ≥ 60 (a3 = 1) или ровно 60 (a3 = 0) и в двух «категориях 4-й профессии» 0
  (4/6 → кат. 10/11, 15/17 → 12/13, 26/28 → 14/15 — так в стоке) → **LABEL_99** (`loc_4820C6`).
- LABEL_99: `sub_48A8C0(skill, user, X − 1)` выдаёт навыки строки X таблицы `SkillTable_Info\ChangeJobAddSkillTable.txt`
  (загрузчик `GameServer.c:71655` / `0x4B2E63 cmp id, 0x27`: строка id → запись id−1 по 8 б `@0x600B60` — `+0` i16 число,
  `+4` указатель на i16 коды; id 1…39) с проверкой требований `SkillInfo.sif` и шлёт 5252.

**Дефект:** в LABEL_99 X = **основной класс**, а не подкласс.

## 2. Что делает P87
Площадка **0x4820C9** (7 б, `movzx eax, byte ptr [edx+190h]`) → `jmp` на трамплин + 2 `nop`. Трамплин:
1. исполняет ту же стоковую `movzx eax, byte ptr [edx+190h]` (тот же `CUser`, сбой — как у стока);
2. `pushfd` / `pushad`, зовёт `P87_PickRow(skill = [ebp-10h], user = edx, userNum = [ebp+8], a3 = [ebp+0Ch], stockRow = eax)`;
3. ответ пишет в слот EAX кадра `pushad` (`[esp+1Ch]`) — без глобальных переменных (нити карт параллельны); `popad` / `popfd`;
4. единственный выход — `jmp [g_pRet]` = **0x4820D0** (`sub eax,1` … `call sub_48A8C0` — стоковые).

`P87_PickRow`: подкласс S = `CUser+0x191`;
- 1 ≤ S ≤ 39 и число навыков строки S (`*(i16*)(0x600B60 + 8·(S−1))`) > 0 → **строка S** (журнал `ac.other` **106**);
- иначе (6/17/28 — строки нет; S вне 1…39) → стоковое значение `CUser+0x190` (журнал **107**);
- исключение чтения подкласса/таблицы → стоковое значение (журнал **108**, `value2` = 1).

### 2.1. Побочное стока — звание «3-я профессия» (сохранено)
`sub_48A8C0` первым делом (`0x48A9A3…0x48AA14`) по `arg4 + 1` == 3 / 0xE / 0x19 (строки 3/14/25) зовёт
`sub_54A050(userMng = [[this+4]+34h], user, 24/25/26, 0, 0)`. Разбор `sub_54A050` (`GameServer.c:126114`): при включённом звании
(`FameInfo.txt` +2 = 1) и **если звания ещё нет** (`sub_54A890` — бит не стоит) — для 24/25/26 ветка `switch` «+1 к счётчику»
(не `arg8`!, т. к. флаг записи +92 = 0) и `sub_54B260` — выдача при достижении цели +4 = 1. `FameInfo` стока и живой (`e2c78373…`,
280 записей): 24/25/26 — `1 0 1 0 … 36 0 0 0` (включено, цель 1, +92 = 0). То есть вызов **не пустой**: звание выдаётся, если
его нет (обычно оно уже выдано на 3-й ступени — тогда `sub_54A890` вернёт 0 и ничего не произойдёт; без звания — например,
класс выставлен в БД вручную или звание снято — сток выдал бы его при смене на 4-ю профессию).
С подклассом `arg4` станет 3/14/25 и вызова в `sub_48A8C0` не будет, поэтому **P87 зовёт `sub_54A050` сам, ровно как сток**: тот же
`userMng` (`[[[[skill+4]+2Ch]+4]+34h]` — как `this` `sub_48A8C0` в `0x4820DF` и его `ecx` в `0x48AA08…0x48AA11`), те же аргументы
(звание по строке основного класса, `arg8 = argC = 0`), до выдачи навыков. Для строк 6/17/28 (сток) вызов делает сам `sub_48A8C0`.
Сбой цепочки указателей при вызове звания — строка подкласса всё равно выдаётся, журнал 108 с `value2` = 2.

### 2.2. Журнал и лог
`ac.other`: `item_code` = S, `value1` = класс `CUser+0x190`, `value2` = навыков в строке (108 — этап сбоя 1/2), `opcode` 5252,
учётка `CUser+0x174`, слот `CUser+0x18C`, имя `CUser+0x178`, IP пира; `detail` «P87 sub S job J row R n N a3 A title T»
(T: 1 — звание вызвано, 0 — не нужно, −1 — сбой). `Log_Operator` (канал 6) — строка на каждое событие
(«P87 Job4StartSkills: UserNum … SubJob … Job … -> ChangeJobAddSkillTable row R (N skills) by subclass / stock …»).

### 2.3. Что НЕ меняется
- Гейт стока (≥ 60 / ровно 60 очков, категории 4-й профессии = 0, `switch` по 4/6/15/17/26/28) — до площадки, не тронут
  (стенд T7: 59 очков, 61 при a3 = 0, категория 10 > 0 — выдачи нет).
- Вызов при счётчике профессий ≠ 4 (`GameServer.c:37959`, `:38186`) — сток (строка класса — для 1–3-й ступени верно).
- `sub_48A8C0` (проверки требований `SkillInfo.sif`, 5252, достижения 24/25/26 для строк 3/14/25) — сток.
- Подклассы **6/17/28**: строк в таблице нет — **сток** (повторная строка 3-й ступени), журнал 107. Какие навыки им выдавать —
  **решение владельца** (данных нет ни в стоке, ни на живом; выдумывать нельзя). Если владелец добавит строки 6/17/28 в
  `ChangeJobAddSkillTable.txt` (GameServer и Indun), P87 начнёт выдавать их без пересборки DLL — после рестарта GameServer/Indun
  (таблицу сервер читает при старте; P87 смотрит в загруженную таблицу при каждом вызове).
- Уже существующие персонажи 4-й профессии стартовых навыков задним числом не получат: P87 срабатывает в момент смены
  профессии (a3 = 1) или при изучении навыка, доводящем сумму ровно до 60 (a3 = 0). Выдача пропущенного — отдельное решение.

## 3. Пересечения
Адресов `0x481CE0…0x4820EC` и `0x48A8C0…0x48AF80` нет ни у одного патча `src/patches` (verify_p87, текстовый поиск); переходов
внутрь `(0x4820C9, 0x4820D0)` и ровно на `0x4820C9` в `.text` нет (rel8/rel32/jcc/abs32, три образа); на `0x4820C6` ведут 24 перехода
`sub_481CE0` (все — до `mov edx`, т. е. в трамплин edx = CUser всегда). P21/P24 правят `sub_54A890`/`sub_54A980`/`sub_54AD00`/`sub_54B260`
— вызов `sub_54A050` из P87 идёт через них так же, как вызов стока. Соседи, сверяемые до записи (MISMATCH — не ставится):
`0x4820C6` (3 б), `0x4820D0` (23 б, до `call sub_48A8C0`), `0x48A9A3` (118 б, выбор звания и вызов `sub_54A050`), `0x48AA3B` /
`0x48AA53` (чтение таблицы `@0x600B60` / `@0x600B64`).
