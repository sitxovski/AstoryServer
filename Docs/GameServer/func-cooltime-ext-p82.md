# P82 — откат функциональных предметов с кодом ≥ 600 (FuncCoolTimeExt)

| | |
|---|---|
| **Дата** | 2026-10-24, решение координатора («полная копия поведения, не урезанная») |
| **Сервер** | GameServer + Indun_GameServer (один образ `e7b4ac38`; сток `4e20f0ad` — те же байты во всех площадках) |
| **Тип** | [ИСПРАВЛЕНИЕ] предела стока: 5 площадок `jmp/call rel32` (C, G, R1, R2 — `jmp`; T, S, Z — `call`) на трамплины; трамплины выходят только на стоковые адреса и зовут по одной своей stdcall-функции. Протокол не меняется |
| **DLL** | AsdaPatch v54 `20de24b92778ab3fbbe34f62b601645b` (вместе с P81 и правками его ревизии), Version 53 → 54, секция `[P82_FuncCoolTimeExt]` |
| **Проверки** | `tools/verify_p82.py`, стенд `tools/stand_p82` (3 образа × 6 режимов), `tools/run_checks.py` |

## 1. Дефект стока

Откат «по коду» функционального предмета (Function_Table `+18`, мс) сток держит в таблице `CUser+0x3BC41`: **600 записей** по 12 б
`{i32 код, u32 длительность, u32 такт старта}`, индекс = код. Все пользователи таблицы (полнота — второй метод: линейный дизасм всего
`.text`, инструкции с `+0x3BC41/45/49` только в этих функциях, `verify_p82`):

| функция | что делает | предел |
|---|---|---|
| `sub_4F27F0` (5450 `Char_FunctionItem_Use`, вызов 0x4EDDC7) | проверка: запись активна → отказ **5451 код 8** | код ≥ 0x258 → **всегда 0** |
| `sub_4F2640` (ответ БД 2141, вызов 0x4EF606) | регистрация: не активна и `+18 > 0` | код ≥ 0x258 — пропуск |
| `sub_4F24E0` (TimerProcess 0x543353) → `sub_4F2710` | истечение → снять, **5452 {i32 код}** себе | < 0x258 |
| `sub_52EEF0` (выход / портал) | 2157 `UPItemCooltime`: блок предметов 30 × {код, сек}, остаток/1000 > 2 | цикл i < 600 |
| `charLogonCoolTimeSaveRes@0x528EA0`, `charPortalLogonCoolTimeSaveRes@0x52E030` | восстановление из БД → CUser, тело **5465**, групповой откат | **предела НЕТ** — код ≥ 600 пишется за таблицу (порча CUser) |
| `sub_4A2DC0` (ClearUserMemory 0x527399), конструктор 0x4A0610 | сброс | 600 |

Итог: предметы 600…637 (маунты донора fable) не применялись **никогда** — клиент показывал «Откат:» (журнал владельца 24.10:
`[REQ_FAIL] … Code:636/615/609, Result:8`, оригинальный 123 — `[USE] Success`).

## 2. Что делает P82 (для кодов 600…`Function_Table.count`; коды < 600 — сток байт в байт)

Своя таблица по слоту (0..549) до 64 записей `{код, длительность, старт}`; хозяин слота — `Userindex` (`CUser+0x174`).

| площадка | замещено | P82 |
|---|---|---|
| **C** 0x4F2820 (9 б) | `cmp [ebp+0Ch],258h ; jl` | код ≥ 600: запись активна → 0 (**отказ 8**, как сток), таблица полна → 0 + журнал 93, иначе 1; выход 0x4F2849 |
| **G** 0x4F2672 (9 б) | то же в `sub_4F2640` | как сток: только если не активна и `+18 > 0`; выход 0x4F2709 |
| **T** 0x543353 | `call sub_4F24E0` | свой такт (перевод такта, `elapsed ≥ длительности` → снять + **5452** `(net, 5452, 4, num, &код, 0, 1)` как `sub_4F2710`), затем сток |
| **S** 0x52F374 | `call 0x5646C0` (уход 2157) | свои записи — в свободные места блока предметов (`+186 + 6j`, код −1), правило стока (> 2 с); истёкшие → 5452; мест нет → журнал 92 |
| **R1** 0x5290BE / **R2** 0x52E23A (6 б) | `mov edx,[ebp-6F0h/-6F8h]` | запись с кодом ≥ 600 в стоковую запись CUser **не идёт** (на `++j`): в Function_Table → своя таблица (1000·сек), копия 6 б в тело 5465, групповой откат `sub_4DA920(+38)` как сток; вне таблицы → отброшена, журнал 91 |
| **Z** 0x527399 | `call sub_4A2DC0` (там же сток сбрасывает свою таблицу) | своя таблица слота очищается |

Групповой откат (`+38`, `sub_4DA990`/`sub_4DA920`, отказ 12) у кодов ≥ 600 — сток (не ограничен). Сохранение через стоковую БД:
`UPItemCooltime` хранит коды `INT` (`idx1..30`), портал GameServer ↔ Indun и рестарт переживает. Площадки P75 (0x4EDDC7/0x4EF606
— зовут `sub_4F27F0`/`sub_4F2640` по адресу) и общая точка P63/P75 0x527374 не задеты.

**Страж восстановления** (R1/R2) ставится и при `Enabled=0` (`RestoreGuard=1`): строки ≥ 600 в `dbo.ItemCoolTime`, сохранённые P82,
`deploy_p82.py --rollback`).

## 3. Ключи `[P82_FuncCoolTimeExt]`

| ключ | умолч. | смысл |
|---|---|---|
| `Enabled` | 1 | 0 — механика не ставится (коды ≥ 600 — сток: всегда отказ 8) |
| `SaveRestore` | 1 | сохранение/восстановление своих откатов через 2157/5465; 0 — теряются при выходе, при входе отбрасываются стражем |
| `RestoreGuard` | 1 | страж R1/R2 (и при `Enabled=0`); выключать нельзя, пока в `dbo.ItemCoolTime` есть строки ≥ 600 |
| `LogEvents` | 1 | строки FuncLog `[P82] FuncCoolTime REG/END/SAVE/LOAD/DROP/FULL` |
| `LogChannel` | 8 | канал `sub_569DF0` (8 = Log_Func, рядом со стоковыми `[REQUEST]/[USE]`) |
| `JournalIntervalSec` | 10 | журнал — не чаще раза за столько секунд на (слот, вид) |

## 5. Проверки

* `verify_p82.py` — 3 образа: функции побайтно равны; полнота пользователей таблицы (второй метод); предел 0x258 у 4 функций и его
  отсутствие в восстановлении; байты площадок/соседей, границы инструкций, переходов внутрь нет; чужие патчи площадок не называют;
  MAP/трамплины (выходы, один вызов, без `ret`); исходники (Version 54, ключи, виды 91–93, порядок реестра).
* `stand_p82` — настоящие `sub_4F27F0`/`sub_4F2640`, циклы восстановления, хвост `sub_52EEF0`, вызов такта, хвост ClearUserMemory,
  5450/2141 (и через P75): код 123 — сток; 600 — пропуск, затем отказ 8; 601 (1,2 с) — 5452 по истечении; 2157 — дописано в
  свободное место, ≤ 2 с не пишется, полный блок → 92; ClearUserMemory; чужой хозяин слота; таблица 64 → отказ 8 + 93; вход/портал —
  своя таблица + 5465 + групповой откат, 905 вне таблицы → 91, CUser цел; цикл «выход → вход». Режим `off` показывает ловушку стока
  (запись `CUser+0x3BC41+12·636` есть), `guard` — страж без механики, `nosave`, `mismatch`, `p75`.

## 6. Выкладка

`tools/deploy_p82.py` (SSH): сверяет фактическую DLL стойки — **v52 `a97f162e` или v53 `7470f594`**, одинаковую в обеих папках;
бэкапы `*.bak_20261024_p82`, `v2\_backup\2026-10-24_p82`, `@@ASTORY_DEV_ROOT@@\_backup\2026-10-24_p82\server`. Рестарт — координатор
(`restart_stack.py --deploy deploy_p82.py --expect P82_FuncCoolTimeExt`). Клиент порта коды до 637 уже знает (special_itemlist,
5452/5465 — штатно).
