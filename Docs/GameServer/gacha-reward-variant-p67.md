## 1. Что было

**6581 `Recv_UserPrimiumGaChaReward@0x4F72B0`** (GameServer.c:95393–95443). Тело 11 б: `+0` код приза, `+4` слот,
`+6` контейнер, `+7` код **варианта**. Сток проверяет: запись в ячейке есть (`sub_4D61E0`), `+0 == код в ячейке`,
`sub_532A90(вариант)` и `item_table[вариант].+36 == 3`. Связь «вариант ∈ семейству приза» не проверяется ⇒ любой
кэш-предмет класса 3 вместо приза (DB-2555 снимает приз, кладёт вариант; `recvDBPrimiumGaChaReward@0x4F7690`).

**6579 `Recv_UserSoulResult@0x49A8C0`** (61948–62120). Выдаёт результат рулетки по `CUser+99382` (строка, i16) и
`+99384` (столбец, u8) таблицы `dword_5F5F60` (40 б/строка, `word_5F5F5C` строк), потом обнуляет состояние
(62106–62115), включая флаг сессии `CUser+99252` (его ставит 6575 @61841). Флаг до выдачи не проверяется: повторный
6579 читает строку 0/столбец 0 и выдаёт то, что лежит в таблице (опыт/предмет/HP по типу `+20+col`).

## 2. Правило клиента и что из него доказуемо на сервере

Эталон `itemFindVariantBySlotOption@0xB71840` (item_inventory.c:5480), порт `AsdaPremiumGachaSubsystem::
CollectVariantCandidates/ResolveVariant`: база = запись приза; кандидат — `cand.LinkWordCode(+220,u16) ==
base.LinkWordCode` для коробок (`ItemSubType ∈ {200,201}`), иначе `cand.SetCode(+232) == base.SetCode`; затем выбор по
SS1/SS2 (`UsageCategory +92` / `RequiredLevel +80`) при равном `ItemGrade +236`. Порт отсекает нулевой ключ (кандидатов
нет → пакета нет); 6581 уходит только из `ConfirmVariant` с `Variant = ResolveVariant(...)` (вариант может равняться
самому призу).

Сервер: `Item_Table.txt` → `dword_5F5E98` (71 б, 42 колонки, `sub_4A96A0@0x4A96A0`). Соответствие колонок клиентской
записи снято эмпирически по 58 878 общим кодам (`tools/verify_p67.py --tables`):

Таблица гачи `PrimiumGaChaTable.txt` → `sub_4BCAD0@0x4BCAD0`: записи 9 б (`+0` i16 idx, `+2` u8 автомат, `+3` i32 код,
`+7` i16 кол-во); объект-владелец `0x60AD18` (тот же `this`, что у `sub_4A7EA0`): счётчик `this+0x1D565C` = `ds:[0x7E0374]`
(i16), массив `this+0x1D5660` = `ds:[0x7E0378]` (дизасм `sub_4BC200` 0x4BC617/0x4BC633; 6577 @0x4F7042 читает
`ds:[0x7E037C]` — счётчик PrimiumGaChaPriceTable).

⇒ **Серверное правило P67 (6581)**, в порядке проверки, после всех стоковых:
1. база (код в ячейке, `[ebp-0x158]`) — код таблицы предметов (`sub_532A90`), иначе **вид 50**;
2. `RequirePrizeInTable=1`: база ∈ PrimiumGaChaTable (честный 6581 всегда про приз из 6578; gp7 крутит ту же таблицу),
   иначе **вид 50**;
3. `вариант == база` → пропуск;
4. коробка (`+27 ∈ {200,201}`): `LinkWord(+65)` базы и варианта равны и не нулевые, иначе **вид 51**
   (нулевой ключ = «семейства нет», как отсечка порта; `ZeroKeyIsViolation=0` — считать непроверяемым и пропускать);
5. не-коробка: `SetCode` серверу недоступен ⇒ только тот же код (`NonPackageSameCodeOnly=1`), иначе **вид 51**.
   По живой PrimiumGaChaTable (MD5 `9a441c0344402c08d2a126261e60923a`, 141 код: 74 коробки, 15 предметов, 52 кода
   < 20551 вне таблицы предметов) все 15 призов-предметов имеют `SetCode == 0` — порт для них вариантов не предлагает.

**6579:** флаг `CUser+99252 != 0` (`SoulResultGuard=1`), и при `RequireTerminalCell=1` — клетка финальная:
`0 <= row <= word_5F5F5C`, `col <= 4`, `*(char*)(dword_5F5F60 + 40*row + 36 + col) < 0` (так 6575 @61868 помечает финал;
эталон и порт `AsdaSoulRouletteSubsystem` шлют 6579 только после 6576 с `NextRowId == -1`). Иначе **вид 52**.

## 7. Не закрыто / ограничения (доказательно)

1. **SetCode и ItemGrade на сервере нет** — для призов-не-коробок семейство непроверяемо; принято строгое «тот же код»
   (по живой таблице честный путь это не задевает: все 15 призов-предметов с `SetCode 0`). Если в гачу попадут предметы
   с `SetCode ≠ 0`, потребуется серверный источник `SetCode` (отдельная таблица/ключ) — отложено.
2. **Расхождение таблиц порта и сервера по LinkWord** (клиент `item_list.csv` vs живая `Item_Table.txt`): у 867 из 1 962
   коробок-баз семейства не совпадают; на призах живой гачи — **35 честных пар из 452** получат отказ в Mode=1:
   69244 (сервер lw 299 / клиент 208 ↔ семейство 69352…69360), 69298 (124 ↔ 31460…31492 с серверными 42/43),
   69352 (208 ↔ 69244…69252 с серверным 299), 70679 (239 / клиент 243 ↔ 76821…76823), 71120 (256 ↔ 75903…75905 с
   серверным 0), 75647 (сервер 0 / клиент 438 ↔ 75650, 75653). Авторитет — сервер (`client-server-table-desync`):
   перед `Mode=1` синхронизировать LinkWord этих кодов в порту (или поправить серверную таблицу) и перепрогнать
   `--tables` до «отвергнет 0». В Mode=0 (умолчание) честные игроки не страдают.
3. `RequirePrizeInTable=1` отвергнет приз из **старой** версии PrimiumGaChaTable, лежащий в почте/инвентаре (таблица
   у владельца менялась: локальная копия 37 кодов, живая 141). Ключ выключаемый.
4. Призы с кодом < 20551 (52 кода в живой таблице: 30, 31, …, 467…) не коды таблицы предметов: сток 6581 для них уже
   отказывает по варианту, порт пакета не шлёт; P67 считает такую базу видом 50.
5. Indun_GameServer: байты площадок совпадают (проверено), но обработчики 6577/6581 на Indun не вызываются игроками
   (гача — основной сервер); патч ставится в обе DLL одинаково, вреда нет.
