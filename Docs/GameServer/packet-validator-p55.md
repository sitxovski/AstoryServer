## 1. Что не так в оригинале (по декомпилу `RE/ida/server_work/GameServer.c`)

- Рамка приёма `CopyToWriteBuffer@0x5656D0` проверяет только `0xFB`, `size ∈ [1..700]` (WORD +1 — **весь** кадр, `GetReadBuffer@0x42A6B0`
  требует `pkt[size-1] == 0xFE`). Ожидаемый размер для опкода почти нигде не сверяется (явно — аукцион `sub_5218A0`, чат).
  Обработчики копируют фиксированные длины из 4096-байтового слота: короткий кадр даёт нули/мусор слота, длинный — лишний хвост.
- Частоты на сессию нет: диспетчер `sub_42A9D0@0x42A9D0` считает пакеты только глобально по опкоду (`0x5A79C0`).
- Штатные санкции: счётчик «Hack Packet» `sub_524540@0x524540` (`++CUser+0x22`) → `CheckDisConnectUser@0x526C20` кикает при `> 5`
  (`sub_524580`, тип 3). В стоке его растят только два места в `CharItemBuy`.

## 2. Что делает P55

Гейт `P55_PacketGate(mgr, opcode, userNum, pkt)` зовётся **первым** из `P47_OperatorGate` с теми же аргументами (кадр диспетчера:
`pkt = [ebp-4]`, `userNum = [ebp-0x44]` — ставит сервер, `opcode = word [pkt+7]`, размер = `word [pkt+1]`). Площадка `0x42AB4F`
лежит в ветке `userNum < 10000` (`jge 0x42F0BC @0x42AA80`) — только клиентские пакеты; серверные соединения (DB/Login, ≥ 10000) не затрагиваются.

1. **Длина кадра** (`CheckLength`). Таблица `OpcodeLengths.h`: `minSize = 9 + 8·secret + 16 + LEN + 1`, `maxSize = minSize + 19`
   (паддинг клиента `CNetwork_Send a6=1`: `(+11)%20`) или `0` = верх не проверять (чат, переменные формы). LEN и вид конверта —
   из аргументов `sub_523F00(pkt, LEN, userNum, secret)` (`secret=1`: MD5 с +17, тело с +33; `0`: MD5 с +9, тело с +25).
   Опкод без записи — длина не проверяется, только общее правило «кадр ≥ 10 б» (заголовок 9 + хвост). Покрытие: **260 из 277**
   опкодов дерева (246 из `sub_523F00`, 14 ручных с ссылкой на декомпил), 17 без длины (`wave_A4_opcode_lengths.md`).
   ★ `5450`: LEN `0x101` (клиент), не стоковые `0x89` — см. P49; без переопределения легитимный кадр 291 б считался бы длинным.
   ★ `20000` лежит выше индекса `0..0x2AFF` — отдельная константа `kIndexAcceptEx`.
2. **Частота** (`CheckRate`). Token-bucket на `(userNum, класс)`: классы прочее / движение / бой-навыки / чат / предметы-торговля /
   тяжёлые-БД / GM (класс — в таблице; явные списки + эвристика по имени обработчика в генераторе). Пополнение `Rate<Класс>PerSec`,
   запас `Rate<Класс>Burst`, `0` = без лимита. Массив `0x226 × 7`, O(1), без аллокаций и блокировок.
3. **Режим** (`Mode`). `0` — **только журнал** (умолчание; план §6: отказы не раньше недели наблюдения): обработчик вызывается как в стоке.
   `1` — отказ: обработчик не вызывается (стаб P47 уходит в хвост switch `0x42F036`), с `HackPacketOnRefuse=1` ещё `+1` к штатному
   счётчику Hack Packet → штатный кик `> 5`; `0` — тихий сброс. Протокол клиента не меняется.
4. **Журнал** — только нарушения, с ограничителем на `(userNum, вид)`: одна строка в `JournalIntervalSec` (60 с), подавленные —
   в `repeat_suppressed`. Таблица `joylog1.ac.packet_validator` (через P53 `AcJournal`, таблица 8) + строка PatchLog (`LogHits`).
   Неизвестные опкоды (default диспетчера) не дублируются — их пишет P53 (`ac.other`, вид 3).

### Таблица `ac.packet_validator` (свои колонки; общие — как у всех `ac.*`)

| колонка | смысл |
|---|---|
| `event_kind` | `кадр короче минимума для опкода` / `кадр длиннее максимума для опкода` / `превышена частота пакетов класса` / `кадр короче заголовка (10 б)` |
| `action` | `журнал` / `отказ (Hack Packet +1)` / `отказ (тихий)` |
| `op_class`, `handler` | класс опкода; имя обработчика сервера по таблице |
| `frame_size`, `size_min`, `size_max` | заявленный размер; ожидаемый диапазон (`size_max` NULL = верх не проверяется) |
| `rate_per_sec`, `rate_burst`, `packets_last_sec` | лимит класса, запас, пакетов класса за последнюю секунду |

Представления: `ac.v_events` (тип `Валидатор пакетов`, `summary` вида `кадр короче минимума для опкода; опкод 4006 (CharMove); класс движение; размер 52 [53..72]; журнал`),
`ac.v_account_daily` / `ac.v_top_offenders` — колонка `packet_validator`; `ac.UP_AC_JournalPurge` чистит и эту таблицу.

## 3. Площадки

Своих нет. Используется площадка P47 `0x0042AB4F` — `8B45FC 0FB74807 898D38EFFFFF` (13 б; байты одинаковы в стоке и живых образах;
переходов/abs32 внутрь — 0; границы инструкций — на месте; `verify_p55.py`). Если `[P47] Enabled=0` или на `0x42AB4F` нет `jmp`,
P55 возвращает `Failed` с объяснением в PatchLog и не работает. При `[P47] OperatorGmFlag=0` P47 ставит стаб ради P55 (общая точка
`P55_GateWanted`, строка в PatchLog).

## ★ sec2c (15.10.2026) — учёт кика: `pendingOther` и база (ревизия SEC2 Н-4/Н-5)
`KcAttr` += `pendingOther[4]`, `base[4]`. `P55_NoteOtherHack` заменён парой `P55_PendOtherHack` (P47 ДО `pHackCount`, под `KcLock`)
и `P55_CancelOtherHack` (инкремент не случился). `KcAccountLocked`: прирост сначала гасит `pendingOther` («прочее»), остаток — классу
предыдущего кадра. `KcResetLocked`: `base = cur` (valid 0→1), `pendingOther = 0`; счётчик уменьшился — `base = 0`.
`P55_KickAttribution`: «только целостность» = `integ > 0 && base + other ≤ порога`; `*otherOut = base + other`.
`P55_TestKickAttr` (стенд): op 3 — base, op 4 — pendingOther. Свой +1 P55 (Mode=1) не менялся: класс кадра выставлен до него.
