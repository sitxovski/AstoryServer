## 1. ЗАЧЕМ (симптом → диагноз)

**Симптом.** В окне чата каналы **«Поиск отряда»** и **«Торговля»** не работают: сообщение
уходит, но никому не приходит — ни отправителю, ни другим игрокам.

**Диагноз.** В `GameServer.exe` обработчика этих каналов **НЕТ ВООБЩЕ**.

Клиент отправляет их опкодом **6560 (0x19A0)** (`ChatInput_SendChannel@0xBA4A20`,
`RE/etalon/chat.c:2529`) и ждёт рассылку **6561 (0x19A1)**
(`Recv_WhisperOrSystemMessage@0xBA8560`, `RE/etalon/network.c:10823`; диспетчер клиента
`network.c:817` — `if (opcode == 6561) Recv_WhisperOrSystemMessage(g_pChatWnd, pktBuf)`).

На сервере оба опкода попадают в дыру между рядами `case`. Разобрано по стоку:

```
0042AD91  cmp  [ebp-0x10C8], 19ABh        ; opcode
0042AD9B  jg   0042ADE3                   ; ветка > 0x19AB (там case 0x19AF…)
0042ADA7  je   0042EA2A                   ; ровно 0x19AB
0042ADB3  sub  edx, 189Eh                 ; switch 254 cases
0042ADBF  cmp  [ebp-0x10C8], 0FDh         ; таблица покрывает 0x189E…0x199B
0042ADC9  ja   0042F020                   ; -> ОБЩИЙ default
```
`0x19A0 − 0x189E = 0x102 > 0xFD` ⇒ 6560 уходит в `default` и попадает в
`sub_5244B0(mgr, charIndex)` — **счётчик «мусорных» пакетов** `CUser+0x1E`
(`sub_5244F0` считает клиента плохим после 6 штук). То есть не просто «молчание»:
активная переписка в этих каналах ещё и портила игроку репутацию у античит-счётчика.

Проверка grep-ом по `RE/ida/server_work/GameServer.c`: `6560`, `0x19A0`, `6561`, `0x19A1` —
**0 совпадений**.

## 2. ЧТО ИЗМЕНЕНО

### Точка перехвата — ОБЩАЯ ветка `default` диспетчера `sub_42A9D0`

| адрес | было (сток, MD5 `4e20f0ad…`) | стало |
|---|---|---|
| `0x0042F020` (5 б) | `0F BF 4D BC 51`  → `movsx ecx,[ebp-0x44]` / `push ecx` | `E9 xx xx xx xx` → `jmp` в стаб DLL |

Возврат «не наш опкод» → `0x0042F025`; возврат «наш опкод» → `0x0042F036`
(общий хвост `switch`, **мимо** `sub_5244B0` — счётчик мусора не растёт).

**Почему именно `default`, а не `case`.** Диапазон `0x189E…0x199B` свёрнут компилятором в
jump-table (`byte_42F820` + `jpt_42ADDC`), `0x19A0` физически выше верхней границы —
вставить туда `case` нельзя. Ветка `default` (IDA `def_42AC29`) — **единственная** точка,
куда сходятся все необработанные опкоды: 14 прямых `jcc` + `default` пяти jump-таблиц.

**Безопасность площадки.** Полный перебор кодировок по `.text` стока: ни один
`rel8`/`rel32`/`jcc` **не ведёт ВНУТРЬ** `0x42F021…0x42F024` (0 совпадений) ⇒ занять 5 байт
под `jmp` безопасно. Ссылок ровно на `0x42F020` — 14 (все на начало).

### Стаб (проверено `verify_dll.py` по собранной DLL)

```
mov   eax, [ebp-4]              ; v25 — буфер пакета (так же его читает хвост switch)
cmp   word ptr [eax+7], 0x19A0  ; опкод
jne   not_ours
mov   edx, [ebp+8] / mov [edx], 0x19A0     ; маркер прогресса «вошли»
lea   eax, [ebp-0x1048]  push               ; pkt
movsx ecx, word ptr [ebp-0x34]  push        ; packetLen
movsx ecx, word ptr [ebp-0x44]  push        ; charIndex
mov   edx,[ebp-0x10C4]/mov eax,[edx+4]/mov eax,[eax+0x34]  push  ; CUserManager
call  AsdaOnChatWide6560                    ; __stdcall
mov   edx, [ebp+8] / mov [edx], 0x19A1      ; маркер «вышли»
jmp   0x0042F036
not_ours:
movsx ecx, word ptr [ebp-0x44] / push ecx   ; оригинальные 5 байт
jmp   0x0042F025
```

Кадр диспетчера сверен с эталонным `case 0x13DE` (5086) `@0x42BBCC`.

## 3. ПРОТОКОЛ (всё подтверждено декомпилом, не догадками)

### Кадр пакета — `sub_5643E0@0x5643E0`

```
+0  BYTE 0xFB | +1 WORD totalLen = bodyLen + 10 | +3 WORD a7 | +5 WORD userIdx
+7  WORD opcode | +9 тело (bodyLen) | +9+bodyLen BYTE 0xFE
```
⇒ **`bodyLen = packetLen − 10`**. Ровно так же считает оригинальный 5086:
`memcpy(chatText, pPacket + 36, (packetLen − 10) − 27)`.

### Вход 6560 (`ChatInput_SendChannel@0xBA4A20`)

| смещение тела | поле |
|---|---|
| +0 | `BYTE channelType` |
| +1… | текст cp1251, **без завершающего нуля**; `sendLen = strlen(text) + 1` |

⇒ `textLen = bodyLen − 1`. Клиент режет ввод по 199 символам; сервер режет по **80**
(как `char chatText[80]` / `if (chatLen <= 80)` в 5086).

Флаги отправки у 6560 — `CNetwork_Send(..., 6560, 0, 1, 1, 0, 0)`, **те же, что у 5086**
(у подписанного 6616 шестой аргумент = 1) ⇒ **пакет НЕ подписан**, MD5/анти-реплей на нём
не проверяются — как и у обычного чата.

### Выход 6561 (`Recv_WhisperOrSystemMessage@0xBA8560`)

Клиент: `payloadLen = totalLen − 9 − 32; memcpy(msgText, body+32, payloadLen − 1)`.
С `totalLen = bodyLen + 10` это даёт **ровно `textLen`** байт при `bodyLen = 32 + textLen`.

| смещение тела | размер | значение |
|---|---|---|
| +0 | 1 | вид = **1** (сообщение канала; 5 = нотис предмета — не наш случай) |
| +1 | 1 | `channelType` — **эхо пришедшего**, клиент красит по нему (`Chat_AddChatLine(..., ch+7, ...)`) |
| +2…+11 | 10 | клиентом не разбираются → нули |
| +12 | 20 | имя отправителя cp1251, **берётся С СЕРВЕРА** (`CUser+0x178`), поле из пакета игнорируется |
| +32 | N | текст (≤ 80 б), cp1251, без нуля |

Ранга и цвета в пакете нет: строку клиент собирает по loc **20030** `"[%s] > [%s]"`,
цвет берёт из таблицы каналов (канал 1 → `FF8C91FF`, канал 2 → `FF99CC00`).

## 4. ОБВЯЗКА — 1:1 с `recvGlobalChatClient@0x547670` (обработчик 5086)

Порядок проверок и рассылки списан с эталона, адреса и смещения сняты дизассемблером стока:

| шаг | как в оригинале |
|---|---|
| гейт всех чат-опкодов | `if (!sub_52EEA0(mgr, idx))` — байт `CUser+0x182D3 == 1` = чат заблокирован |
| гейт типа сервера | `*(BYTE*)(*(DWORD*)0x5F5E18 + 0xEC*idx + 0x3F) != 4`, где `idx = *(DWORD*)(*(DWORD*)(mgr+4) + 0x4950)` |
| отправитель | `sub_5324A0(mgr, idx)` (CUser) + `sub_532670(mgr, idx)` (байт `CUser+0x190`) |
| обход онлайна | `sub_523E50(mgr, i)` → `sub_5328F0(idx)` → `sub_5324A0(mgr, idx)` |
| фильтры получателя | `CUser+0x174 >= 0` && `CUser+0x2E == 1` && `CUser+0x141 == 0` |
| отправка | `sub_4C28F0(*(void**)(mgr+4), op, bodyLen, idx, body, 0, 0)` |
| сторож цикла | `if (++guard > 1000) sub_569DF0(13, "…")` |
| хвост | запись чата на лог-сервер: `sub_5646C0(0x7E0538, 3670, 106, sub_4C0A90(net), rec, idx)` |

Адреса, добавленные в `SrvApi.h`: `0x4C28F0` SendPacket, `0x523E50` GetUserIdxAt,
`0x532670` IsUserInGame, `0x52EEA0` IsChatBlocked, `0x532570` GetCharNamePtr,
`0x532530` GetUserSubFlag, `0x560DC0` ChatLogRecInit, `0x5646C0` ConnectSend,
`0x4C0A90` GetChatSrvIdx, `0x7E0538` CUserMoveManager, `0x5F5E18` таблица настроек серверов.

### ★ Антифлуд НЕ реализован — намеренно
`recvGlobalChatClient` никакого throttle не содержит; выдумывать серверную механику,
которой в оригинале нет, запрещено. Ограничение частоты стоит на клиенте (кулдаун канала
+ антиповтор). Серверный антифлуд — отдельная задача с отдельным флагом.

### ★ Расхождения с исходным ТЗ (найдены при сверке, ТЗ поправлено по коду)

1. **Фильтры отправителя.** ТЗ предписывало применить к отправителю три фильтра
   `+0x174 / +0x2E / +0x141`. В оригинале это фильтры **получателя** в цикле рассылки;
   отправитель проверяется иначе — `sub_5324A0` + `sub_532670` (байт `CUser+0x190`).
   Реализовано как в оригинале: получателям — три фильтра, отправителю — свои две проверки.
   (Отправитель всё равно попадает в цикл и видит собственное сообщение — как в 5086.)
2. **Гейт диспетчера.** ТЗ его не упоминало. Все чат-опкоды (`5084`, `5086`, `5088`, `6316`)
   диспетчер гейтит через `sub_52EEA0`; для 6560 сделано так же.
3. **Гейт типа сервера.** ТЗ его не упоминало. `recvGlobalChatClient` полностью выключает
   широкий чат, если тип карты сервера = 4. Реализовано, ключ `RespectServerMapTypeGate=1`.
4. **Пересылка на лог-сервер.** ТЗ не упоминало хвост 5086 (пакет 3670, 106 б). Код
   реализован полностью, но **выключен по умолчанию**: код ТИПА чата в записи (у глобального
   чата = 7) для широких каналов в оригинале не задан, а выдумывать константу нельзя.
   Включается ключом `ChatLogType=<код>`.
5. **Секция ini.** ТЗ предлагало `[patches] chat_wide_channels_6560=1`; в проекте принята
   схема «секция на патч» — использована `[P13_ChatWideChannels6560] Enabled=1`.

## 5. Ключи `ConfigSet\patches.ini` (секция `P13_ChatWideChannels6560`)

| ключ | по умолч. | смысл |
|---|---|---|
| `Enabled` | `1` | патч ставится |
| `AllowedChannelMask` | `6` | **десятичная** битовая маска каналов: бит 0 = канал 0 «По всем каналам» (из клиента убран, ВЫКЛ), бит 1 = «Поиск отряда», бит 2 = «Торговля». `6 = 2\|4` |
| `RespectServerMapTypeGate` | `1` | повторять гейт глобального чата (тип карты сервера = 4 → широкий чат выключен) |
| `ChatLogType` | `0` | код типа для записи 3670 на лог-сервер; `0` = не отправлять |
| `RuntimeLog` | `1` | писать строки `[chat6560]` в `PatchLog` |

Файл `patches.ini` **никогда не перезаписывается целиком** — DLL дописывает только
недостающие секции/ключи, значения администратора сохраняются.

★ **ДОПОЛНЕНИЕ 2026-08-05 (этап 7, P14).** Предел длины текста для 6560 больше не зашит в
код: он берётся из общего `g_chatMaxTextLen`, который выставляет патч **P14**
(`[P14_ChatMessageLength] MaxTextLen`, по умолчанию **160**; без P14 — стоковые 80).
Запись на лог-сервер 3670 при этом по-прежнему содержит ровно первые **80** байт — формат
записи (106 б) фиксирован. См. [`chat-message-length-x2.md`](chat-message-length-x2.md).

## 7. БЭКАП

Отдельный бэкап **не требуется**: `GameServer.exe` не меняется вовсе, патч живёт в
`AsdaPatch.dll`. Перед подменой достаточно сохранить предыдущую DLL:

```
copy /Y AsdaPatch.dll AsdaPatch.dll.bak_pre_p13_20260805
```

Схема загрузки (инъекция дескриптора импорта, бэкап `GameServer.exe.bak_predll_20260804`)
описана в `dll-loader-and-patches.md` и этим патчем не затрагивается.

```
stop_servers.bat

cd \\@@ASTORY_SERVER_HOSTNAME@@\h(@@ASTORY_SERVER_HOSTNAME@@_ns)\ASDA\Working_ASDA\v2\GameServer
copy /Y AsdaPatch.dll AsdaPatch.dll.bak_pre_p13_20260805
```

`GameServer.exe` подменять НЕ нужно. В `patches.ini` должно стоять
`[General] MasterEnable=1`; секция `[P13_ChatWideChannels6560]` допишется сама при
первом старте новой DLL (значение `Enabled=1` по умолчанию).

## 9. КАК ОТКАТИТЬ

Три уровня, от мягкого к жёсткому:

1. `[P13_ChatWideChannels6560] Enabled=0` в `patches.ini` + рестарт GameServer —
   поведение стока, бинарь и DLL не трогаем;
2. вернуть прежнюю DLL: `copy /Y AsdaPatch.dll.bak_pre_p13_20260805 AsdaPatch.dll` + рестарт;
3. полностью убрать DLL из процесса: вернуть 8 байт по файловому смещению `0x170`
   в `GameServer.exe` (`84 4b 1a 00 78 00 00 00`) — см. `dll-loader-and-patches.md`.

## 10. Риски

- **СРЕДНИЙ.** Патч трогает горячий путь диспетчера (ветка `default` выполняется для
  КАЖДОГО неизвестного опкода), но добавляет там всего две инструкции сравнения.
- Для «не наших» опкодов поведение стока сохранено байт-в-байт (включая `sub_5244B0`).
- Площадка сверяется перед установкой (`Hook::Verify`); при несовпадении патч
  не ставится (`MISMATCH`), остальные патчи ставятся.
- Рассылка идёт **всем онлайн-игрокам сервера** (не по карте) — это и есть смысл
  «широких» каналов; нагрузка эквивалентна глобальному чату 5086.
- **Проверено только статически** (`verify_dll.py`): локально GameServer запускать нельзя —
  нет БД и остального окружения. Живой тест — на сервере.
