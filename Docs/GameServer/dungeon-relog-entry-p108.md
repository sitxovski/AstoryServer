# P108 — повторный вход из данжа в точку входа (AsdaPatch v65, 05.11.2026)

Сессия dungeon-relog. Требование владельца: при релоге, переподключении или перезапуске клиента внутри данжа
персонаж должен появляться в точке входа данжа, а не там, где вышел. Иначе можно пропустить прохождение
или проложить эксплойт-маршрут.

## Что делает оригинал

| Этап | Где | Что происходит |
|---|---|---|
| выход, обрыв, закрытие клиента | `DisConnectUser@0x5245D0` (GameServer.c:111155) | пакет 2003 → DBManager `EXEC UPLogoutGame` с картой `[ebp-15h]` и клеткой `CUser+0x54E6/+0x54E8` |
| подмена точки | там же | только для атрибутов MapInfo 1/2/4/5/6: точка возврата `CUser+49149/+49150/+49152` или карта 3. В журнале осталось «if((iMapIndex==8)\|\|(iMapIndex==9))» — след старого правила для Palace/Chess. У данжей атрибут 3, под правило они не попадают |
| портал, смена канала | 5056 → `PortalDisConnectUser@0x525EB0` | пакет 2091 `UPPortalLogOut` пишет СТАРУЮ карту; 2003 не отправляется (`CUser+321`) |
| вход | LoginManager `Send_SelectChar` (LoginManager.c:4227), DBManager `DBM_CHARINFO_RES` | `EXEC UPCharPos` → Poridx/Posx/Posy без проверок. Карта подменяется только для 19/20/22 (`UPCharDetailPos`) |
| вход на GS | `charLogOnRes@0x5277D0` | X/Z берутся из ответа БД; клиент получает их в 4003 |
| турнирные 10/11 | `UPLogOutGame` / `UPUserNumUp` | Poridx 10/11 не сохраняется, а Posx/Posy пишутся с турнирной карты. Игрок оказывается на прежней карте в произвольной точке |

Итог: в оригинале игрок встаёт в ту же клетку данжа. Поэтому P108 — [ИСПРАВЛЕНИЕ] дефекта оригинала.

Первую точку MapInfo использует и сам сток: обработчик 9915 (`sub_521770`) на картах атрибута 3
переносит игрока именно в неё (`CharJumpCommandPosition_0`).

Турнирные карты: оригинал не хранит Poridx 10/11 и при входе выводит игрока с карты. P108 сохраняет этот
замысел и исправляет только точку — туда, куда ведёт выходной портал. Ставить игрока в точку входа самой
t_-карты можно только правкой `UPLogOutGame`/`UPUserNumUp`, и это решает владелец.

## Правка

- Площадка `0x5257A0` (10 байт: `movsx ecx,[ebp-15h]; mov [ebp-5BBh],ecx`). Это точка схождения обеих веток
  выбора X/Z, до упаковки карты. Трамплин `St_P108` вызывает `P108_Decide(ebp)`, затем повторяет замещённые
  команды и возвращается на `0x5257AA`.
- `[P108_DungeonRelogEntry]`: `Enabled=1` (0 — сток), `EntryMaps=8,9,17`, `ReturnMaps=10,11`, `LogChannel=0`.
- Значения читаются из памяти GS: MapInfo (`dword_5F5E18`, шаг 0xEC) и портальная таблица своей карты
  (`CUserManager+0x910/+0x914`, шаг 41, STARTPOS `+0x20/+0x22`). Порталы берутся, только если
  `CUserManager+0x8E9` совпадает с картой.
- Журнал стока: `P108 DungeonRelogEntry: <имя> UserIndex N: logout map A (x,z) -> map B (x,z) (...)`.
- Соседи в функции: P35 (пролог `0x5245D0`, кадр не меняет) и P71 (`0x525C9D…0x525CB2`). Пересечений нет.
- Протокол клиента и пакеты БД не меняются. Клиент берёт позицию только из 4003, правка клиента не нужна.

## Принудительная остановка стойки (SQL-пара)

`restart_stack.py` останавливает процессы через `Stop-Process -Force`, `DisConnectUser` не вызывается.
В CharPos при этом остаётся клетка портала старой карты (её пишет `UPPortalLogOut`), а Poridx уже данжа.

Исправление:
  `dbo.DungeonRelogLog`, процедура `dbo.UP_AsdaDungeonRelogReset`. Процедура выводит строку `DUNGEON|…`.
- `restart_stack.py`, шаг 4б2: процедура вызывается до `UP_AsdaCharPosReset`. Если процедуры нет, выводится
  предупреждение и работа продолжается.
- Применять только со слова владельца.

## Рестарт стойки: штатное завершение GameServer (07.11.2026, баг 9)

Жалоба Player58: после рестарта игрок появляется в случайной точке карты. Случайного спавна в сервере нет:
`CharMake` проверяет только границы карты (`sub_4221D0`), затем ищет ближайшую проходимую клетку (`sub_41EC30`).

Причина: GameServer пишет позицию только при выходе (2003) и портале (2091, старая карта и её клетка), а
`UPUserNumUp` меняет только Poridx. `Stop-Process -Force` не сохраняет никого, поэтому игрок, сменивший карту за
сессию, входит на новую карту с клеткой прежней. Без смены карты — откат к месту прошлого выхода.

Подтверждено журналами клиентов: Zeus 04.11 (Sillaris (126,89) — клетка Sunny Coast), Player56 02.11 (Flammio
(157,357) — клетка Alpen).

Правка: шаг 3а `restart_stack.py`, штатный путь оригинала. `SC_CLOSE` окнам GS → `sub_4A5720` → `sub_4BFBE0` →
`Send_AllDisConnectUser` → `DisConnectUser` каждому игроку. Сообщение шлёт задача `/IT`, потому что окна GS в
интерактивной сессии. `Stop-Process` остаётся страховкой. Выключатель: `--no-graceful-stop`.

Не покрыто: падение GS, зависание GS дольше 90 с, ручной `stop_servers.bat` (`taskkill /f`).
