## Что / где / зачем

Задача владельца: «частота атак и навыков по серверному времени (4026/4028/5256), дальность по серверным позициям, откат и мана навыков». Разбор (`02_parts/combat_skills.md`, Б-01/Б-02) показал, что сервер уже делает многое — P56 закрывает ровно дыры и добавляет вторую линию с журналом.

Клетка CUser — WORD `+0x54E6` (x) / `+0x54E8` (y): те же поля сток передаёт в `sub_41A010` (безопасная клетка) во всех четырёх обработчиках. Монстров GameServer по индексу не адресует (позиции у NpcServer) — дальность 4026/4028 остаётся за стоком NpcServer + N14.

«Мана»: отдельной площадки нет — MP проверяется стоком на заявке (`sub_46F600`) и списывается в 8206; отметка «в пути» не даёт второй заявке пройти до списания, то есть двойного каста на один MP не будет.

### Честный клиент не страдает

- Порт после каждой заявки ставит состояние 25 и вторую 5256 не шлёт до 5257/5270 (`AsdaSkillUseSubsystem.cpp` П29) — отметка «в пути» для него невидима.
- Список целей порта без повторов: `PickEntityRenderIdsInGameBox(…, ExcludeRenderId)` исключает первичную цель.
- Темп атаки порта: клип удара / `AttackTempoMul` (макс. ≈ +0,5) ≥ ~0,6 с, пол 200 мс не достижим; у PvP то же.
- Дальность PvP: сток NpcServer режет на 4 клетках, порог 6 — с запасом; дальность цели-игрока у навыка 20 клеток — только журнал.

## Конфиг `[P56_CombatLimits]` (Config::kVersion 35 → 36)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `Enabled` | 1 | 0 — ни одной площадки |
| `Mode` | **0** | 0 — только журнал (виды 7–11); 1 — отказ штатными кодами (5257 код 7; 4027/4202 код 0). Включать после недели журнала (план §6) |
| `DedupeRefuse` | 1 | повтор цели → отказ штатным путём (5257/6159 код 0) **независимо от Mode**; 0 — только журнал (вид 6) |
| `InFlightTimeoutMs` | 2000 | срок отметки «в пути» без ответа 8206 (100…10000) |
| `AttackFloorMs` | 200 | пол интервала 4026/4028 одного userNum по `GetTickCount` GameServer; 0 — выкл |
| `PvpFloorMs` | 200 | пол интервала 4201/4203; 0 — выкл |
| `PvpMaxCells` | 6 | дальность PvP по клеткам, max(|dx|,|dy|); 0 — выкл |
| `SkillMaxCells` | 20 | дальность цели-игрока в 5256/6158; только журнал; 0 — выкл |

Журнал — таблица `joylog1.ac.move_combat` (P53): `event_kind` = текст вида; `tick_prev/tick_now` — такты; `interval_ms` — интервал (виды 7–9) или расстояние в клетках (10/11) или номер первой повторной записи (6); `violation_count` — счётчик нарушений сессии; `p_duration` — порог (виды 7–11: таймаут/пол/клетки; у 6 — число записей); `duration` — id навыка (6/7/11), 0 (8), userNum цели (9/10). Ограничитель P53 на сессию действует.

## Проверка

- `tools/verify_p56.py` — байты 9 площадок + 21 сосед в трёх образах GameServer, `.text` живых = сток; границы инструкций; перебор rel8/rel32/jcc32/abs32 по `.text` — входов внутрь 0 (один ложный байт `e8` в `mov ax,[ebp-0x18]` @0x44CC5B исключён с доказательством); стабы в DLL найдены, `jmp dword ptr` разыменованы в стоковые цели; unicorn: GateTail/St_Cool (пропуск → jmp сток с нетронутыми esp/ecx/ebp; отказ → `ret 8`, eax), St_Send8205/St_Resp8206 (стек/регистры целы, аргументы C-функций верны).
- `tools/stand_p56/stand_p56.exe gs <GameServer.exe> <AsdaPatch.dll> <Mode>` — настоящий образ в памяти стенда, заглушки стоковых целей, установка P53+P56 через реестр, вызов стабов через подменённые площадки с настоящими соглашениями: дубли целей (отказ, сток не вызван), 20 записей, 0 записей; отметка «в пути» → код 7 (Mode 1) / журнал (Mode 0), снятие по 8206, по таймауту, чужой 8206 не снимает; темп 250 мс → пропуск, подряд → журнал/отказ, раздельный счёт по userNum; PvP 3 клетки → пропуск, 20/40 → журнал/отказ, индекс 999 — пропуск; дальность цели-игрока 5256 (журнал), сам/моб не считаются; CUser=null и 25 записей — без падения; строки журнала по видам 6–11 с именем/UserIndex. 46/46 в обоих режимах.
- Живого прогона на dev не было (решение владельца 11.10: наблюдение не нужно, игроков нет) — после интеграции достаточно PatchLog `[OK] P56` и строк вида 6–11 в `ac.move_combat` при сценарии владельца.
