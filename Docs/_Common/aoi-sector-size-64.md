- **Дата:** 2026-08-03 (текущее). Хронология: 2026-08-01 30→256; 2026-08-02 откат→256; **2026-08-03 унификация→64**.
- **Статус:** ✅ ДЕЙСТВУЕТ (сектор 64, симметрично, сетка 8×8).
- **Процессы:** GameServer, Indun_GameServer, ChannelManager, NpcServer, Indun_NpcServer (в `_Common`, т.к. значение ОБЯЗАНО совпадать во всех — секторные индексы пересекают границы процессов).
- **Тип:** конфиг (текстовые файлы карт/секторов).

## ЗАЧЕМ (симптом → диагноз)
- **256** = весь сектор ≈ вся карта в AoI → «залповые» атаки (толпа мобов бьёт разом на кадре AI ~17с).
- **30** = слишком узкий обзор.
- **64** = компромисс: сетка 8×8, AoI = 3×3 соседей ≈ 9/64 карты; режет залпы, обзор шире оригинала.
- **512 (1 сектор) НЕЛЬЗЯ** — жёсткие лимиты `CSector` (0x2138): мобы 200 (`AddMonster@0x46DEF0`), юзеры 400, предметы 400, NPC 50.

## ⚠ ЗАКОН (выучен крэшем)
Размер сектора **обязан совпадать во всех 5 файлах**. Асимметрия (напр. NpcServer=30, GameServer=256) = гарантированный OOB-краш GameServer через ~5с после коннекта NpcServer: NpcServer сам считает индекс сектора моба (`sub_41B480`) по своему `SectorInfo.ini` и шлёт GameServer'у; `Send_SectorInNewAddMonsterInfo@0x4250A0` индексирует `ppSector[]` БЕЗ верхней границы → OOB-deref.

## Как ОТКАТИТЬ
Вернуть нужный бэкап во все 5 файлов (одинаковое значение!):
- к 256: `*.aoi256_20260802` или `*.pre64_20260803`;
- к оригиналу 30: `*.bak_aoi_20260801`.
Копировать поверх основного файла, затем **рестарт ВСЕХ серверов** (`stop_servers.bat` → `start.bat`).
