## Зачем
Владелец 16.11: «нужна возможность двигать предметы и надевать/снимать снаряжение» в окне инвентаря админ-центра.
Логин панели `asda_admin` остаётся строго «только чтение». Запись идёт отдельным узким логином и только из операций
панели: предпросмотр, подтверждение, журнал `adm.audit`, откат.

## Правила (1:1 с сервером, GameServer.c)
* Только когда учётка не в игре. Одна транзакция: строка Charinfo под UPDLOCK, затем предикат `Us_member.Flag = 0 И UserNum = -1 И нет CharPos.UserNum ≠ −1` (разбор `Reports/admin_items/research_online_persist.md`).
* Переставить — только внутри одной сумки 1→1, 2→2, 5→5. Надеть: слот = itemType, кольцо — пара 5/6. Проверки `sub_4CDAA0`/`sub_4CDDA0`: класс, уровень, прочность, самоцветы, щит при двуручном. Привязка `Owner = 1` и `MaxupCnt` при надевании — как у сервера (`:82469`, `:82477`). Снять — в «родную» сумку предмета (`sub_5340B0`).
* Двуручное при надетом щите — отказ «сначала снимите щит» (сервер щит сам не снимает).

## Бэкап
Изменений существующих объектов нет: только новый логин и пользователи. Каждое перемещение пишется в `adm.audit` с «было/стало» по Uuid и откатывается из журнала.

## Откат (пошагово)
2. Ключ `OPS_PASSWORD` из файла секретов можно оставить: без логина он не действует.
3. Служба без логина продолжает работать: операция `items.move` отказывает «нет подключения на запись».

## Рестарт
Не нужен. Игровая стойка не затронута; изменения предметов игрок увидит при следующем входе.

## Риски / связанное
* Правка инвентаря у персонажа в игре даёт потерю или дюп. Поэтому запись блокируется проверкой «не в игре» в той же транзакции. Висящие после аварии флаги снимаются входом-выходом игрока или стартом карты.
* Не проверено в игре: пересчитывает ли сервер характеристики персонажа при входе после надевания, сделанного в панели. По разбору GameServer читает инвентарь из БД при входе.
