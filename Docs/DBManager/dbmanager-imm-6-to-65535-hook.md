# DBManager — detour-хук: непосредственный аргумент 6 → 65535 (0xFFFF)

- **Дата:** бинарь `DBManager.exe` от 15.12.2024 (патч внесён до попадания в стойку; обнаружен дифом 2026-08-03).
- **Статус:** ✅ ДЕЙСТВУЕТ (рабочий `DBManager.exe` пропатчен).
- **Процесс:** DBManager.
- **Файл:** `\\@@ASTORY_SERVER_HOSTNAME@@\h(@@ASTORY_SERVER_HOSTNAME@@_ns)\ASDA\Working_ASDA\v2\DBManager\DBManager.exe` (MD5 `B8F3A5EC59B96DE59A78213A73C95138`, 536576 б). Запуск из `start.bat` (`cd DBManager & start DBManager.exe`).
- **Тип:** бинарный патч — detour (trampoline) через code-cave (ImageBase 0x400000).
- **Бэкап (оригинал):** `DBManager\DBManager-Original.exe` (MD5 `4CEC9B6130C4CE6B8ADD39E8EC9FE574`, 536576 б) — чистый. Диф ровно 2 рана, 18 байт.

## ЧТО изменено (было → стало)
Две точки:

**1) Точка перехвата @ VA `0x44C1E9`** (5 байт):
```
ориг: 6A 06 8B 45 0C        push 6 ; mov eax,[ebp+0xC]
патч: E9 94 59 FB FF        jmp 0x401B82            (в cave)
```
Контекст оригинала: `push 0x1002; push 6; mov eax,[ebp+0xC]; mov ecx,[ebp-1C0]; mov edx,[ecx+eax*4+0x2C]; push edx; call [0x466260]`.

**2) Code-cave @ VA `0x401B82`** (в оригинале — CC-паддинг между функциями):
```
ориг: CC CC CC CC CC ...    (int3 padding)
патч: 68 FF FF 00 00        push 0xFFFF
      8B 45 0C              mov eax,[ebp+0xC]
      E9 5F A6 04 00        jmp 0x44C1EE            (обратно, за перехват)
```

**Нетто-эффект:** непосредственный аргумент, который оригинал толкал как `push 6`, заменён на **`push 0xFFFF` (65535)**; остальная логика (`mov eax,[ebp+0xC]` и далее вызов `[0x466260]`) сохранена. То есть некий счётчик/лимит/параметр, передаваемый в вызов `call [0x466260]` (индекс таблицы `[ecx+eax*4+0x2C]`, доп. аргумент `0x1002`=4098), поднят с 6 до 65535.

## ЗАЧЕМ (симптом → диагноз)
⚠ **Намерение НЕ подтверждено декомпилом** (декомпил DBManager в проекте отсутствует; факт байт — точный, смысл — гипотеза). По контексту (`push 0xFFFF` вместо `6`) это **снятие узкого лимита** (напр. число записей/сессий/повторов в DB-операции). Косвенно связано с сагой «второй вход виснет» / несовместимого DBManager (MEMANTO: замена DBManager+ConfigSet рабочим, 2026-07-26) — но прямой связи патча с тем инцидентом не доказано.

## Как ОТКАТИТЬ
```
copy /Y "...\DBManager\DBManager-Original.exe" "...\DBManager\DBManager.exe"
```
(или вернуть 2 диапазона: `0x44C1E9` → `6A 06 8B 45 0C`; cave `0x401B82` → `CC×13`). Затем **рестарт DBManager** (лучше вся стойка: `stop_servers.bat` → `start.bat`, DBManager стартует до Channel/Login).
