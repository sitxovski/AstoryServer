# N21_RespawnFreeTile — монстр при появлении не встаёт в клетку другого монстра (слот P93, 26.10.2026) [ИСПРАВЛЕНИЕ]

**Решение владельца 26.10:** «да, всех, но убедись, что они не в одном тайле спаунятся» (к правке клиента
`asda.Mobs.BatchAllRecords` — шаг пачки 4013 = 173, все записи; волна invismobs).

## Как сервер выбирает клетку появления (сток)

`CAi::Frame_Monster` = `sub_461C80` (`NpcServer.exe.c:64532`), ветка «время возрождения вышло»:

| Кто | Клетка | Где |
|---|---|---|
| одиночка без маршрута | клетка точки спауна из `.svr` (монстр +30384/+30388) | `NpcServer.exe.c:64690` |
| одиночка/вожак с маршрутом (`+34356 ≠ 0`) | случайная точка прямоугольника очередного отрезка (`sub_408AB0` = rand в [min,max], отрезки по кругу 0..8) | `:64676`, `:64702` |
| член отряда | `sub_41AFE0` «SearchAvailableTile»: смещение (размер+1 + rand % 3/6/9/12) от вожака в одной из 4 четвертей, до 5 попыток | `:64760…64960` |

Затем `0x4628C0`: `GetTileState` (`sub_41A310`) — **только проходимость** (статичная карта `./Map/<карта>`, читается при
старте, `NpcServer.exe.c:56300…56355`, во время работы не пишется); непроходимая → `sub_41AC10` ищет соседнюю
проходимую. **Занятость клетки другим монстром не проверяется нигде** — появившийся встаёт в клетку того, кто туда
пришёл (погоня, блуждание).

## Что показали журналы (114 сессий игроков 21–26.10, разбор invismobs)

- Клетки точек спауна в `.svr` (23 карты NpcServer\Monster) все различны.
- 369 возрождений с известной первой клеткой (первый 4015 после 4019 flags=4): в клетке другого живого монстра — **1**,
  в соседней — 15. `cur` в самой 4019 flags=4 — служебная клетка GameServer (`v7[49]/[50]`), клиент её не применяет.
- Кучи в одной клетке при входе в сектор (alpen (296,301) — 8 волков rid 109–116, (335,184) — 5) — настоящее состояние
  сервера: мобы сошлись погоней/блужданием (`cur` записи 4013 состояния 1 совпадает с живой клеткой 4015 в 212 из 215),
  это движение ИИ, а не появление; у оригинала то же (он показывал лишь первую запись пачки).
- Записи 4013 состояния 2 (идёт): `cur` — НАЧАЛО отрезка (устаревший, > 5 клеток в 6631 из 24699), `dst` ≈ живая клетка
  (24546 из 24699).

## Правка

Площадка `0x46292B` (7 б `mov edx,[esp+30h]` / `lea ecx,[edi+8]`) — общая точка всех веток: клетка выбрана и проверена
на проходимость, сейчас запишется в +30360/+30364 монстра. Если в клетке стоит ЖИВОЙ монстр той же карты (ячейка
`this + i·92F8h`, флаг `+765Ch` бит 0, клетка `+76A0h/+76A4h`, число монстров `this + 2954858h`, карта
`this + 11547E4h` = `[esp+20h]`), N21 ищет по кольцам 1..`Radius` проходимую (`GetTileState == 0`) клетку без живого
монстра, внутри кольца — случайную (своё ГПСЧ, `rand` стока не трогается). Не нашлась — клетка стока. Клетки ≤ 0
не выбираются (как в стоке, `0x4628B0`). Позицию выбирает сервер — у всех клиентов и у NpcServer одна клетка
(клиентский разнос дал бы рассинхрон с проверками дальности 8204/8940).

Ключи `[N21_RespawnFreeTile]`: `Enabled=1`, `Radius=2` (1..5). Config AddonNPC 11 → 12. Протокол не меняется.
Счётчики стенда — экспорт `N21_Counters` (площадка / занято / разнесено / некуда / ошибок разбора).
