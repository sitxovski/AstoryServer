# NpcServer — правки через AddonNPC.dll

Дата: 2026-08-24. Решение владельца: правки боевого сервера делать так же, как уже сделаны правки
главного, — не байтами в исполняемом файле, а библиотекой, которую он подгружает при старте.
Полный близнец схемы `AsdaPatch.dll` для GameServer (см. `../GameServer/dll-loader-and-patches.md`).

## Схема

**База — стоковый `NpcServer.exe`.** Единственное изменение в нём — **инъекция дескриптора
импорта** `AddonNPC.dll` / `AddonNpcInit`. Секция кода не трогается вообще, поэтому:

- декомпил продолжает совпадать с тем, что работает;
- античиту нечего ловить в `.text`;
- DLL грузится загрузчиком ОС **до точки входа**, когда потоков ещё нет.

Все правки применяются **в памяти**, каждая со своим выключателем в `ConfigSet/patches.ini`.

## Проверенные площадки (не предположение — снято с образа)

| что | где |
|---|---|
| таблица импорта | RVA `0x7A5FC`, size `0x8C` — 6 записей + чистый терминатор |
| дескрипторы + OFT + строки | нулевой хвост `.rdata`: 3777 байт с RVA `0x7B13F`, берём `0x7B200` |
| FirstThunk | нулевой хвост `.data` (флаги **RW**): 3632 байта с RVA `0x7C1D0`, берём `0x7C300` |

★ **Главная грабля, стоившая падения у GameServer:** FirstThunk обязан лежать на **изначально
записываемой** странице — загрузчик снимает защиту только с региона `DataDirectory[IAT]`
(здесь `0x65000..0x65248`), всё остальное должно быть writable само. Симптом ошибки —
`ntdll!LdrpSnapModule` с нарушением доступа при записи адреса функции.

**Самоконтроля целостности у NpcServer нет** (проверено: ни crypto, ни MD5, ни
`MapFileAndCheckSum`, ни HackShield). CRT процесса — `MSVCR80.dll`, наша DLL строится `/MT`,
конфликта нет.

## Результат инъекции

Размер не изменился (516 096), **`.text` не тронут вовсе**, 94 байта в 4 группах:
`DataDirectory[IMPORT]` (5 б) + массив дескрипторов, OFT и строки в `.rdata` (139 + 35 б)
+ FirstThunk в `.data` (3 б).

| файл | md5 |
|---|---|
| сток `NpcServer.exe` | `d292e4ec4edfd5040d8fb39382664eab` |
| **`NpcServer.exe.dllhost.exe`** (сток + инъекция) | `c02486d62e803e98eb6fb4fa98d1fcd6` |
| `AddonNPC.dll` | `7fbaefaf4e7167b904357837a9e203be` |

**Откат инъекции:** вернуть 8 байт `DataDirectory[IMPORT]` по файловому смещению `0x178`
(`fc a5 07 00 8c 00 00 00`) либо просто подменить exe стоком.

## Устройство проекта

`AstoryServer/Patches/AddonNPC/` — `build.bat`, `src/dllmain.cpp`, `src/Config.cpp/.h`, `src/patches/`.

★ **`Hook.cpp` и `Log.cpp` НЕ дублируются** — берутся из `../AsdaPatch/src/`. Это те самые
примитивы, которые пишут байты в чужой процесс; держать их в одном экземпляре важнее, чем
независимость проектов. Всё host-специфичное (точка входа, имя процесса, тексты ini, список
патчей) — своё.

Сборка: `build.bat` (VS2022, x86, `/MT`) → `out/AddonNPC.dll`.

## Патчи

| секция ini | что делает | откуда перенесён |
|---|---|---|
| `N01_AttackTimer32` | античит скорости атаки считает время 32-битным, а не по младшим 16 битам | `patch_npc_attack_timer32.py` |
| `N02_HateClearDamage` | возрождение монстра обнуляет накопленный урон в списке угрозы | `patch_npc_hate_clear_damage.py` |

Разбор каждого — в `attack-speed-timer-16bit.md` и `hate-list-stale-damage.md`.
Скрипты **сохранены**: по ним сверялись байты, и они же запасной путь, если инъекция окажется
недоступна.

★ Правило проекта соблюдено: **ни один патч не пишет байты, не сверив предварительно оригинал**
(`VerifyAllSites`). Не совпало — патч не ставится, в журнал идёт строка с обоими наборами байт.

## Что это открывает

Три правки пришлось отложить только потому, что в отображаемой части `.text` NpcServer **нет ни
одного свободного участка длиннее 32 байт** — врезку делать было некуда:

1. монстр продолжает бить ~1 с после смерти (боевой ИИ работает на «живой» ветке);
2. поиск владельца добычи не проверяет занятость самой первой записи;
3. пакет 8202 отдаёт здоровье монстра без вычета накопителя (сейчас обойдено на стороне клиента).

Через DLL трамплин выделяется в рантайме — «некуда вписать» перестаёт быть препятствием.

## Выкладка (делает владелец)

1. Остановить NpcServer.
2. Сохранить резервную копию текущего `NpcServer.exe` с датой в имени.
3. Положить `AddonNPC.dll` рядом с `NpcServer.exe`.
4. Подменить `NpcServer.exe` файлом `NpcServer.exe.dllhost.exe`.
5. Запустить. **Первый запуск — с `MasterEnable=0`**: это проверка каркаса, сервер должен
   подняться и создать `Log\Log_Patch\PatchLog_<дата>.txt`. Ни один патч при этом не ставится.
6. Убедиться, что журнал создан и сервер работает как раньше. Затем поставить `MasterEnable=1`
   и перезапустить.
7. Проверка правок — `Docs/Port/systems/COMBAT_FIX_VERIFICATION.md`, пачки 12 и 13.

**Откат:** `MasterEnable=0` (мгновенно, без подмены файлов) либо возврат резервной копии exe.
