★ — три площадки **сверх аудита** (в аудите §5 «уже началось» оставалось абсолютным `cmp метка,такт; ja`). Оставлены — доказательство:
- **Кодировка.** `3B /r` = `cmp r32, r/m32`, ModRM `D1` = 11 010 001 → reg = edx (метка), rm = ecx (такт): `ja` = «метка > такт». После замены `CA` = 11 001 010 → reg = ecx (такт), rm = edx (метка): `cmp ecx,edx` считает такт − метка, `0F 88` = `js` → переход при `(int)(такт − метка) < 0`. На 0x44E0C2: `C1` (eax = метка, ecx = такт) → `C8` (ecx, eax). Длины инструкций не меняются (verify: дизасм до/после на всех образах).
- **Операнды.** Метка: `mov edx,[47D2BCh]` @0x41DE31 / `mov eax,[47D2BCh]` @0x44E0B5 / `mov edx,[47D2BCh]` @0x44E1D9. Такт: `call [465054h]` (IAT GetTickCount) @0x41DE1F / @0x44E096 / @0x44E1C7 → `mov ecx,eax` до `fnstsw ax`; между вызовом и площадкой eax/регистры не переписываются, входов в путь извне нет (verify, провенанс).
- **Флаги.** После `js`: прямой путь — `mov ax` + `sub ecx,edx` (полный писатель) / `sub ecx,eax`; цель — `fld; fcomp; fnstsw; test` или `push ebp; …; call`. Никто не читает.
- **Модульная корректность.** Метка := такт₀ + 300000 (0x41DF96: `add ecx,493E0h`). Пока такт ∈ [такт₀, такт₀+300000): такт − метка ∈ [−300000, 0) → `js` «ещё не началось» — при любом положении относительно 2^31 и 2^32 (разность по модулю 2^32). После начала такт − метка ∈ [0, 3600000 + кадр] (событие закрывается по сроку каждые 60/300 кадров и при каждой сдаче) → `js` не берётся, и для `jae` в тех же ветках разность < 2^31 → `jae ≡ jge`. Старых меток нет: все писатели `dword_47D2BC` — 0x41DF96 (взвод), 0x41DEC6/0x44E14F/0x44E260 (0 при конце); читатели — 0x41DE31, 0x41DEFC, 0x44E0B5, 0x44E1D9, 0x44E28A и `sub_437A30` @0x437BE8 (множитель добычи, беззнаково `такт − метка − 1 > 0x36EE7E` — свой час отрабатывает, не трогаем). Все обращения перечислены линейным проходом .text (verify).
- **Стенд и эмуляция** прогоняют ВСЮ `sub_41DDD0` и хвост кадра `sub_44DB70` (0x44E05B…) на сетке такт × метка × флаг × счётчики, включая оба перехода; след вызовов (лог / 8913 / 8914 / 8916 / 8921 / 8919 / 8915) и состояние события совпадают с модульной моделью, а при такте < 2^31 и метке < 2^31 модель N18 тождественна стоковой.

Г3 (площадка не сплошная): стаб `St18_AttackWait` — `sub eax,[esi+7A68h]; test ecx,ecx; jle done; cmp eax,ecx; done: ret`. `call` (5 б) + `nop` ложатся ровно на 6-байтовый `sub`; `push edi` между ними остаётся и флаги не меняет; `cmp eax,ecx` → `nop nop`; `jl` → `jb` читает только CF: при длительности ≤ 0 `test` даёт CF = 0 → «не ждать» (как сток при неотрицательной разности); иначе CF = (беззн.) eax < ecx. Стек: call/ret без локальных; на выходе eax = такт − метка (как в стоке, функция возвращает ax), `push edi` ↔ `pop edi` эпилога @0x439148. Ничего, кроме eax и флагов, стаб не трогает (матрица: ecx = длительность, ebx/esi/edx/edi/ebp/esp целы, на стеке лежит именно edi).

## Почему беззнаковая замена безопасна (предостережение аудита §4 соблюдено)

Беззнаковой нельзя делать разность с полем, которое пишется свежим `GetTickCount()` уже после того, как кадр снял свой такт (разность −16 мс сток терпит по знаку). Все писатели затронутых полей — линейный проход .text трёх образов:
- **+10A88 игрока (Г1):** чтения 0x415EC8/0x41687A; записи своим тактом той же функции 0x415EF2/0x41689B (eax = результат `call [GetTickCount]` @0x415EB4/@0x416830, eax до площадки не переписывается), нулём 0x415F50 (`xor ecx`), 0x4168F4 (`xor edx`), 0x428DB6 (инициализация игрока `sub_428C20`, последний писатель eax — `xor eax,eax` @0x428D02). Будущих меток нет: метка ≤ любой последующий такт.
- **+7A68/+7A6C монстра (Г3):** в .text 10 + 9 обращений. У монстра пишут только конструктор `sub_44BF30` (0x44BF73/0x44BF79, 0x44C115/0x44C10E; ebx = 0 с `xor ebx,ebx` @0x44BF6D) и AlarmMonsterAction `sub_460990` (0x460CB7, ebx = 0 с @0x460C9C; 0x460C96 — чтение в пакет). 0x4127DA/0x4129B0 (`sub_412660`/`sub_412890`) и 0x4113EA/0x411953 (`sub_411340`) — **массив навыков ИГРОКА** (запись 28 б × до 500 навыков от +7A5C; в монстра 37624 б не помещается; вызовы — с `*(буфер+216)` = записью кастера и `a4 + 68264·i`); 0x40D492 — таблица по `[ecx+edx*4+7A6Ch]`. Кусок 0x42E480…0x42E4F5 (пишет +7A68/+7A6C/+7A70/+7A74 тактом) — **ссылок в срезе нет** (перебор rel8/rel32/jcc32/abs32; единственное совпадение 0x42E53D→0x42E4D1 — операнд `fadd` @0x42E53B; перед куском `ret 8` @0x42E47A). Итог: у монстра +7A68 = +7A6C = 0 всегда; сток ждёт ⇔ `(int)такт < 0`, N18 — никогда (длительность 0), при такте < 2^31 оба не ждут.
- **dword_47D2BC (Г2):** см. выше; обе функции читают метку и такт под одной критической секцией `0x47CF8C`.

Поля из предостережения (состояния монстра `sub_4103F0` → `sub_443740`, задержка смерти +8F72, +8644) **не тронуты**.
