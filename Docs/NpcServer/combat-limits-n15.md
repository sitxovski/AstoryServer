## Что сток уже делает (доказано дизасмом, см. отчёт §1)

Заявка 8205 (из 5256) и 8940 (из 6158) несут `iSkillIndex, iUserArrayIndex, iTargetX, iTargetZ` — «центр» навыка, который прислал клиент (шапка 5256/6158, байты +3/+5; GameServer копирует их в 8205/8940 как есть).

| Проверка | Где | Как | Чем кончается |
|---|---|---|---|
| Центр против кастера | `sub_42C4B0` (коробка, `__userpurge`): `call` @0x418912 в `SkillStart` sub_418670 и @0x415061 в `SoulGuarderSkillStart` sub_414E10 | ecx = дальность навыка (`sub_40C0F0` «Skill Distance»: байт слота +0x7A61 + баффы типа 57), ebx = iTargetX, **edi = 20**, esi = Y кастера (+30364), [esp+4] = X кастера (+30360), [esp+8] = iTargetZ. Центр внутри коробки кастер ± (дальность + 20) по обеим осям | al=0 → **код 10** в ответе 8206/8941 (→ 5257/6159 код 10), цели не обрабатываются |
| Цель против центра | `sub_4179D0` (игрок; `call` @0x418C72 цель-игрок, @0x418F28 цель-моб) и `sub_414690` (страж; @0x415339, @0x4155B8), `__stdcall(buf, rec, mobs, players)` | буфер: центр (+222/+224 | +122/+124), радиус навыка (+221 | +121), позиция цели (+304/+306 | +204/+206 ← запись цели +30360/+30364). Цель внутри центр ± (радиус + 20) по обеим осям | иначе `return 0` **без строки и кода** — цель остаётся в списке результата, урона/эффекта нет |

Раскладка буфера доказана по стокам кадра (esp-относительные, буфер игрока = esp+0x25C, стража = esp+0x41C): +216/+116 ← ebp (запись кастера, @0x418813/@0x414FB2), +221/+121 ← dl (радиус, @0x4188B0/@0x415012), +222/+224 ← cx/si = iTargetX/iTargetZ (@0x4188A0; страж @0x415042/@0x415034), +304/+306 ← запись цели +30360/+30364 (@0x418B89/@0x418B9E; страж @0x415263/@0x41524B); `sub_4179D0` читает ровно +0xDD/+0xDE/+0xE0/+0x130/+0x132 (@0x4179EF), `sub_414690` — +0x79/+0x7A/+0x7C/+0xCC/+0xCE (@0x4146AF). Все эти байты — соседи площадок (сверяются при установке).

Итог: «центр AoE не дальше X клеток от серверной позиции кастера» сток **уже** проверяет, X = дальность навыка + 20; молчаливый `return 0` в `sub_4179D0` — это отсев цели дальше радиуса + 20 от центра. Дыры нет — есть невидимость (ни строки в Error_Log, ни журнала) и щедрый допуск +20.

## Что делает N15 (6 площадок `call rel32`, трамплинов нет)

| № | Площадка | Было → стало | Стаб |
|---|---|---|---|
| 1 | `0x00418912` `call sub_42C4B0` (8205) | `E8 99 3B 01 00` → `E8 <St_CenterPlayer>` | `CenterTail`: считает ту же коробку, что сток; центр вне (дальность+20) → журнал **вид 21** (зеркало кода 10), дальше сток (он и откажет). Центр вне (дальность + `CenterSlackCells`) при допуске < 20 → журнал; `Mode=1` → `al=0`, `ret 8` — сток ставит **штатный код 10** |
| 2 | `0x00415061` `call sub_42C4B0` (8940) | `E8 4A 74 01 00` → `E8 <St_CenterGuard>` | то же для стража (индекс навыка из кадра `[esp+0x20]`, у игрока `[esp+0x1C]`) |
| 3–4 | `0x00418C72`, `0x00418F28` `call sub_4179D0` | `E8 59 ED FF FF` / `E8 A3 EA FF FF` → `E8 <St_TargetPlayer>` | `TargetTail`: цель вне (радиус+20) от центра → журнал **вид 22** (зеркало молчаливого пропуска), дальше сток (вернёт 0). Вне (радиус + `TargetSlackCells`) при допуске < 20 → журнал; `Mode=1` → `eax=0`, `ret 0x10` без стока — та же молчаливая пропажа цели. Одна строка на заявку (тот же навык того же кастера в пределах 100 мс не дублируется) |
| 5–6 | `0x00415339`, `0x004155B8` `call sub_414690` | `E8 52 F3 FF FF` / `E8 D3 F0 FF FF` → `E8 <St_TargetGuard>` | то же для стража (раскладка +116/+121/+122/+124/+204/+206) |

24 соседа (регистры перед вызовом, `mov edi,20`, ветка кода 10, индекс навыка в кадре, стоки буфера, чтение буфера в `sub_4179D0`/`sub_414690`, push аргументов, пролог `sub_42C4B0`) — сверяются, не меняются; список в `n15_skill_area_npc.cpp` и `verify_a5b.py`.

Строка журнала (`joylog1.ac.move_combat`): `opcode` 8205/8940; `tick_now` — GetTickCount NpcServer; `interval_ms` — расстояние в клетках max(|dx|,|dz|) (центр от кастера / цель от центра); `violation_count` — счётчик нарушений кастера; `p_duration` — порог (дальность|радиус + допуск, по которому сработало); `duration` — индекс навыка (8205/8940 `iSkillIndex`); `user_num`/`char_name` — запись кастера +0x7864/+0x7714. Ограничитель P53 на сессию действует.

Честный клиент не страдает: допуски 20 по умолчанию = сток (строки появляются только там, где сток и так отказывает молча); порт шлёт в шапке 5256/6158 тайл цели/земли внутри дальности навыка (`SendSkillUseBody`, `AsdaNetSubsystem.cpp`), список целей — из коробки навыка вокруг центра.

## Конфиг `[N15_SkillArea]` (AddonNPC Config::kVersion 5 → 6)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `Enabled` | 1 | 0 — площадки не ставятся. Требует `[P53_AcJournal] Enabled=1` |
| `Mode` | **0** | 0 — только журнал; 1 — при СВОЁМ допуске отказ штатным путём (центр → код 10; цель → молча пропущена). Штатные отказы стока журналируются при любом Mode |
| `CenterSlackCells` | 20 | допуск к дальности навыка для центра, 0…20 (больше 20 нельзя — сток откажет раньше; зажимается) |
| `TargetSlackCells` | 20 | допуск к радиусу навыка для каждой цели, 0…20 |

Виды журнала 21/22 — текст в общем `AsdaPatch/src/AcJournal.cpp` (`KindText`, `kMoveCombat`; в копии `AsdaPatch_w56b` уже добавлен). Пока основной `AcJournal.cpp` без них, DLL из штатного `build.bat` пишет вид как «?» (колонки верны).
