# N14 — серверные лимиты боя, сторона NpcServer (пара к P56; мера 9 плана античита, волна В5)

- **Дата:** 2026-10-12
- **Процесс:** NpcServer.exe и Indun_NpcServer.exe (образы различаются; байты площадок и соседей одинаковы во всех трёх).
- **Тип:** [ПОРТ/СЕРВЕР-ДОРАБОТКА] — только журнал; пороги, допуски и отказы стока не меняются.
- **Документ пары:** `GameServer/combat-limits-p56.md`; отчёт волны: `Reports/anticheat/wave_A5_combat.md`.

## Что / где / зачем

NpcServer уже считает по СВОЕМУ времени и СВОИМ позициям:

- **частота ударов** (`Process_AttackedToMonster` sub_45F3A0, NS:63108; PvP-двойник sub_45FF80, NS:63545): интервал WORD игрок+65172 из `sub_401900` (тип оружия/темп) с баффами, допуск +100 мс, счётчик +65120, >30 → 8905 (кик тип 6). 16 бит → 32 чинит **N01**; «SpeedHack Check/Banish» в журнал пишет **N13** (виды 4/5);
- **дальность** (`sub_42C4F0`, NS:63102 и NS:63537): PvE — игрок внутри коробки моба ± (3 + байт дальности моба +30956) клеток; PvP — ± 4 клетки. Нарушение → строка Error_Log через `sub_408D40` и **штатный отказ**: PvE → 8204 код 1 (GameServer → 4027 код 1), PvP → отказ двойника.

До N14 отказы по дальности были видны только в файловом Error_Log NpcServer. N14 зеркалит их в `joylog1.ac.move_combat` (виды 12/13) тем же приёмом, что N13: подмена цели `call sub_408D40` → стаб → тот же `sub_408D40` с теми же аргументами (ecx сохраняется). Файл-лог пишется как раньше.

### Площадки (байты одинаковы в стоке 16c7a0af, живом c02486d6, Indun 0de2c559)

| VA | Было → стало | Контекст |
|---|---|---|
| `0x0045F581` | `E8 BA 97 FA FF` (call sub_408D40) → `E8 <St_Pve>` | за 5 б `68 38 76 47 00` push строки `%s … px %d, pz %d, mx %d, mz %d (%d)`; за 12 б `lea ecx,[ebp+0x7714]` — имя игрока |
| `0x00460131` | `E8 0A 8C FA FF` → `E8 <St_Pvp>` | за 5 б `68 28 84 47 00` push строки `… %s … px %d, pz %d, tx %d, tz %d (%d)`; `lea edx,[ebp+0x7714]` — имя атакующего, `lea ecx,[ebx+0x7714]` — имя цели |

Аргументы стека у вызова: [1] формат, [2] имя игрока (запись + 0x7714), [3] PvE: индекс моба / PvP: имя цели, [4] px, [5] pz, [6] mx|tx, [7] mz|tz, [8] такт удара. userNum = WORD запись+0x7864 (как у N13). Площадки N01 (`0x45F5A4`/`0x460151`/`0x460169`) и N13 (`0x45F600`/`0x45F674`/`0x4601B4`/`0x460228`) — другие байты, не пересекаются.

Строка журнала: `opcode` 8201 (PvE) / 8222 (PvP); `tick_now` — такт удара; `interval_ms` — расстояние в клетках max(|px−mx|,|pz−mz|); `violation_count` — pz; `p_duration` — индекс моба (PvE) / userNum цели (PvP); `duration` — px.

Центр площадного навыка (`sub_4179D0` NS:16043: каст дальше радиуса+20 от центра → `return 0` без строки) в журнал НЕ зеркалится: раскладка буфера v73 (+222/+224 и +304/+306) не доказана по декомпилу — отложено (см. отчёт).

## Проверка

- `verify_p56.py` (часть NPC): байты обеих площадок + 3 соседа в трёх образах; push строки формата за 5 б и текст формата (`px %d, pz %d`, `(%d)`); границы инструкций; перебор переходов/abs32 внутрь — 0 на каждом образе; в DLL найдены хвост N14 (`jmp → 0x408D40`) и хвост N13 (`→ 0x408DC0`, не задет), входы видов 12/13; unicorn: хвост уходит в писатель с нетронутыми esp/ecx, `N14_OnSite(kind, st)` получает верные аргументы.
- `stand_p56.exe npc <NpcServer.exe> <AddonNPC.dll>`: образ в памяти, заглушка писателя, установка P53+N14 через реестр, вызов стабов с 8 аргументами cdecl — писатель вызван ровно раз, строка стока сформирована с теми же аргументами; журнал: виды 12/13, имя игрока, userNum 42 / опкоды 8201/8222, расстояние/pz/моб-или-цель/px по колонкам. 17/17 на трёх образах.
