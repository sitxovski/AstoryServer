## ЧТО изменено (было → стало)

### Патч 1 — байпас «IP не определён» @ VA `0x406FC6` (функция `CUserProc::Send_LoginUser`, `sub_406C20`)
Оригинал берёт IP из listen-массива (`sub_403420` = GetUserListenArrayIP) и при NULL отбивает логин пакетом `4101 code=5`.
```
1LM (ориг): 89 85 CC FE FF FF   mov [ebp-134], eax        ; v60 = IP
            83 BD CC FE FF FF 00 cmp [ebp-134], 0
            75 6B                jnz continue              ; !=0 → дальше, ==0 → reject
LM  (патч): 85 C0                test eax, eax
            75 05                jnz +5
            B8 64 E3 42 00       mov eax, 0x42E364         ; -> строка "127.0.0.1"
            89 85 CC FE FF FF    mov [ebp-134], eax        ; v60 = "127.0.0.1"
            EB 69                jmp continue              ; безусловно мимо reject
```
Итог: при неопределённом IP клиента вместо отказа подставляется **`127.0.0.1`** (строка по `0x42E364`), логин продолжается.

### Патч 2 — форс-пропуск проверки в логине @ VA `0x407099` (та же функция)
```
1LM: 74 6B   jz  +0x6B    ; условный пропуск блока
LM : EB 6B   jmp +0x6B    ; безусловный пропуск (проверка снята)
```

### Патч 3 — байпас MD5-проверки тела 1010 @ VA `0x40D1F0` (`CUserProc::Recv_ClientLogOut`, `sub_40D0A0`)
★ Уточнение 12.10 (дизасм стока): перед `jne` стоит `call sub_4060E0` (GetMD5_Cmp по 0x3D байтам), а не секрет —
`sub_406360` вызывается выше и всегда возвращает 1. Обход снимал отказ «UPLogoutUser MD5»; причина несходимости
(61 ≠ 32 байта подписи клиента) закрыта **L05**.
```
1LM: 75 53   jnz secret_ok   ; секрет верный → дальше, иначе "Secret Error"
LM : EB 53   jmp secret_ok   ; всегда «секрет верный»
```

### Патч 4 — байпас MD5-проверки тела 1028 @ VA `0x40D41E` (`sub_40D310`, UPBackUser)
★ Уточнение 12.10: как и патч 3 — перед `jne` стоит `call sub_4060E0` (MD5 по 0x3D), не секрет. Закрыто L05.
Тот же паттерн (`call sub_406360; test eax,eax`):
```
1LM: 75 44   jnz secret_ok
LM : EB 44   jmp secret_ok   ; всегда «секрет верный»
```

## ЗАЧЕМ (симптом → диагноз)
UE-порт клиента не воспроизводит серверную «секрет»-механику логина и не всегда даёт LoginManager определить свой listen-IP (порт-код 5 «IP не определён», `4101 code=5`; см. MEMANTO/`server-live-path`, диагнозы 2026-07). Чтобы порт логинился, в LoginManager сняли:
- отказ по NULL-IP (→ подстановка `127.0.0.1`);
- две проверки «секрета» сессии (`sub_406360`) в логаут/смежном хендлере.

## Как ОТКАТИТЬ
Заменить рабочий бинарь оригиналом:
```
copy /Y "...\LoginManager\1LoginManager.exe" "...\LoginManager\LoginManager.exe"
```
(либо точечно вернуть 4 диапазона байт: `0x406FC6`, `0x407099`, `0x40D1F0`, `0x40D41E` — значения из колонки «1LM»). После — **рестарт LoginManager** (по хорошему всей стойки через `stop_servers.bat`/`start.bat`, т.к. процессы связаны).

## Рестарт / риски / связанное
- **Рестарт:** LoginManager (минимум). Правки бинаря = рестарт процесса обязателен.
- **Риск:** снятие secret-проверок ослабляет валидацию сессии — приемлемо только на закрытом/приватном сервере. Если вернуть оригинал `1LoginManager.exe`, UE-порт снова не залогинится, пока порт не начнёт слать корректный секрет/IP.
- **НЕ связано** с cap 550 (`SetEmpty_ListenArray@0x403160`) — тот баг исправлен 27.10.2026 патчем L08 в LoginPatch.dll, см. `cap-550-slot-leak-FIXED-L08.md` и `L08-listen-array-leak.md`.
- Реверс-эталон: `@@ASTORY_DEV_ROOT@@\RE\ida\login_work\LoginManager.c` (`sub_406C20` ~стр.2405, `sub_40D0A0` ~стр.4819, `sub_40D310` ~стр.4879).
