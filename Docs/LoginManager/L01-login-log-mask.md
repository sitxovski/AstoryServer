# L01 — маскировка хеша пароля в журнале входа + MAC отдельным полем

- **Дата:** 12.10.2026
- **Статус:** ✅ выложено 12.10 12:45, первый старт 12:53 — Applied
- **Процесс:** LoginManager — `\\@@ASTORY_SERVER_HOSTNAME@@\h(@@ASTORY_SERVER_HOSTNAME@@_ns)\ASDA\Working_ASDA\v2\LoginManager\LoginManager.exe`
- **Тип:** код-врезка в памяти через `LoginPatch.dll` (замена одного `call`, 5 байт); exe на диске не меняется (кроме прежней инъекции импорта)
- **Назначение:** безопасность — убрать из открытого журнала `OTP_Report` MD5 пароля и устранить переполнение чтения в поле MAC
- **Загрузчик:** [loginpatch-dll-loader.md](loginpatch-dll-loader.md)

## Дефект оригинала

Обработчик входа 1003 `sub_406C20@0x406C20` пишет строку журнала (RVA `0x407079`):

```
sub_41B760(2, "Login User ID %s/%s, Pass %s/%s, IP %s", id1, id2, pass1, pass2, ip)
```

Раскладка аргументов на стеке (сверено дизасмом живого образа, `0x407040..0x40707E`):

| аргумент | источник | проблема |
|---|---|---|
| `pass1` = `&v46` | MD5 32 б + нуль на `[32]` | MD5 пароля (без соли) в открытом тексте |
| `pass2` = `&Buf1[81]` | **сырое поле пакета, 32 б БЕЗ нуля** | `%s` читает дальше нуля → захватывает соседний MAC (`Buf1[113]`) и далее |

Итог: в `LoginManager\Log\LoginMngError\OTP_Report_*.txt` на каждый вход попадают MD5 пароля и MAC машины.
Детектирование: `Reports/anticheat/04_detection_response.md` §6.3, таблица «OTP_Report».

Строка формата `0x42F308` в образе ссылается ТОЛЬКО отсюда (скан бинаря) — площадка единственная.

## Что делает патч

Заменяет `call sub_41B760` @`0x407079` (5 б `e8 e2 46 01 00`) на `call` своего трамплина `LoginLogTrampoline`
(объявлен `__cdecl` с теми же 7 аргументами; стоковый `add esp,0x1C` на `0x40707E` снимает их, как и прежде).
Трамплин:

- пароль НЕ пишет — на его месте литерал `(masked)`;
- MAC читает отдельно от `pass2 + 32`, с ограничением `kMacLen = 17` байт и до первого нуля, непечатаемое → `?`,
  результат завершает нулём в локальном буфере — переполнения чтения больше нет;
- зовёт настоящую `sub_41B760` с безопасным форматом и теми же логином/IP, в тот же канал (level=2, тот же файл).

Новая строка: `Login User ID <id>/<id>, Pass (masked), MAC <mac>, IP <ip>`.

Всё тело в SEH; при негодном указателе пишет `Login User (masked)` и не роняет процесс.

## Конфиг `ConfigSet\patches.ini`

```
[L01_LoginLogMask]
Enabled=1     ; 0 — журнал как в оригинале (с MD5 и MAC внахлёст)
LogMac=1      ; 0 — не писать поле MAC вообще (ещё строже; теряется признак мультиаккаунта)
```

## Проверка

- **Юнит-тест** `AstoryServer/Patches/LoginPatch/tools/test_l01.cpp` (через экспорт `L01_TestInvoke`, подмена функции журнала заглушкой):
  T1 хеш не утёк + MAC корректен + нет over-read; T2 `LogMac=0` убирает MAC; T3 MAC без нуля обрезан ровно до 17 б;
  T4 `pass2=nullptr` не роняет. Все прошли.
- **Статически**: на живом образе `0x407079` = `e8 e2 46 01 00` (совпадает с ожидаемым `kOrig`); единственная ссылка на формат.
- **Сквозной прогон**: DLL загружена в тестовый хост, секция создана, реестр отработал; на НЕ-LoginManager-образе
  сверка дала `MISMATCH` и ничего не записала (защита от правки чужого образа). На живом образе сверка пройдёт.

Сервер локально не запускался (запрет). Живая проверка строки журнала — после рестарта владельцем.
