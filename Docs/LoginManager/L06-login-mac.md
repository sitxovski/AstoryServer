- **Дата:** 12.10.2026
- **Статус:** 🟡 собрано и проверено в рабочей копии `AstoryServer/_archive_waves/LoginPatch_w06` (юнит-тест 30/30, статика, сквозной прогон); в основную папку и на шару НЕ выложено — интеграция за координатором
- **Процесс:** LoginManager — `\\@@ASTORY_SERVER_HOSTNAME@@\h(@@ASTORY_SERVER_HOSTNAME@@_ns)\ASDA\Working_ASDA\v2\LoginManager\LoginManager.exe` (образ `51db86b2…`, = сток на площадках обхода + P17 + инъекция)
- **Тип:** код-врезка в памяти через `LoginPatch.dll` (замена `call`, цепочкой поверх L03); `.text` на диске не меняется
- **Загрузчик:** [loginpatch-dll-loader.md](loginpatch-dll-loader.md); соседи по площадке — [L02/L03](L02-L03-login-sql-hardening.md), [L01](L01-login-log-mask.md)
- **План:** `Reports/anticheat/00_PLAN.md`, П5 «MAC в UPUserLogin»; отчёт волны — `Reports/anticheat/wave_L06_mac.md`

## Дефект

Обработчик входа 1003 (`sub_406C20`, `LoginManager.c:2582`) строит запрос

```
sub_40F440(&unk_43ACD8, v57, 0, a4, v58, "EXEC UPUserLogin '%s','%s','%s', %d, '%s', '%s', '%s', '%s'",
           Str, v46, v60, v45, &v33, &v29, &v25, &v16);
```

5-й `'%s'` — `&v33` (`[ebp-0x2530]`). Переменная обнуляется при входе в функцию и **никогда не заполняется**:
в `@Mac VARCHAR(20)` всегда уходит пустая строка. Процедура прокидывает её в
`JoyLog1.dbo.UPLoginGame 1,@Userindex,0,@Ip,@DATE,0,@Mac` → `LogInfo.Mac` — поле пусто во всех строках
(wave_B1: 92 из 92), суточный отчёт M8 «мультиаккаунт по MAC» слеп. При этом MAC клиент присылает:
cred-блок `Buf1` (243 б, `memcpy(Buf1, a5+33, 0xF3)`), поле `Buf1[113]`, 17 б строкой `xx-xx-xx-xx-xx-xx`
(порт `BuildLoginBody` cred+113, нижний регистр; L01 читает его оттуда для журнала).

## Площадка и кадр (дизасм образа `51db86b2`, совпадает со стоком `LoginManager.exe.orig`)

```
0x407221  8d85d0daffff  lea eax,[ebp-0x2530]   ; &v33 — 11-й аргумент (5-й '%s')
0x407227  50            push eax
…
0x40725e  68d8ac4300    push 0x43acd8          ; 1-й аргумент
0x407263  e8d8810000    call 0x40f440          ; ← площадка (та же, что L03)
0x407268  83c438        add esp,0x38           ; 14 аргументов снимает вызывающий (cdecl)
```

После `call`: `[esp+0x2C]` = `&v33`. Под `v33` в кадре ровно **12 байт** (`char v33; int v34; int v35; __int16 v36;`
→ следующая `v37` @`ebp-0x2524`) — 17 символов + NUL не влезают, писать в `v33` нельзя.

**Источник MAC** — `Buf1[113]` = `ebp-0x9F` (`Buf1 = ebp-0x110`: `push 0xf3 … lea eax,[ebp-0x110]` @0x406E3C/0x406E50).
★ НЕ «пароль+32», как в L01: на этой площадке 2-й аргумент `[esp+0x20]` = `v46` (`ebp-0x2508`) — **копия** пароля
в кадре (`push 0x20; lea eax,[ebp-0xbf]; lea ecx,[ebp-0x2508]` @0x406FA0; `v46[32]=0`). В L01 «pass2+32» верно
потому, что там второй аргумент пароля — `&Buf1[81]` = `ebp-0xBF`.

## Исправление (★)

Площадка `0x407263` делится с L03, поэтому L06 ставится **после L03 цепочкой**:

```
сток:        site → sub_40F440
L03:         site → L03_Trampoline → sub_40F440
L03 + L06:   site → L06_Trampoline → L03_Trampoline → sub_40F440
только L06:  site → L06_Trampoline → sub_40F440
```

Установка: если на площадке стоковые `e8 d8 81 00 00` — следующее звено `sub_40F440`; если `call L03_Trampoline`
(адрес через `L03_TrampolineAddr()`, байты сверяются) — звено L03; иначе `MISMATCH`, запись не производится.

Трамплин L06 (дизасм из DLL, `0x10002FA0`):

```
sub  esp,0x14                 ; буфер MAC в своём кадре (17+NUL)
push ebp ; lea eax,[esp+4] ; push eax
call L06_FillMac              ; MAC из [ebp-0x9F] → буфер (санитизация)
add  esp,8
push [esp+0x4C] ×3            ; аргументы 14,13,12 (смещение постоянное: каждый push сдвигает esp и индекс на 4)
lea  eax,[esp+0xC] ; push eax ; 11-й → НАШ буфер вместо &v33
push [esp+0x4C] ×10           ; аргументы 10..1
call [g_next]                 ; L03_Trampoline или sub_40F440 (call, не jmp — буфер жив до возврата)
add  esp,0x38 ; add esp,0x14 ; ret
```

`ebp` не трогается (кадр `sub_406C20` виден и L03, и сборщику). Буфер в кадре трамплина — свой у каждого потока
(рабочих потоков несколько: `sub_4041B0` → `CreateThread(StartAddress)` в цикле → `sub_402360` → `sub_406C20`), живёт
до возврата `sub_40F440` (`vsprintf` внутри синхронный). Отказ L03 (`*out=0`, `eax=0`) проходит сквозь L06 как есть.

**Санитизация** (L03 апостроф в MAC не проверяет — делаем сами): читаются не более 17 байт поля (18-й — соседнее поле,
NUL не гарантирован); допустимы только `[0-9a-fA-F-]`; `Strict=1` — ровно 17 символов `hh-hh-hh-hh-hh-hh`;
`Lowercase=1` — `A-F → a-f`. Любое отклонение — пустая строка (ровно то, что уходило в стоке). Инъекция через MAC
невозможна по набору символов.

принимают 17 символов. L02 маскирует и этот `'%s'` в OLEDB_LOG.


| Ключ | По умолчанию | Смысл |
|---|---|---|
| `Enabled` | 1 | 0 — как в оригинале (пустая строка в `@Mac`) |
| `Strict` | 1 | 1 — только ровно `hh-hh-hh-hh-hh-hh`; 0 — любой набор `[0-9a-fA-F-]` до 17 символов |
| `Lowercase` | 1 | `A-F` → `a-f` (единый регистр для группировки по MAC в M8) |
| `LogBad` | 1 | отметка в PatchLog, когда НЕпустое поле MAC отброшено (первые 20) |

## Проверка

- **Юнит-тест** `tools/test_l06.cpp` (экспорты `L06_SanitizeMac`, `L06_TestSetup`, `L06_TestGetTrampoline`,
  `L03_TestGetTrampoline`, `L03_TestSetup`): трамплин зовётся по-настоящему с поддельным кадром (`ebp` → буфер,
  `Buf1 = ebp-0x110`) и 14 аргументами, стаб сборщика проверяет 2/6/7/8/11-й. Честный MAC → 11-й аргумент ровно
  17 символов; верхний регистр → нижний; апостроф/двоеточия/не-hex/20 hex без тире/короткий/пусто/`nullptr`/негодный
  указатель → пусто; поле без NUL читается ровно 17; `v33` вызывающего не тронута; цепочка L06→L03: честный вход
  проходит с MAC, апостроф в логине/пароле — отказ (`*out=0`, сборщик не вызван), апостроф в MAC — вход не сломан,
  MAC пуст. **30/30.**
- **Статически**: байты площадки и кадра на образе `51db86b2` = сток (`0x407263 = e8 d8 81 00 00`,
  `0x407221 = 8d 85 d0 da ff ff 50`, `0x406E50 = 8d 85 f0 fe ff ff`, `0x406FA0 = 6a 20 8d 85 41 ff ff ff 50 8d 8d f8 da ff ff`);
  дизасм трамплинов L06 (`0x10002FA0`) и L03 (`0x10002640`) из собранной DLL — как в описании; `L06_Trampoline`
  не содержит `jmp`, стек после `ret` сбалансирован (0x14 + 0x38).
- **Сквозной прогон** (`tools/host_load.cpp`, ini Version=6, MasterEnable=1): секция `[L06_LoginMac]` дописана,

Сервер локально не запускался. Живая проверка после выкладки: `SELECT TOP 20 Mac, Ip, Userindex FROM JoyLog1.dbo.LogInfo
ORDER BY 1 DESC` → у новых входов `Mac` = 17 символов; PatchLog — строка `L06: MAC (Buf1[113] = ebp-0x9F) → 5-й '%s' …
цепочка: L03_Trampoline → sub_40F440`.

## fix13 (2026-10-13) — цепочка не зависит от порядка установки

L06 экспортирует `L06_TrampolineAddr()` (адрес трамплина, если поставлен) и `L06_ChainNext(expectOld, newNext)` (смена слота
«следующее звено» сравнением с обменом). L03, поставленный ПОСЛЕ L06, узнаёт `call L06_Trampoline` на площадке по этому
адресу и встаёт в слот — итог тот же: site → L06 → L03 → `sub_40F440`. Подробно и проверки — `L02-L03-login-sql-hardening.md`
§fix13. LoginPatch v7 `e720b640513e3f4a87c3920e13df7769` (164 864 б), НЕ выложен.
